## 一、交付与证据

### 1) OCR 接入（RapidOCR 本地 CPU）
- `engine/adapters/ocr.py`：新增 `RapidOCREngine`（图片 → 行文本 + 四点坐标 + 置信度），参数可配 `limit_side_len` / `intra_op_num_threads` / 模型目录，延迟加载。

### 2) 拆掉大模型（路线调整令 §2）
- `engine/pipeline.py`：默认 `engine_mode=rules`，走 `engine/rules_engine.py` 确定性拼装；大模型只在 `QBL_USE_LLM=1` 时作为插件启用（默认关闭）。
- `engine/schema.py`：`source` 只允许 `rule` / `pattern`；顶层字段 `prompt_version` → `rules_version`；`rules_version` 校验 `v主.次`。
- `engine/report.py`：报告输出 `rules_version`；绿灯摘要改为 D16 口径「截图里没看到明显风险」。
- 后端同步：`backend/app/engine_runner.py` 不再创建模型；`worker.py` 落库 `model=rules` + `rules_version`；`/analysis/{id}` 返回 `rules_version`。
- `engine/prompts.py`：`RULES_VERSION = v2.0`（旧 `PROMPT_VERSION` 仅保留别名）。
- **证据**：`python -m engine.selftest` → **52/52 通过**（新增「默认走确定性规则引擎」「插件打开后模型未配置按失败处理」）。

### 3) 文本规整 + 变形写法表（路线调整令 §2）
- `engine/variants.py` + `lexicon/variants_v1.json`：36 组变形写法（V信/薇信/威信→微信、扣扣→QQ、押 金/ya金→押金、工装费→服装费、缅北→缅甸…），词库加载时自动展开成正则，字与字之间容忍空格；运营可直接加词，不发版。
