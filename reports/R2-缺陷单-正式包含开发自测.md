## D-05【P1】正式包 `app.json` 里仍注册了 `pages/dev/index`

| 项 | 内容 |
| --- | --- |
| 证据 | `dist/build/mp-weixin/app.json` 的 `pages` 数组包含 `pages/dev/index` |
| 证据 | `dist/build/mp-weixin/pages/dev/` 目录存在，且随包发布 |
| 影响 | ① 违反 §9 第 5 条；② 提审时审核员可在包里看到调试页；③ 调试页含开关（可切换真后端/强制 mock），被恶意调用有风险 |
| 复现 | `pytest tests/rebrand/test_no_hardcoded_color.py::Test开发自测页守卫::test_开发自测页不进正式包` |

**根因**：`src/pages.json` 里固定写了 `pages/dev/index`，`uni build` 不会自动剔除页面。

**建议修复**（任选其一，推荐 A）：
- **A**：`pages.json` 分两份（`pages.json` 用于正式、`pages.dev.json` 用于开发），或用 `vite` 的条件编译 / 环境变量在 build 时生成不含 dev 的 pages.json；
- B：把 dev 入口做成独立分包，正式版打包时排除该分包；
- C（最简）：构建后处理脚本，在 build 产物里删掉 `pages/dev` 并从 `app.json` 移除，同时必须在 CI 里强制执行，否则漏一次就上线了。

## D-06【P2】「我的」页 wxml 里残留「开发自测（仅开发环境）」文案

| 项 | 内容 |
| --- | --- |
| 证据 | `dist/build/mp-weixin/pages/mine/index.wxml` 含 `<view wx:if="{{q}}" class="card dev-entry">…开发自测（仅开发环境）…` |
| 问题 | 元素被 `v-if` 隐藏了，**但文案字符串仍在包里**。审核员反编译 wxml 即可看到 |
| 复现 | `pytest tests/rebrand/...::test_正式包无开发自测文案` |

**根因**：`isDev` 用 `process.env.NODE_ENV !== 'production'` 做运行期判断，
`v-if` 只控制**渲染**，不控制**打包**。

**建议修复**：改用**编译期**判断，让 build 时整段被 tree-shaking 掉，例如：
```js
// 编译期常量，build 时该分支被移除
// #ifdef MP-WEIXIN
const isDev = import.meta.env.DEV
// #endif
```
或最简单：build 前用脚本把该块替换为空（与 D-05 的 C 方案合并处理）。

## 附：为什么这两条之前没被发现

我一开始还写过「dev 页不在正式包里」的判断（只查了 `pages/dev` 目录当时是否存在），
**那个判断是错的**——它恰好出现在两次构建之间。现在已经改成直接读 `app.json` 的页面列表 + 目录存在性双查，
不再依赖"某次构建的快照"。

这也说明：**构建产物类断言必须每次构建后重跑**，不能凭记忆。
