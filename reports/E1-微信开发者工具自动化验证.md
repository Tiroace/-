## 0. 结论先讲（给 Chief / 开发者直接用）

| 判定项 | 结果 | 依据 |
| --- | --- | --- |
| ① `cli.bat open --project ... --port 9420` 能否打开 | **否** | 卡在 `wait IDE port timeout`（§2.3） |
| ② `cli.bat auto --project ... --port 9420` 能否起自动化 | **否** | 同上，9420 从不监听（§2.5） |
| ③ `miniprogram-automator` 能否连 9420 并点击/断言 | **未验证（前置条件不成立）** | 9420 端口从未出现，无连接对象（§3） |
| ④ 失败卡在哪 | **IDE 服务端口未开启，且 CLI 自动开启失败** | §4 根因链 |

**根因链（逐级有实测证据）**

1. `.ide-status` 内容为 `Off` → IDE 的 CLI 服务端口处于**关闭**状态。
2. CLI 检测到 `Off` 后先打印提示，然后**阻塞在交互提示 `Enable IDE Service (y/N)`** 上等 stdin。
   → 这正是 Chief 00:02 那次「卡住 2 分钟无输出」的**真正原因**（不是 IDE 死了，是在等人敲 y）。
3. 喂 `y` 后，CLI 会带 `--enable-service-port` **自己拉起一个新 IDE 实例**去开启端口（实测参数见 §2.4）。
4. 该新实例在当前环境**无法存活**：约 5–20 秒后退出（`launch.log` 记 `守护进程…退出`）。
   → 端口没开成，CLI 等 IDE 端口 30 秒超时（`wait IDE port timeout`），命令以「看起来成功了」的方式结束（exit 0，但什么也没做）。
5. 另有一个**前置污染**：`.ide` 文件里残留旧端口 `26611`，导致 CLI 反复出现
   `IDE may already started at port 26611, trying to connect` 这类误导性报错。

## 5. 能不能用、怎么用、有什么限制

### 5.1 三个必须知道的坑（已封装进 `tests/support/wxdev-cli.ps1`）

1. **路径带空格 + 中文**：不能用 `cmd /c "完整路径\cli.bat"`；要 `cwd=安装目录` + `cli.bat`。
   `--project` 传带空格路径时，先用 8.3 短路径（`Scripting.FileSystemObject.GetFolder().ShortPath`）。
2. **必须先喂 stdin**：不开服务端口时 CLI 会阻塞等 `y`，不喂就永远挂着。必须 `stdin='y'` + **≥120s 超时**。
3. **每次调用前清理残留**：中断的调用会留下 `node.exe ... cli\index.js` 占住回调端口 3800，
   不清会拿到错误的端口回调。`Clean-CliLeftover` 只杀这一类 node，**不碰 IDE**。

### 5.2 当前可用的部分

- CLI 进程能从**我的非交互环境**正常启动并完成参数解析、HTTP 回调服务、读取 `.ide`、提示交互（§2）。
- 冒烟工程结构、脚本封装、超时/清理规范已就绪。

### 5.3 当前不可用的部分

- **无法在本机全程无人值守地开 IDE / 起自动化 / 连 automator**。

### 5.4 解除卡点需要的动作（需老板/人手动操作，**我做不了**）

**请老板在已打开的 IDE 里手动开一次服务端口**（因为自动开启在本机失效）：

> 微信开发者工具 → 设置 → 安全设置 → 把「**服务端口**」打开（Service Port **On**）

开启成功后：`.ide-status` 会变成 `On`，IDE 会开始监听一个真实端口。
之后我这边跑 `cli.bat open/auto` 就不需要再喂 `y`，链路应能直接往下走。

**备选方案**：若手动开启后 `cli.bat auto` 仍失败，则判定「本机 IDE 自动化不可用」，
测试策略降级为：① 单元/契约测试全自动（引擎侧，见第 2 项任务）；② 小程序前端用**静态检查 + 构建产物校验**；
③ 交互类用例（额度、广告、支付）走**真机手动验收清单**。

### 5.5 顺带发现的两个质量问题（建议同步开发者）

1. **CLI 失败仍 exit 0** —— 以后所有脚本化测试必须**断言副作用**（端口出现、产物文件、日志），不能只看退出码。
2. **`--port` 与 `.ide` 不一致会直接 `exit -1`** —— 文档里说「IDE 已用别的端口开过就必须先 quit」，多任务并行时会互相踩。测试环境应固定 9420 且串行执行。

## A.4 使用限制（必须写清，否则后来人会踩）

| # | 限制 | 说明 |
| --- | --- | --- |
| L1 | **`--port` 与 `--auto-port` 是两个不同端口** | 9420 是 IDE HTTP 服务端口；automator 必须连 `--auto-port` 指定的端口（本机用 9422）。连 9420 会报 `Failed connecting ... check if target project window is opened with automation enabled`。 |
| L2 | **automator 0.13 的 `page.$()/page.$$()/page.data()` 在本机全部超时** | 但 `mp.evaluate()` / `mp.screenshot()` / `mp.reLaunch()` / `mp.pageStack()` 正常。**断言一律走 `mp.evaluate(() => getCurrentPages())`**。这是本机唯一可靠的取数通道，不是降级。 |
| L3 | **uni-app 编译后 data 字段被压缩成 a/b/c…** | 不能按字段名断言，要按「值」或「WXML 静态文案」断言。 |
| L4 | **大量文案在 WXML 模板里，不在 data 里** | 例如「选图/拍照」不在 data 中。断言必须把编译产物 `pages/<p>/*.wxml` 文案并入判定，否则会误判为缺失。 |
| L5 | `automator.launch()` 在 Windows 上**用不了** | 它用 `child_process.spawn` 直接执行 `cli.bat`，路径带空格/中文必失败。必须「手动起 `cli.bat auto --auto-port`，再 `connect()`」。 |
| L6 | 不要用 `cli.bat open` 不带 `--port` | 会把端口变成随机值，后续连不上。 |
| L7 | 每次重启 IDE 后 `--auto-port` 需重新执行 | 自动化端口不会自动恢复。 |
| L8 | 残留 node 进程会占住会话 | 中断的 automator 进程会让下一次 `connect` 后 RPC 全部超时，先清理 `node.exe ... probe*/e1-assertions` 再重跑。 |
