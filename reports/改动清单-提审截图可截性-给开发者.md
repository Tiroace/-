## 改动 1：mock 支持「指定报告结论」

### 改哪里
| 文件 | 改动 |
|---|---|
| `src\src\common\config.js` | `STORAGE_KEYS` 增加一个键：`mockForceOverall: 'qiuzhibilei_mock_force_overall'`（与现有 `mockAdFail / mockStartRunning / mockBackground` 并列，命名风格一致） |
| `src\src\services\mock.js` | `pickReportId(hash)` 开头加一段：读该存储键，值属于 `red/amber/green/unknown` 时**直接返回该值**；否则保持现状（走原 hash 取模） |

### 实现约束（四条硬要求）
1. **默认关闭**：存储键为空/非法值 → 行为与现在**完全一致**，不得改变任何现有轮次结果。
2. **只在 mock 链路生效**：该开关只在 `useMock() === true` 时才有意义；**真实后端路径不得读取它**。
3. **产物不得留调试入口**：不得新增「开发自测」页面、不得新增任何用户可见的开关文案（`pages/dev` 已被 `strip-dev-build.mjs` 删除，继续用存储键即可，**不要加 UI**）。
4. **【安全·必做】开关不得在正式包里留活口**（产品经理提出，安全项）：
   存储键写在**本地存储**，会跟着设备走——用户在某台真机上设过值，值就留在那台机器上。虽然正式包 `useMock()===false` 不读它，但**任何一次构建若把 mock 打开，这个开关就是活的**，而它能让人**人为指定「这份报告没有风险」**，被误用等于产品欺骗用户。
   必须做到下面之一或全部（二选一即可，建议都做）：
   - **在 `useMock() === false` 的分支里主动清掉该键**（`removeStorageSync`），确保正式模式下设备上不残留；
   - **写入值时带构建标识**：键名或值里拼上构建标记（如 `__QBL_BUILD_ID__` / 构建时间戳），读取时必须匹配当前构建，否则视为未设置。
   验收：设过值后把 `useRealBackend` 设为 `1`（模拟正式模式）→ 该键被清除或不再生效；正式构建产物中该键**无法影响任何界面结论**。

### 验收怎么验
- 在 `D:\qiuzhibilei\src` 下：`npm run build:mp-weixin`（内置 strip-dev-build + postbuild-check）→ **15 组断言全绿**（含「无开发自测」「上屏无 AI」「无 prompt_version」）
- 在 `D:\qiuzhibilei\src` 下：`npm run check:r1`（**54 项**）、`npm run check:report`（33 项）、`npm run check:r3`（38 项）、`npm test`（47 项）全绿
- ⚠️ **不要用 `D:\qiuzhibilei\miniprogram\`** —— 那是 `.gitignore` 忽略的旧目录，其 `check:r1` 只有 43 项，会漏检 11 项
- 存储键设为 `red` → 连续上传 3 张图，**3 次都是 red**；
- 存储键清空 → 上传 5 张，结论**仍然随机**（分布上四种都出现过）；
- **正式模式残留检查**：设 key=`red` → 切 `useRealBackend=1` → 该键已失效/被清（见约束 4）；
- 产物 `dist\build\mp-weixin` 内搜索 `qiuzhibilei_mock_force_overall` 应**只出现在 mock 相关代码**，不出现任何界面文案。

## 改动 2：公司核实卡片补「无全称」两态

### 产品口径（06 号 §三 #11，两态都是明文要求）
- 有公司全称 → 显示「查一下这家公司」+「来自截图」+ 全称 +「复制公司全称」+ 两个官网链接；
- **无公司全称 → 显示「复制这句话问 HR」**。

### 改哪里
| 文件 | 改动 |
|---|---|
| `src\src\pages\report\index.vue` | 公司卡片区块（源码 **L81–L105**，`<view v-if="companyName" class="card corp-card">`）后补 `v-else` 分支：同款卡片外观，**标题两态一致，都是「查一下这家公司」**；副文案 + 一行可复制的提问 + 按钮「复制这句话问 HR」 |
| `src\src\pages\report\index.vue` | 补 `copyAskHr()` 方法（与 `copyCompany` 并列），复制**定稿文本**（见下）；点击后**按钮文字变「已复制」2 秒再恢复** |
| `src\src\common\exampleReports.js` | 给**其中一份**样例（建议 `red` 或新增一份）补 `company` 全称字段，格式符合现有正则：`XX（上海）科技有限公司` 这类「字号 + 有限公司」结构；**用虚构名**（如「示例（上海）科技有限公司」），不得用真实公司名 |

### 文案状态：**【产品已定稿，按下文原文写，一个字都不用改】**

| 位置 | 定稿文字 |
|---|---|
| 卡片标题（两态一致） | **查一下这家公司** |
| 无全称态 · 副文案 | **还没拿到公司全称。把这句话发给 HR，拿到全称再回来查。** |
| 无全称态 · 复制内容 | **请问贵公司全称是什么？我核实一下公司信息。** |
| 无全称态 · 按钮 | **复制这句话问 HR** |
| 复制后反馈 | 按钮文字变 **已复制**，**2 秒**后恢复原文字 |

**定稿说明（产品原意，实现时不要擅自加料）**：
- 复制内容**不要加引号**、不要内嵌句号包装——用户会直接粘进聊天框发给 HR，加了引号显得外行；
- 无全称态**不挂 D20 免责声明**：这句是用户的提问，不是我们的结论，挂了反而把「问一句」写成「法律意见」；
- 标题两态一致：换标题会让用户以为换了功能，提审时也难解释是同一张卡片。

### 实现约束
1. 无全称分支**必须在真实用户路径也生效**，不是只在 mock 里——这是功能缺失，不是截图 hack。
2. 卡片样式走现有 `corp-card` 体系，不新增写死色值（`check:r1` 会拦）。
3. 不得出现「AI」「开发自测」「退出登录」等禁用文案。
4. **复制后必须有反馈**：按钮变「已复制」并保持 2 秒（产品红线），否则用户会以为没点上反复戳。
5. 无全称态**不加 D20 免责声明**。

### 验收怎么验
- 用改动 1 的开关：设 `red` → 报告页**有全称**态可见、复制成功；
- 设 `amber`（该样例无 company 全称）→ 报告页**无全称**态可见：
  - 标题是「查一下这家公司」；
  - 副文案为「还没拿到公司全称。把这句话发给 HR，拿到全称再回来查。」；
  - 按钮为「复制这句话问 HR」，点击后复制成功、**按钮变「已复制」且持续约 2 秒**；
  - **该卡片上不出现 D20 免责声明**；
- `postbuild-check.mjs` + `check:r1` 全绿；
- 包体大小变化记录在提交说明里。
