# 真机预览重出码标准动作（微信小程序）

> 项目：面试请等等（D:\qiuzhibilei）｜ 记录人：软件测试者 ｜ 日期：2026-11-03
> 适用：需要用 `cli.bat preview` 重新生成真机预览二维码时。

---

## 一、结论

可以一键做，不必人肉盯。`preview` 出码这一步依赖真实 AppID，而产物 `project.config.json` 里保持占位符 `touristappid`；因此每次出码 = **注入 → 预览 → 恢复**，三步必须原子完成。

一键脚本：`D:\qiuzhibilei\tests\support\wx-preview-qr.ps1`

```powershell
# 在 D:\qiuzhibilei 下
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\support\wx-preview-qr.ps1
# 产物：reports\真机预览二维码-<时间戳>.jpg
```

脚本内部固定做这 6 件事（顺序不可换）：
1. 从 `$env:DSH_SECRET_WX_TEST_APPID` 读 AppID；**从不打印**，出现即打 `[secret]` 占位；
2. 以**无 BOM UTF-8** 把 AppID 写进 `miniprogram\dist\build\mp-weixin\project.config.json`；
3. 调 `cli.bat preview --project <8.3 短路径> -f image -o <输出图>`（`-f image` 由 CLI 直接出图，不靠截字符画）；
4. **无论成功失败**，在 `finally` 里把产物恢复成源文件的 `touristappid` 占位符；
5. 全仓（排除 `node_modules`/`.git`）扫描 AppID 明文，必须 0 命中；
6. 打印结果路径与码有效期。

## 二、必须知道的坑（全部实测）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | IDE 被普通方式启动 → CLI 一律 `wait IDE port timeout` | 先 `cli.bat quit`，再用 `cli.bat` 带 `--port 9420` 起 IDE。⚠️ 2026-11-03 前端补测：`quit` 本身也走 CLI，同样会超时失败，此时用 `taskkill /F /IM "微信开发者工具.exe" /T` 强制结束；且 IDE 有自动重启行为，清理后要**立刻**用 CLI 带 `--port` 拉起，否则它抢回端口又要重来 |
| 2 | `cmd /c "D:\Program Files (x86)\...\cli.bat"` 路径带空格会截断 | `cd` 到安装目录，用相对名 `cli.bat`（`tests/support/wxdev-cli.ps1` 已封装） |
| 3 | `--project` 传长路径会被 cmd 的 `%*` 展平踩坑 | 传 8.3 短路径（`Get-ShortPath`） |
| 4 | **写产物 JSON 带 UTF-8 BOM → IDE 报「请检查 project.config.json 是否存在及是否有效」且 `Using AppID: undefined`** | 一律 `New-Object Text.UTF8Encoding($false)` 写入 |
| 5 | 用 PowerShell 5.1 默认 `Set-Content` 写中文会变 GBK 乱码 | 读源文件时显式 `[Text.Encoding]::UTF8`，写时用无 BOM UTF8 |
| 6 | 二维码 `-f image -o x.png` 实际产出的是 **JPEG** | 输出名用 `.jpg`；或读出文件头再定扩展名 |
| 7 | 字符画（terminal 格式）扫不出 | 不要用字符画，直接用 `-f image` |

## 三、安全与合规

- AppID 只在环境变量里，**不 ech/o、不进仓库、不进报告**；脚本输出里一律脱敏。
- 产物 `project.config.json` 在 `miniprogram/` 下，`.gitignore` 第 33 行已整条忽略（`git check-ignore` 已确认），且该文件未被 git 跟踪。
- 出码结束**必须恢复占位符**；`git status` 里不应出现该文件。
- 二维码本身有时效，可对外传递；**AppID 不行**。
