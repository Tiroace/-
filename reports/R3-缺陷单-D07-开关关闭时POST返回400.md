# D-07【P2】开关关闭时，POST 社区接口返回 400 而不是 404，泄漏接口存在性

- 发现：软件测试者，2026-10-31 14:30
- 位置：`backend/app/routers/community.py` 中所有带请求体的 POST 端点
- 依据：实施计划 D14 + 测试计划 F-01「开关关闭时接口返回 404，**且不泄漏接口存在性**」

## 一、现象

开关 `QBL_FEATURE_COMMUNITY=0` 时，逐个打社区接口：

| 方法 | 路径 | 期望 | 实际 |
| --- | --- | --- | --- |
| GET | `/community/posts` | 404 | ✅ 404 |
| GET | `/community/posts/{id}` | 404 | ✅ 404 |
| GET | `/community/posts/{id}/experiences` | 404 | ✅ 404 |
| **POST** | `/community/posts` | 404 | ❌ **400** |
| **POST** | `/community/posts/{id}/vote` | 404 | ❌ **400** |
| **POST** | `/community/posts/{id}/experiences` | 404 | ❌ **400** |
| **POST** | `/community/posts/{id}/report` | 404 | ✅ 404（该端点 body 为可选） |
| **POST** | `/community/appeals` | 404 | ❌ **400** |

复现：`pytest tests/community/test_community_rules.py::Test功能开关::test_关闭时所有社区接口404`

## 二、根因

```python
@router.post("/community/appeals")
def create_appeal(body: AppealCreate, request: Request, user: dict = Depends(current_user)) -> dict:
    settings = _require_enabled()      # ← 第一行就检查开关
    ...
```

`_require_enabled()` **确实写在了 handler 第一行**，但 FastAPI 的处理顺序是：

```
请求 → 路径匹配 → 【请求体解析 + Pydantic 校验失败 → 400 VALIDATION_ERROR】→ 才进 handler
```

也就是说，当客户端 POST 一个空 body 或字段不全的 body 时，
**请求在进入 handler 之前就被 Pydantic 挡下并返回 400**，
`_require_enabled()` 根本没机会执行。

对**外部**来说，结果就是：
- GET 接口 → 404（看起来「没有这个功能」）
- POST 接口 → 400「参数不合法」（等于告诉对方「这个接口是存在的，只是我参数没传对」）

## 三、影响

- **严重级 P2**：不是安全漏洞（关着的时候没有数据泄漏），但**违背了 D14 的设计目的**——
  开关默认关是为了资质未核实前对用户「完全不可见」，400 会让探测者知道功能已存在。
- 前端目前靠 `404` 判断是否隐藏入口，**不影响**前端行为（前端发的是合法请求，会正常走到 404）。
- 但在提审 / 对外期间，如果有任何探测，会暴露社区功能已在代码里。

## 四、建议修复（任选其一）

**方案 A（推荐，最干净）**：用依赖注入做开关闸门，让它在 body 校验**之前**生效。
```python
def require_enabled_dep() -> None:
    if not get_settings().feature_community:
        raise not_found("求助广场暂未开放")

@router.post("/community/appeals", dependencies=[Depends(require_enabled_dep)])
def create_appeal(body: AppealCreate, ...): ...
```
FastAPI 的 `dependencies=` 参数的执行顺序在 body 校验之前，
因此空 body 也会先走到 404。

**方案 B**：中间件级拦截。在 app middleware 里对 `/community/*` 前缀统一判断开关，
关闭时直接返回 404——连路由匹配都不必走，最彻底。

**方案 C**：把所有 POST 的 body 参数改成可选（`body: X | None = None`），
让 handler 能先进来。代价是每个 handler 都要自己处理 None，代码变脏，不推荐。

## 五、验证方式

修完后跑：
```powershell
& "...\python.exe" -m pytest tests/community/test_community_rules.py::Test功能开关 -v
```
期望 `test_关闭时所有社区接口404` 与 `test_关闭时错误体与普通404一致` 同时通过。

## 六、附带说明：这一条为什么值得记

刚开始看代码时，`_require_enabled()` 明明在 handler 第一行，
很容易得出「已经做了，没问题」的结论。
**是测试打出来的 400 才暴露了「框架层的校验先于业务逻辑」这个顺序问题。**

同理适用于：任何「开关/鉴权/限流」写在函数体第一行的地方，
只要该端点带**必有请求体**，都要检查是否会被框架的 422/400 抢先返回。
