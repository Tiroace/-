## 三、过程中处理的三件事（都是测试自身问题，不是产品缺陷）

### 1. 初始 6 条 skip 其实是「规则正常工作」
现象：多个投票用例 skip，原因是「发帖前置失败（403）NEW_ACCOUNT_RESTRICTED」。
查明：新注册账号 24h 内不能发帖——**这正是要被验证的规则**，只是我的用例前置没处理好。
处理：新增 `_age_account()`，把测试账号的 `created_at` 拨到 25 小时前。
**这不是绕过规则**，是新号限制由专门用例 `test_新号24小时内不能投票` 单独验证。

### 2. 投票人也要过新手期
修完发帖后仍失败：`新注册账号 24 小时内不能投票`。投票人账号同样要 `_age_account()`。

### 3. 发帖后停在 pending，缺少审核放行接口
现象：帖子创建成功但 `status=pending`，投票接口返回「帖子不存在」。
查明：后端只有「先审后发」**写入 pending** 的逻辑，**没有提供审核放行的 HTTP 接口**。
处理：测试前置直接改库置为 `approved`，同时在代码注释里写明这是临时手段。
**这一缺口登记为 D-08。**

## 四、缺陷单

### D-07【P2】开关关闭时 POST 社区接口返回 400 而非 404，泄漏接口存在性

| 项 | 内容 |
| --- | --- |
| 位置 | `backend/app/routers/community.py` 所有带请求体的 POST 端点 |
| 现象 | `POST /community/posts`、`/vote`、`/experiences`、`/appeals` 在开关关闭 + 空 body 时返回 **400 VALIDATION_ERROR**，期望 404 |
| 根因 | `_require_enabled()` 虽写在 handler 第一行，但 FastAPI **先做请求体 Pydantic 校验**，校验失败直接 400，handler 根本没执行 |
| 影响 | 违背 D14「关闭时对用户完全不可见」的初衷；GET 是 404、POST 是 400，外部可推断「这里有功能」 |
| 影响范围 | 前端不受影响（前端发合法请求会正常走 404）；属于对外探测面问题 |
| 建议修复 | 用 `dependencies=[Depends(require_enabled_dep)]` 把开关做成路由依赖（在 body 校验前执行）；或中间件统一拦截 `/community/*` |
| 复现 | `pytest tests/community/test_community_rules.py::Test功能开关 -v` |

详见 `reports/R3-缺陷单-D07-开关关闭时POST返回400.md`

### D-08【P2】缺少后台审核放行接口，「先审后发」无法闭环

| 项 | 内容 |
| --- | --- |
| 现象 | 帖子创建后状态为 `pending`，但**没有任何 HTTP 接口能把它改成 `approved`** |
| 后果 | ① 真实运营无法审核放行，帖子永远不展示；② 测试只能用改库的方式造数据 |
| 任务书要求 | §11.3「先审后发：机器审核通过即发布，拿不准的进人工审核」——后半句没有实现 |
| 建议 | 补 `POST /community/admin/posts/{id}/approve`、`/reject`，以及审核队列 `GET /community/admin/review-queue`（需管理员权限） |
