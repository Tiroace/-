## 五. 缺陷单

### D-01【P1】词库规则等级未作为下限，模型下调未被拦截

| 项 | 内容 |
| --- | --- |
| 发现时间 | 2026-10-31 00:5x |
| 发现方式 | 全量评测复核：16/20 等级一致，T012/T013/T014 三条标注 warn 被判 notice |
| 影响 | 试用期超限、不缴社保、扣押证件三类**违法条款被降级为「轻微」**，用户会放松警惕 |
| 触发条件 | 模型对规则命中的风险项给出低于词库等级的 level，且该轮的编造项被证据校验删除 |
| 复现 | `pytest tests/engine/test_defect_D01_level_floor.py` |
| 现状 | **未修复（红）** |

**证据链（逐步实测）**

```
规则命中   : R-PROBATION-01 level=warn hard=False   原文「合同期一年，试用期六个月」
模型输出   : 风险项 level=notice                      ← 下调了
校准       : adjustments = []                         ← 没有拉回
最终等级   : notice                                    ← 应为 warn
```

**建议修复**：校准阶段增加「下限回拉」：对每条能与词库规则对应的风险项，
`level = max(模型给的等级, 词库规则等级)`；硬证据仍按 high 兜底。修完跑：

```powershell
python -m pytest tests/engine/test_defect_D01_level_floor.py -v
```
本用例会自动转绿，不需要改测试。

## 六. 关于「测试全绿但没测到」（重要过程记录）

首轮 69 条用例全绿。但做**变异验证**时发现：

> 把「证据校验」整个关掉（`verify_risks` 直接全保留），47 条引擎用例**仍然全绿**；
> 把「等级校准」整个关掉，同样全绿。

原因是 **MockModel 会照抄规则命中**，自己就吐出 `level=high`、`evidence=规则原文`，
所以那两道防线在不工作中也看不出来。

**已补** `tests/engine/test_pipeline_depths.py`：用故意作恶的假模型直接打防线。
重做变异验证：关掉证据校验 → 3 红；关掉等级校准 → 3 红；恢复后 75 绿。**防线现在被真正覆盖。**

**这条经验要一直保留**：以后新增任何「兜底逻辑」，都要配一个「不兜底就一定错」的对抗用例。

## 过程中发现并修正的 3 个测试自身问题（记录备查）

1. **线程池跨用例串扰**：`POST /analysis` 是异步的，上个用例的任务可能在本例运行时仍在跑 → 余额/去重断言抖动。
   **症状**：同一用例单独跑通过、全量跑失败。已用 `worker.shutdown(wait=True)` 在每例收尾。
2. **去重用例的前置不成立**：去重只认 `status=done` 的任务；只传图片不传 `ocr_text` 会因 OCR 不可用而 failed，
   永远等不到 done。已改为「图片 + ocr_text」同时传，与原型期前端用法一致。
3. **余额断言的时间窗口太窄**：任务跑得太快，创建后再查 `/me` 已经回补完成。
   已改为断言**创建响应体里的 `quota.balance`**（契约规定的预扣后余额），不再依赖请求后的时间窗口。

> 这 3 条都是「测试写法错、不是产品缺陷」，在代码注释里写清了原因，避免以后有人照着改错。
