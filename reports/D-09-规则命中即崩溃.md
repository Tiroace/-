# D-09【P0】规则命中的截图会让引擎崩溃：`RuleHit` 缺 `why` 字段

- 发现：软件测试者，2026-10-31 17:30
- 位置：`engine/lexicon.py:316` 的 `RuleHit(...)` 构造
- 触发：**任何一条规则命中的截图**

---

## 一、现象

跑一份**有规则命中**的截图（如 T001，含刷单/垫付话术），引擎直接抛异常：

```
File "engine/pipeline.py", line 172, in analyze
    trace["rule_hits"] = [h.to_dict() for h in hits]
File "engine/lexicon.py", line 88, in to_dict
    "why": self.why,
AttributeError: 'RuleHit' object has no attribute 'why'
```

**注意**：这份报告连生成都做不到。规则命中越多，崩得越快。
没有规则命中的截图（如 S0001 被判 `is_job=False`）反而不崩——所以**冒烟若没覆盖「有命中」的样例就会漏掉**。

## 二、根因

`RuleHit` 定义了 15 个字段：

```
rule_id, type, dimension, level, title, hard, evidence,
matched, start, end, note, why, law, questions, verify
```

但 `lexicon.py:316` 构造时只传了 11 个，**漏掉 `why` / `law` / `questions` / `verify`**：

```python
RuleHit(
    rule_id=..., type=..., dimension=..., level=..., title=...,
    hard=..., evidence=..., matched=..., start=..., end=..., note=...,
)          # ← 缺 why / law / questions / verify
```

而 `to_dict()` 里引用了 `self.why`，于是必崩。

## 三、为什么这是 P0

1. **主流程直接不可用**：真实截图绝大多数会命中至少一条规则。
2. **风险最高的一侧正好崩**：越像骗局、命中越多，越容易崩。
3. 这是路线调整令「确定性引擎」改造中引入的**新回归**，
   说明「改完没有拿一份真实命中样例跑一遍」。

## 四、复现

```powershell
cd D:\qiuzhibilei
& "...\python.exe" -c "from engine.config import default_config; from engine.pipeline import analyze; c=default_config(); c.report_dir=None; c.use_dedupe=False; analyze([], 'data/testset/ocr/T001.txt', config=c)"
```

## 五、建议修复

`lexicon.py:316` 补上四个字段，从 `rule` 取值即可：

```python
RuleHit(
    ...,
    note=rule.note,
    why=rule.why,
    law=rule.law,
    questions=rule.questions,
    verify=rule.verify,
)
```

并在 `RuleHit` 上把 `to_dict` 改为 `self.__dict__` 直出，或给四个新字段默认空值，
避免以后再加字段时又漏。

## 六、给我的教训（测试侧）

这正是「**测试要覆盖真实路径**」的例子：我的引擎用例大量直接用 `analyze()`，
但**冒烟里缺一条「有规则命中的最小样例必须跑通」**。已补（见 `test_defect_D09`）。
