## 二、逐项说明

### 2.1 去 AI 字样（16 处替换 + 页面重写）

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| 首页说明入口 | 本服务由 AI 生成内容，查看 AI 服务说明 | 本服务根据截图文字和规则库自动检查，查看**检查规则说明** |
| 我的菜单 | AI 服务说明 | **检查规则说明** |
| 报告页顶部标识 | AI 生成 · 仅供参考 | **系统自动生成 · 仅供参考** |
| 报告页来源标签 | 规则命中 / 套路库匹配 / AI 推理 | **规则命中 / 套路库匹配**（去掉第三种） |
| 广场详情 | AI 检查结论 | **自动检查结论** |
| 分析中阶段 | 4 段（含「正在写报告」） | **3 段**（读截图→比对套路库→逐项检查） |
| 文档页 | AI 服务公示与生成内容说明 | **检查规则说明**（整页重写） |

**要注意的判定口径**：`fail`、`main`、`aiNotice`、`detail` 这类里含 ai 的**变量名不算**。
断言用的是「独立的 AI 两个字，前后都不是英文字母」的正则。

### 2.2 免责声明新版

```
本报告由系统根据截图文字和规则库自动生成，仅供参考，不构成法律意见，也不代表对任何企业的评价。
```

产品给最终版后替换 `constants.js` 里的 `DISCLAIMER_TEXT` 一处即可（报告页也引用同一个常量）。

### 2.3 检查规则说明页

替换原「AI 服务公示」，五节：

1. 怎么检查（截图读成文字，逐句比规则库和套路库）
2. 规则从哪来（公开法规条文 + 公开反诈案例）
3. **可能漏判**（换说法、图模糊、截一半都会漏；检查通过不代表一定安全）
4. 报告怎么生成（只拼模板，不编造）
5. 内容安全

第 3 节是路线令要求的「可能漏判」，写得很直白。

### 2.4 公司核实卡片（报告页新增）

- 从**截图原文**（findings 的 context/evidence、核实方法）里正则提取公司全称
- 识别特征：以「有限公司 / 有限责任公司 / 股份有限公司 / 分公司 / 集团 / 工作室 / 个体工商户」结尾
- **一键复制公司全称**
- 引导去两个官方渠道：**国家企业信用信息公示系统**、**黑猫投诉**
- **不接第三方数据**：只复制网址 + 提示用户到浏览器搜索（小程序内不能直接打开外域网页）

## 五、真机测试（需要老板操作）

**卡点：游客模式 `touristappid` 不能真机调试，必须换正式 AppID 或测试号。**

步骤（给老板）：

1. 打开微信开发者工具，菜单 **设置 → 项目设置**，或者直接改 `miniprogram/src/project.config.json` 的 `appid`
2. 换成自己的**小程序 AppID**（在 mp.weixin.qq.com 注册后拿到），或用「测试号」
3. 重新构建：`pnpm build:mp-weixin`
4. 点工具栏 **「真机调试」**，生成二维码
5. 手机微信扫码，就能在真手机上看到小程序

**测试号能测什么、不能测什么**：
- ✅ 能测：首页、上传截图、出报告、我的、会员页（展示）
- ❌ 不能测：真实支付、激励视频广告（要正式商户号和广告位）

**我这边卡住的原因**：本机没有正式 AppID，也没有测试号，`touristappid` 生成不了真机二维码。
需要老板注册后把 AppID 给我（或自己替换后扫码）。
