## 一、目标与边界

一句话：**输入 1–3 张招聘截图（原型期为 OCR 文本），按 6 个固定维度逐项亮灯，输出 v2 报告；每条发现都能指回截图原文。**

做：

- v2 报告结构（`overall` + 6 维度 + `findings` + 追问/核实方法 + 两个版本号）；
- 套路库三表 + 本地降级语义匹配（D13），阈值可配；
- 灰灯自动补追问；`overall` 由后端规则算；
- 证据校验覆盖红/黄/绿三种 finding；
- 评测新增「维度级准确率」「套路库召回率」，保留原来三条门槛。

不做：公司黑名单/排行、定性「骗子」、长期存原图、真实云 OCR/向量服务（无账号）。

## 二、报告 JSON v2（唯一契约）

```json
{
  "is_job_posting": true,
  "overall": "red | amber | green | unknown",
  "summary": "一句话结论，30 字以内",
  "dimensions": [
    {"key": "fee", "level": "red|amber|green|none", "short": "≤6 字"},
    {"key": "work", "level": "...", "short": "..."},
    {"key": "title", "level": "...", "short": "..."},
    {"key": "pay", "level": "...", "short": "..."},
    {"key": "company", "level": "...", "short": "..."},
    {"key": "contract", "level": "...", "short": "..."}
  ],
  "findings": [
    {"level": "red|amber|green", "dimension": "fee", "title": "4–8 字",
     "evidence": "截图原文", "context": "包含 evidence 的整句", "reason": "大白话",
     "source": "rule|pattern|llm", "pattern_id": null, "rule_id": "R-DEPOSIT-01"}
  ],
  "questions_to_ask": ["..."],
  "how_to_verify": ["..."],
  "prompt_version": "v2.0",
  "pattern_db_version": "2026-10-30"
}
```

- `dimensions` 固定 6 项、顺序固定：fee 收费与借贷 / work 工作内容 / title 岗位名称 / pay 薪资待遇 / company 公司信息 / contract 合同社保。
- `findings` 每条必须带 `evidence`（原文）与 `context`（包含它的整句）、`source` 来源标签；`source=rule` 必须带 `rule_id`，`source=pattern` 必须带 `pattern_id`。
- `overall` **由后端按规则算**：有红→red，否则有黄→amber，否则绿；非招聘/信息太少→unknown。模型自报的 overall 不采用，前端也不自己算。
- 版本号两处：`prompt_version`（提示词 v2.0）、`pattern_db_version`（套路库 2026-10-30），每条报告都记。

## 三、识别流程（v2）

```
内容安全 → OCR → 去重 → OCR 切句 → 规则词库(6 维度) → 套路库召回 Top5
        → 模型判断(6 维度 JSON) → 补 context 整句 → 证据校验(红黄绿)
        → 等级校准(规则/套路下限) → 组装(灯/overall/灰灯追问) → 脱敏 + PII 硬断言 → schema 校验 → 落库
```

| 步骤 | 实现 | 说明 |
| --- | --- | --- |
| 去重 | `dedupe.py` | 24h 同图直接返回旧报告；key 含词库/套路库/模型/提示词版本 |
| 内容安全 | `adapters/content_safety.py` | 接口 + 本地桩（第二道闸；第一道在上传接口） |
| OCR | `adapters/ocr.py` | 本地旁路文本 / 云 OCR stub |
| 切句 | `textnorm.split_sentences` / `context_containing` | 句子边界做 `context`，保证「包含 evidence 的整句」 |
| 规则初筛 | `lexicon.py` | 规则自带 `dimension` 与 `title`；否定词窗口；`check` 支持薪资跨度/试用期 |
| 套路召回 | `patterns.py` | 每句可同时命中多条套路，按套路去重取 Top5；阈值可配（默认 0.35） |
| 模型 | `adapters/models.py` | `MockModel`（默认）/ `DeepSeekModel`（无 key 明确报错） |
| 证据校验 | `evidence.py` | evidence 不在 OCR 原文就删（编造防护，绿灯同样要证据） |
| 等级校准 | `calibrate.py` | 规则/套路等级是下限（D-01）；模型漏报硬证据时按规则兜底补一条 |
| 组装 | `report.py` | 维度灯 = 该维度 findings 最高等级；灰灯补追问；overall 规则计算 |
| 脱敏 | `report.py` + `textnorm` | summary/reason/evidence/context/questions 全部脱敏；脱敏前原文留 `trace.evidence_raw` |
| PII 断言 | `pipeline.py` | 报告 JSON 全文扫手机号/身份证/银行卡/微信号/邮箱，残留即 `PII_LEAK` 失败并退次数 |
| schema | `schema.py` | 两档校验：模型原始输出（决定重试）/ 最终报告（一致性、overall、灯与 findings 对齐） |

## 四、词库 v2（运营可配置，不发版）

`lexicon/lexicon_v2.json`：**25 条规则**，其中 4 条是绿色规则（正面证据），覆盖 6 维度。

规则字段新增：`dimension`（6 维度之一）、`title`（finding 标题 4–8 字）、`level` 支持 `green`（出绿灯 finding）。其余（`rule_id`/`type`/`hard`/`match`/`keywords`/`regex`/`check`/`negations`/`说明`）沿用。

- `hard: true` 的规则命中即硬证据，等级不得下调，模型漏报时兜底补一条。
- 绿色规则只用于「这一项写得清楚」的正面证据，同样要能对回原文。
- 运营加词流程：改 JSON → `python -m engine.evaluate --compare data/eval/eval_report.json` → 指标不降才发布。

## 五、套路库（三表 + 本地降级匹配，D13）

- 表结构：`patterns`（id/name/dimension/level/why/how/status/source/updated_at）、`pattern_examples`（pattern_id/text）、`pattern_hits`（pattern_id/report_id/hit_at，不存用户截图）。
- 种子：`lexicon/patterns_v1.json`，R3 已扩到 **50 条**（每条 3–6 条话术样本，目标 5–10 条），只描述话术、不写公司名；后端启动时「表为空才灌」。
- 匹配：每个 OCR 句子做向量检索 → 取最相似套路 → 跨句 Top5；相似度低于阈值丢弃（阈值在 JSON 与 `QBL_PATTERN_THRESHOLD` 都可调）。
- **降级实现（D13）**：`EmbeddingProvider` 接口 + `LocalTfidfProvider`（字符 bigram + TF-IDF 余弦，数字连续段压成 `#` 防手机号/金额噪声）。拿到云向量服务只换 provider，不动上层。
- 命中落库：报告落库时把 `findings[].pattern_id` 写进 `pattern_hits`，首页「最近常见」按近 7 天真实命中次数排序（`GET /patterns/recent`）。

- 标注口径：维度灯按「这条招聘信息在这一维度上有没有风险」；绿灯 = 写得清楚且引用得到原文。
- 生成脚本 `python scripts/gen_testset_seed.py`（可复跑）。
- 300 张真实测试集仍等授权（docs/02 第 11 条），这 20 条是链路自测集，不是 A 关口依据。

## 七、评测指标与本次实测

指标口径写死在 `engine/evaluate.py`：

| 指标 | 定义 | 门槛 |
| --- | --- | --- |
| 整体结论准确率 | overall 与标注一致的比例 | — |
| 高危召回率 red_recall | 标注 red 的样例判成 red 的比例 | ≥ 90%（沿用） |
| 正常误判红 green_false_red | 标注 green 的样例判成 red 的比例 | ≤ 5%（沿用） |
| 维度级准确率 | 6 维度灯色判对比例（120 个灯） | ≥ 80%（R1 试用门槛） |
| 套路库召回率 | 标注套路在检索/发现里命中的比例 | ≥ 60%（R1 试用门槛） |
| 证据可追溯率（脱敏前） | evidence 在 OCR 原文可找到的比例 | 100% |
| context 自洽率 | context 包含 evidence 的比例 | 100% |
| 输出层 PII 泄漏 | 报告 JSON 全文扫描 | 0 处 |

2026-10-31 实测（20 条，MockModel 注入缺陷）：

```
整体结论准确率      100.00%
高危召回率(red)     100.00%  pass
正常误判红          0.00%    pass
中风险报警率(amber) 100.00%
维度级准确率        92.50%  (111/120)  pass
套路库召回率        76.19%  (16/21)    pass
套路库精确率        42.11%（本地降级实现，见下面说明）
证据可追溯率        100.00%  pass
context 自洽率      100.00%  pass
PII 泄漏            0 处      pass
灰灯追问率          100.00%
平均耗时            95 ms
```

说明：Mock 的指标只证明链路正确（防编造、等级校准、灰灯、PII 过滤），**不代表真实识别准确率**；接 DeepSeek/云 OCR 后再按 300 张重测。

套路库精确率偏低（42%）是本地降级（字符 n-gram + TF-IDF）的已知短板：50 条套路下按召回优先把阈值放到 0.35，错配增多但都被规则去重/维度校验兜住（维度准确率仍 92.5%、overall 100%）。接云向量后应同时重调阈值并复核精确率。

## 八、隐私与红线落点

| 红线 | 落点 |
| --- | --- |
| 不执行截图里的指令 | 系统提示词红线 + `R-INJECT-01` 当风险提出（T007 用例） |
| 每条发现引用原文 | `evidence.py` 校验；`context` 由切句重算 |
| 证据/上下文脱敏 | `report.apply_text_policy` 全覆盖；原文留 trace |
| 不出现定性词 | `BANNED_WORDS` 替换并留痕 |
| 不说公司是骗子 | 提示词红线 + 文案过滤 + schema 里没有定性字段 |
| PII 零泄漏 | `find_pii` 硬断言，残留即失败退次数 |
