# 内测与上线后节奏

> 依据：老板 2026-10-31 要求。前提：拿到**正式 AppID** 之后才能开始。

## 一、上线前：小范围内测（1 周）

1. **范围**：10–20 位真实求职者（应届生、蓝领/服务业、宝妈兼职、转行人群各覆盖一些）。
2. **方式**：正式 AppID 的真机预览/体验版；每人至少用 3 次（上传→报告→反馈）。
3. **收集**：
   - 产品反馈：报告是否看得懂、结论是否有用、最想改哪一处；
   - 「判断不准」按钮的反馈逐条登记；
   - 真实招聘截图：**必须征得本人同意**，打码后进测试集（real 轨道），记同意与打码状态。
4. **内测门槛（进公开上线前）**：
   - 真实截图轨道 ≥120 张；
   - 高危召回 ≥90%、正常岗位误判高危 ≤5%（真实/合成分开统计）；
   - 无 P0/P1 缺陷遗留；
   - 律师审阅完成（免责声明/协议/隐私政策/社区规范）。

## 二、上线后：每周一次固定节奏

| 动作 | 说明 |
| --- | --- |
| 复核「判断不准」反馈 | 逐条看，区分「模型/规则判错」与「用户预期不符」；判错的补规则或补反例 |
| 更新规则/套路库 | 新规则先加反例与正例样本；运营可加词，不发版 |
| 每周政策简报 | 合规助理出，附官方来源 |
| 数据看板复盘 | 看完成率/失败率/红黄绿分布/广告与会员转化/次日留存 |

## 三、发布闸门（rules_version 每次升级必须走）

1. 改规则/套路库 → 升 `RULES_VERSION`；
2. 跑**留出集**（`eval/splits.json` 里冻结的 holdout）与练习集，两套分开报；
3. 指标不退化才能发布：高危召回不降、正常误判不升、证据可追溯 100%、确定性不变；
4. 发布后 24 小时盯看板失败率与「判断不准」比例；
5. 退化就回滚版本（规则文件与 `rules_version` 一起回退），并在 DECISIONS 记原因。

## 四、责任

- 内测招募与同意书：老板本人；
- 反馈复核与规则更新：软件开发者 + 测试者；
- 数据看板与失败率监控：运维；
- 每周政策简报：合规助理；
- 汇总与对外：Chief。
