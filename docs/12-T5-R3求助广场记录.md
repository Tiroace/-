## 三、社区三页

### 3.1 开关策略（D14）

后端 `QBL_FEATURE_COMMUNITY=0` 时所有 `/community/*` 返回 **404**。
前端不写死开关，而是**探测后端真实状态**：

```
fetchPosts(limit:1)
  → 成功     ⇒ 社区开放，渲染页面
  → 404      ⇒ 社区关闭，整页隐藏（不是显示「开发中」）
  → 其它错误 ⇒ 按关闭处理（不让用户看到坏页面）
```

`common/features.js` 做运行内缓存，避免每个页面都打一次接口。

**mock 层同口径**：`services/communityMock.js` 默认也抛 `NOT_FOUND`，
只有本地存储 `qiuzhibilei_mock_community = '1'` 才返回数据。
这样产品/老板想预览社区页面时打开这个开关即可，不需要起真后端。

### 3.2 广场列表（设计稿 06）

- 搜索：公司名 / 岗位 / 城市 / 提问
- 排序：最新 / 参与最多 / 我投过的
- 帖子卡：公司名 + 结论小灯 + 职位·城市 + 提问 + 投票比例条 + 人数 + 经历数
- 右下角「发起求助」悬浮按钮
- 底部标注「只代表个人经历」

### 3.3 求助详情（设计稿 07）

- 投票：建议去 / 不建议去；**再点同一项 = 取消**（一人一票可改）
- 理由标签：我也被要求过交钱 / 岗位和说的不一样 / 面试流程正常 / 其他
- 经历列表 + 写经历（先审后发）
- 举报弹层（5 种理由）
- 企业申诉弹层（企业全称 + 联系方式 + 理由，提示 24 小时处理）
- AI 结论框标注「只针对截图内容」

### 3.4 发起求助（设计稿 08）

- **必须选一份检查记录**（没有记录引导去做检查）
- 打码预览 + 补充打码
- 公司 / 职位 / 城市 / 提问（**上限 200 字**，带计数器）
- 匿名开关（**默认打开**）
- **必须勾选**「确认是真实经历并已阅读社区规范」
- 撰写提示：「写事实，不写『骗子』这类结论」

### 3.5 错误码 → 大白话

| code | 提示 |
| --- | --- |
| `NEW_ACCOUNT_RESTRICTED` | 账号注册还不满 24 小时，暂时不能发帖和投票 |
| `CONTENT_BLOCKED` | 内容没通过审核，请改成描述事实 |
| `FORBIDDEN` | 不能给自己的帖子投票 |
| `NOT_FOUND` | 内容不存在或已隐藏 |

## 六、遇到的问题

### 1. 社区开放与否前端说了不算，必须探测

如果按环境变量写死，可能出现「前端以为开了、后端其实关着」→ 用户点进去 404。
所以采用**探测后端**的方案，两边永远一致。

### 2. 打码预览目前是文案示意

真环境下打码后的图片地址要由后端在发帖响应或预览接口返回。现在 `mask_supplement` 只是把
「用户补充打码」这个意图传给后端，真正的遮罩交互要等后端提供预览图接口。

端口一通就能出对比图。
