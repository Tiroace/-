## 一、修了什么

### D-05【P1】正式包 `app.json` 含 `pages/dev/index`

**现象**：`dist/build/mp-weixin/app.json` 的页面列表里有 `pages/dev/index`，
整个 `pages/dev/` 目录随包发布。审核员能在包里翻到调试页（含「切真后端 / 强制 mock」开关）。

**根因**：`pages.json` 是静态的，`v-if` 只影响渲染、**不影响打包**。
之前用 `process.env.NODE_ENV` 做运行期判断，页面照样编进包里。

**修法**（采取「构建后置处理」，比维护两份 pages.json 更稳）：
新增 `scripts/strip-dev-build.mjs`，在正式构建后做三件事：

1. 从 `app.json` 的 `pages` 里移除 `pages/dev/index`
2. 删除 `dist/pages/dev/` 整个目录
3. 扫全包，若仍出现「开发自测」等文案 → **退出码 1**（CI 能挡住）

已接进 `package.json`：

```json
"build:mp-weixin": "uni build -p mp-weixin && node scripts/strip-dev-build.mjs dist/build/mp-weixin",
"build:mp-toutiao": "uni build -p mp-toutiao && node scripts/strip-dev-build.mjs dist/build/mp-toutiao"
```

### D-06【P2】「我的」页 wxml 残留「开发自测」字符串

**修法**：入口改用**编译期条件编译**，不再是 `v-if`：

```vue
<!-- #ifdef MP-DEV -->
<view class="card dev-entry" @tap="gotoDev">
  <text class="dev-text">开发自测</text>
</view>
<!-- #endif -->
```

`MP-DEV` 只在开发构建时定义，正式构建整段不参与编译，**字符串根本不进包**。
（文案也从「开发自测（仅开发环境）」简化成「开发自测」，减少特征串。）

### P1 广场发帖页写死色值

`pages/post-create/index.vue` 的 `<switch color="#FFC93C">` → `:color="SWITCH_COLOR"`，
常量放在 `common/brand.js`（原生组件 color 属性只接受字面量，所以集中在常量文件里）。

**顺带**：开发自测页那 3 个 `<switch color="#2b6cf6">`（蓝色）也一并换成 `SWITCH_COLOR`。
之前测试者报的「dev 页 3 处蓝色」是真实存在的，只是写在模板属性里、`<style>` 块扫不到。

## 四、口径分歧的说明

测试者报「前端写死色值 = 0 不对」，指的是 `pages/dev/index.vue` 的 3 个
`<switch color="#2b6cf6">`。这个反馈**是对的**：

- 我的 `check-r1` 原先只扫 `<style>` 块
- 他把整份文件（含 `<template>` 属性）都扫

两边都没写错，是**扫描范围不同**。现在已经：
1. `check-r1` 增加「模板属性色值」扫描（含 `color=` / `background=` 等）
2. 全项目模板属性写死色值 = 0
