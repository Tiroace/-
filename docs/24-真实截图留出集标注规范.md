# 真实截图留出集 · 标注规范（v1）

- 制定：2026-11-03（第 4 关准备）
- 依据：`docs/23-上线总清单与派单.md` 第 4 关——**≥60 条真实截图标注、正常岗位占一半、高危召回 ≥90%、正常误判 ≤5%**
- 适用范围：真实截图轨（`track=real_screenshot`）。**与现有 `real_text` 轨是两套东西，不能混算**（见 §一）

---

## 一、先说清楚：这和现在的 129 条有什么关系

| 轨道 | 现在有多少 | 图从哪来 | 能证明什么 | 算不算第 4 关 |
| --- | ---: | --- | --- | --- |
| `real_text` | 129 条 | **文字真，图是渲染出来的** | 规则能不能识别真实骗术话术 | **不算** |
| `real_screenshot` | **0 条** | 真机实拍 / 公开页摘录 | 整条链路（OCR→规则→报告）在真实图片上准不准 | **算** |

第 4 关要的是**第二行**。之前多次强调过不能把 `real_text` 混进「真实截图」的数字里——混进去就是虚高，等于骗自己。

**结论**：规范今天出，真实截图等内测收集。收满 60 条之前，第 4 关的评测条件**不成立**，不能先报数。

## 二、一条样本要长什么样

### 2.1 必填字段

| 字段 | 说明 | 校验 |
| --- | --- | --- |
| `id` | `RS` + 4 位序号，如 `RS0001` | 前缀必须是 `RS` |
| `track` | 固定 `real_screenshot` | 必须等于该值 |
| `image` | 图片相对路径，如 `data/testset/images/RS0001.png` | 文件必须存在 |
| `ocr_text` | 该图的 OCR 结果文件路径 | 由脚本生成，不许手写 |
| `source.type` | `real_phone`（本人实拍）/ `public_page`（公开页摘录，B 类） | 二选一 |
| `source.url` | 公开页的来源 URL；实拍填 `null` | `public_page` 时必填 |
| `source.collected_at` | 采集日期 `YYYY-MM-DD` | 必填 |
| `masked` | 是否已打码（姓名/手机号/微信号/头像） | `true/false` |
| `label.overall` | `red` / `amber` / `green` / `unknown` | 枚举 |
| `label.dimensions` | 六维各一值，`red/amber/green/none` | 六维必须齐 |
| `label.verdict_reason` | **一句话说清为什么是这个结论**（≤40 字） | 必填，空则拒收 |
| `annotator` | 标注人 | 必填 |
| `annotated_at` | 标注日期 | 必填 |
| `difficulty` | `easy` / `medium` / `hard` | 枚举 |
| `is_normal` | 是否正常岗位（用于核对"正常占一半"） | 布尔 |

### 2.2 六维定义（沿用现有口径，不新造）

`fee` 收费与借贷 / `work` 工作内容 / `title` 岗位名称 / `pay` 薪资待遇 / `company` 公司信息 / `contract` 合同社保

某一维在图上**完全没提** → 标 `none`（灰灯），并在 `verdict_reason` 里体现「未提及」，**不要**因为「看着像有问题」就点灯。

### 2.3 打码规则（硬性）

必须打码：**姓名、手机号、微信号/QQ、身份证、住址门牌、头像人脸、公司内部工号**。
不必打码：岗位名称、薪资数字、公司公开名称、招聘平台 UI。
打码后要保证**结论依据那句话仍然可读**——把「加我V：abc12345，押金600」整段糊掉，样本就废了。

**来源纪律**：公开页只做少量摘录（B 类），不批量爬、不绕登录、不用别人账号。本人实拍优先。

## 三、分布要求（脚本会检查）

| 项 | 要求 | 理由 |
| --- | --- | --- |
| 总条数 | **≥60** | 硬门槛 |
| 正常岗位（`is_normal=true`） | **≥50%**（即 ≥30 条） | 只有正常占一半，才能测出误判率 |
| 高危（`overall=red`） | ≥15 条 | 召回率分母够才可信 |
| 每个 `style` | 岗位详情/聊天记录/招聘广告各 ≥10 条 | 三种形态都要覆盖 |
| 维度覆盖 | 六维各 ≥8 次「非 none」 | 防止只测收费一种 |

**为什么必须一半正常**：预测全绿可以拿到 100% 的「≤5% 误判」，但召回是 0。只测骗子样本则相反。两个指标必须在一份「正常与高危混合」的集上同时成立才有意义。

## 四、验收指标（第 4 关判定）

用**本留出集**跑一次，同时满足：

| 指标 | 定义 | 门槛 |
| --- | --- | --- |
| 高危召回 | `overall=red` 的样本里，引擎也判 `red` 的比例 | **≥90%** |
| 正常误判 | `is_normal=true` 的样本里，引擎判 `red`（或 `amber`）的比例 | **≤5%** |
| 证据可追溯 | findings 的 evidence 能在 OCR 原文里找到 | **100%** |
| 结果一致 | 同一张图跑两次结论完全相同 | **100%** |

指标不达标就是不过，**不许靠调阈值去凑**，更不许拿留出集调参——留出集一旦被用来调参就不叫留出集了（这就是 `eval/splits.json` 里那句「冻结后不得改动」的原因）。

## 五、标注流程

1. **收集**：实拍/摘录 → 复制到 `data/testset/images/`，命名 `RSxxxx.png`
2. **打码**：`scripts/annotate_screenshot.py mask` 辅助记录（人工确认，不做自动识别）
3. **OCR**：`scripts/annotate_screenshot.py ocr` 跑引擎 OCR，落 `data/testset/ocr/RSxxxx.txt`
4. **标注**：`scripts/annotate_screenshot.py add` 交互录入，写进 `data/testset/real_screenshots_v1.jsonl`
5. **校验**：`scripts/annotate_screenshot.py check` —— 字段齐全、分布达标、打码标记齐
6. **评测**：`scripts/eval_holdout.py` —— 出四项指标，不达标 `exit 1`

## 六、双人标注与仲裁

前 10 条**两人独立标**，算一致性（结论一致率 < 80% 说明规范本身有歧义，先修规范再继续）。
有分歧的样本进 `data/testset/arbitration_v1.jsonl`，由产品经理按 D30/D32/D34 已定口径裁决，**裁决结果要回写规范**，避免下一批又吵同一件事。

## 七、这条规范的自我约束

- 留出集**不参与**规则调试。工程师调规则只看练习集。
- 每收一批（≥20 条）就做一次分布检查，防止前面收的全是骗子、后面补的全是正常，最后凑不出 60 条合格样本。
- 报告里必须写清**采集时间段**和**样本来源构成**（实拍 X 条 / 公开页 Y 条），后来人才能判断这个数字能不能复用。
