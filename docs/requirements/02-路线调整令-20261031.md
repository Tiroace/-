# 面试请等等 · 路线调整令

2026-10-31。本令优先于之前所有文档；和《改版任务书》《项目任务下派书》冲突的地方，以本令为准。

## 一、老板的决定

1. **一期不用大模型，不要 DeepSeek key。** 识别全部用程序：本地 OCR + 规则引擎 + 套路库匹配。
2. **不用云 OCR。** 用开源 OCR，部署在自己的服务器上。
3. **不做生成式 AI 登记。** 不用大模型，就不属于《生成式人工智能服务管理暂行办法》的适用范围（第二条、第二十二条：适用于有内容生成能力的模型）。产品里不出现「AI」字样。
4. **测试截图你自己收集、自己合成。** 来源已授权，见第四节。
5. **7 天内交付：** 准确率报告 + 真机跑通的录屏。

不要再把「等 key」「等 OCR 账号」「等登记」列成卡点。

## 二、识别引擎改造

替换《改版任务书》第 4 节里所有用到大模型的步骤。流程：

1. **OCR**：用 RapidOCR（Apache-2.0，可商用，默认支持中文，`pip install rapidocr onnxruntime`），跑在服务器 CPU 上，离线运行；备选 PaddleOCR。
   - 每张图长边缩到 1600 以内。
   - 按行输出文字和坐标，同一行的文字合并。
2. **文本规整**：
   - 全角转半角，繁体转简体（OpenCC），去掉多余空格，中文数字转阿拉伯数字。
   - 建一张「变形写法」表，例如：V信、薇信、威信 → 微信；扣扣 → QQ；「押 金」「ya金」→ 押金。表放后台，运营可以随时加。
3. **判断是不是招聘截图**：文字少于 20 个字，或一个招聘关键词都没有（招聘、岗位、薪资、底薪、月薪、面试、入职、上班、HR、工作），就判为 unknown，退回次数。
4. **规则引擎**：6 个维度各一组规则（见第三节）。规则命中的那段 OCR 原文，就是证据。
5. **套路库匹配**：jieba 分词 + TF-IDF 余弦相似度，加关键词组覆盖率，阈值用测试集调。全部是确定性计算，同一张图每次结果一样。
6. **整体结论**：按《改版任务书》4.2 第 8 步算：任一维度红灯 → 红；否则有黄灯 → 黄；否则 → 绿。
7. **报告文字**：每条规则、每个套路都自带模板（标题、为什么有风险、法条、要问 HR 的问题、核实方法）。报告按命中结果拼出来，不临时生成新文字。
8. **报告 JSON 结构不变**（见《改版任务书》4.4），只改两处：
   - `source` 只剩 `rule` 和 `pattern` 两种。
   - `prompt_version` 改名 `rules_version`。

另外：

- 保留一个「模型插件」接口，默认关闭。以后要开，必须先办生成式 AI 登记。
- 单次检查（最多 3 张图）5 秒内出结果。

## 三、六个维度的首批规则

先照这个写，再用测试集调。

| 维度 | 红灯 | 黄灯 | 绿灯 | 灰灯 |
| --- | --- | --- | --- | --- |
| 收费与借贷 | 押金、保证金、服装费、工装费、体检费、培训费、材料费、入职费，加上交、缴、付、收；办卡、贷款、分期、垫付；索要银行卡号、验证码 | 「自费」「费用自理」这类模糊说法 | 截图里没发现收费要求 | — |
| 工作内容 | 刷单、点赞返利、关注返利、做任务、垫付；打字员、手工活带回家；境外高薪（缅甸、柬埔寨、迪拜等，加高薪或包机票） | 要求下载陌生 App、进 QQ 群 | 职责写得具体（命中 2 个以上常见职责词） | 没写职责 |
| 岗位名称 | — | 岗位名是储备干部、管培生、行政助理、客服、总裁助理、人事助理这类，职责里却有电话、回访、销售、地推、拉新、保险、理财、开发客户、直播带货、业绩 | 名称和职责对得上 | 没写职责 |
| 薪资待遇 | — | 最高工资是最低的 2.5 倍以上；写「无需经验」「零基础」，最高工资却在 15000 以上；「上不封顶」「轻松月入过万」「日赚」「躺赚」；只写「综合薪资」 | 有具体数字，区间合理 | 没写工资 |
| 公司信息 | — | 只留个人微信、QQ 或手机号，没有公司名 | 有「……有限公司」这类全称或详细地址 | 两样都没有 |
| 合同社保 | 扣押身份证、毕业证 | 试用期超过 6 个月；试用期不交社保；社保只写「按国家规定」 | 写了劳动合同或五险一金 | 没提到 |

薪资解析要支持这些写法：8000-20000、8k-2w、8千到1.5万、日结200-500（按 22 天折成月薪）、年薪。

## 四、测试截图：你自己收集，来源已授权

目标 300 张：真实截图至少 120 张，其余合成。真实和合成的准确率分开统计。

| 来源 | 怎么收 | 要求 |
| --- | --- | --- |
| A 公开反诈案例 | 公安、网信、人社部门官网和公众号公布的招聘诈骗案例，以及新闻报道 | 记下出处链接 |
| B 公开投诉平台（黑猫投诉等） | 人工浏览，少量摘录话术和截图 | 只用于内部测试，不对外展示；人名、电话、账号先打码 |
| C 正常岗位 | 人工在招聘 App 上浏览，截取正常岗位 | 同上 |
| D 合成样本 | 用话术模板 + 程序，渲染成「岗位详情页」和「聊天记录」两种样式的截图；专门做变形写法、模糊、只截一半的样本 | 标明是合成 |

不允许：批量爬取、绕过登录或反爬、用别人的账号、把采集到的内容对外展示。

## 五、查公司信息（新增）

- **一期**：从 OCR 文字里提取公司全称，报告里放一张「核实这家公司」卡片：一键复制公司名，配文字说明，教用户去国家企业信用信息公示系统、黑猫投诉搜索。
- **一期之后**：接企查查或天眼查开放平台的工商信息接口（按次付费，Bot 先查清价格报给老板）。取成立时间、经营状态、经营异常、经营范围，新增三条规则：
  - 成立不到 3 个月 → 黄灯
  - 经营异常或已吊销 → 红灯
  - 经营范围和岗位明显不符 → 黄灯
- 不爬 BOSS 直聘、黑猫投诉的数据放进产品。

## 六、文案改动

- 去掉所有「AI」字样：
  - 「AI 检查」改成「自动检查」。
  - 「AI 服务说明」改成「检查规则说明」，写清楚怎么检查、规则从哪来、可能会漏判。
  - 免责声明改成：「本报告由系统根据截图文字和规则库自动生成，仅供参考，不构成法律意见，也不代表对任何企业的评价。」
- 「具体发现」的来源标签只剩「规则命中」和「套路库匹配」。
- 「分析中」页面的文案：正在读截图 → 正在比对套路库 → 正在逐项检查。
- 删掉生成式 AI 登记、模型公示相关的页面和任务。
- 求助广场继续关着（开关默认关闭）。对外开放前，仍按《改版任务书》11.6 节核实。

## 七、上线只差这几件事

| 事项 | 谁做 | 多久 |
| --- | --- | --- |
| 真机测试 | Bot：今天就用微信开发者工具的「测试号」扫码在真机上跑（测试号不能测付费和广告） | 今天 |
| 营业执照（个体工商户，线上办） | 老板本人 | 几天 |
| 注册小程序拿正式 AppID：先注册抖音小程序（广告收入在抖音），微信同时注册 | 老板本人（要实名和人脸认证）；Bot 先写好一步一步的注册说明 | 执照下来当天 |
| 小程序 ICP 备案 | 在小程序后台提交，Bot 准备材料 | 管局审核 1–20 个工作日，看省份 |
| 付费和广告的真机测试 | Bot | 拿到正式 AppID 后 |
| 律师看一遍协议 | 老板找人 | 公开上线前，不卡开发 |

主体注册后不能更改，所以先办执照，再注册小程序。

## 八、7 天排期

| 天 | 做什么 |
| --- | --- |
| D1–D2 | 拆掉大模型；接入 RapidOCR；写规则引擎和变形写法表 |
| D3–D4 | 套路库首批 50 个；测试集先合成 200 张，同时收集真实截图 |
| D5 | 跑评测，调阈值 |
| D6 | 改文案；用测试号在真机上跑通 |
| D7 | 交付 |

D7 交付：

- 准确率报告：真实和合成分开、6 个维度分开。
- 漏判、误判各列 20 条，写清原因和修法。
- 真机录屏。

验收门槛不变：高危召回率 ≥ 90%，正常岗位误判高危 ≤ 5%；另加单次检查 ≤ 5 秒。

## 九、测试变慢

测试分成两套：

- 快速冒烟：1 分钟内跑完，每次提交都跑。
- 全量：每天跑一次。

找出最慢的 10 条用例，社区和 IP 风控那几条改成共用一个服务实例。

## 十、汇报方式

每天一条：今天完成了什么、明天做什么、需要老板做的事。最后一项只列必须老板本人做的事（实名、人脸、付钱、签字），能自己解决的不要列成卡点。
