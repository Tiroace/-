## 一、三类反馈分开做，别混一个按钮

| 类型 | 谁提 | 诉求 | 处理时限 | 入口 |
| --- | --- | --- | --- | --- |
| 判断不准 | 使用者本人 | 认为报告判错了 | 目标 7 个工作日答复；留样需单独同意 | 报告页「判断不准」 |
| 内容申诉 | **企业 / 个人（含被提及的 HR、公司）** | 认为某份报告内容不当、侵犯权益 | 目标 7 个工作日答复 | 「我的」→ 申诉／也可在报告页点「我要申诉」 |
| 意见反馈 | 任何人 | 功能建议、体验问题 | 不承诺时限，但会回复 | 「我的」→ 意见反馈 |

## 二、入口设计（P0）

### 2.1 报告页底部

```
[判断不准]   [我要申诉]
```

- 「判断不准」：只有报告所有者可见。
- 「我要申诉」：**所有能看到报告的人都可见**（含被评价企业通过公开渠道联系我们时，也走这里）。

### 2.2 「我的」页底部

```
联系我们 / 申诉与投诉 → 申诉表单
```

### 2.3 企业侧入口（企业没有小程序账号也能提）

企业或个人不必注册、不必登录即可提交申诉，方式二选一：

1. 打开小程序 → 「我的」→ 申诉与投诉 → 选择「我是企业」→ 填写；
2. 邮件至【待老板确认：申诉邮箱】，格式见第三节。

> 关键：**不能设置「必须登录才能申诉」的门槛**，否则等于剥夺第三人救济渠道。

## 三、申诉表单字段（企业侧）

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 申诉类型 | 是 | 内容不实／侵犯名誉／泄露个人信息／其他 |
| 企业或个人名称 | 是 | |
| 统一社会信用代码／身份证明 | 是（可后补） | 用于核验主体真实身份，**只核验不用作他途** |
| 涉及的报告编号或分享图截图 | 是 | 没有编号可用分享图截图 |
| 具体问题描述 | 是 | 说明哪一句、为什么有问题 |
| 证明材料 | 否 | 营业执照、授权书、更正说明 |
| 联系方式 | 是 | 邮箱或电话（**仅用于回复**） |

## 四、处理流程与时限

| 步骤 | 动作 | 时限（内部 SLA） | 责任 |
| --- | --- | --- | --- |
| 1 受理 | 收到后回执（邮件/站内） | 1 个工作日内 | 客服 |
| 2 核验 | 核验主体真实性，确认报告是否存在 | 2 个工作日内 | 客服 + 产品 |
| 3 研判 | 复核报告内容：证据是否在 OCR 原文中、措辞是否越界 | 2 个工作日内 | 产品 + 测试 |
| 4 处置 | ①不成立：说明理由；②成立：删除/更正报告并告知申诉人 | 2 个工作日内 | 产品 |
| 5 答复 | 书面答复申诉人，说明结论与理由 | **合计不超过 7 个工作日** | 客服 |
| 6 加急 | 涉嫌诽谤、涉及大规模传播的，**24 小时内先行下架**再研判 | 24 小时 | 值班负责人 |
| 7 复盘 | 对已确认的错误，进评测集、修提示词 | 每周 | 产品 + 开发 |

**SLA 兜底**：7 个工作日是下限目标；若需延期（例如需向模型服务商核实），必须**在第 7 个工作日前书面告知申诉人**并给出新的答复时间，不能沉默。

## 五、处置口径（写死，避免各说各话）

1. **不评价企业**：我们的报告只针对截图内容。发现报告出现「这家公司是骗子」类表述，一律视为缺陷：**立即下线该报告并修提示词**（这是 bug，不是申诉才处理）。
2. **报告只有上传者本人可见**：若申诉人不是上传者，我们核实到报告未公开传播，向申诉人说明「该报告未对外展示」，同时评估是否需要删除该报告。
3. **涉及个人信息**：如报告或分享图暴露了 HR 的手机号、姓名等，按「个人信息泄露」加急处理（24 小时内处理）。
4. **不做「删帖换钱」**：任何人以付费为条件要求删除他人合法报告，一律拒绝并记录。

## 六、高危报告强制提示（P0，下派书 §8；**v2 口径**）

高危（`overall = red`）报告页的「已经交了钱？」区块：**固定展示、不可关闭**。

```
重要提醒
· 不要转账，不要交任何押金、服装费、体检费、培训费。
· 遇到诈骗，拨打 110 报警，或拨打 96110 反诈专线。
· 劳动权益问题（欠薪、不缴社保、扣押证件），可拨 12333。
```

- **v2 口径变更**：v1 用 `risk_level = high` 判定，v1 已作废；v2 判定条件改为 **`overall = red`**（后端按规则算：有任一红灯维度即 red）。
- 与报告页设计稿 6.3 一致：报告页另有「已经交了钱？」区块，仅在 `overall = red` 出现，两者并存不冲突。
- **D21 排法（执行口径）**：`overall = red` 区块里**只有 110、96110 两个拨号按钮**；**12333 不做拨号键**，是按钮下方单独一行文字「劳动权益问题（欠薪、不缴社保、扣押证件），可拨 12333」。理由：12333 是人社服务热线，不是反诈，做成拨号键会让用户误以为能追回被骗的钱。
- 要求：字体不小于正文；不能折叠、不能弹窗「知道了」后就消失；**不得使用 emoji**（上面那个警告符号仅为本文件示意，界面上用线性图标）。
- **显示范围（D21 补充，2026-11-03）**：110 / 96110 / 12333 **只出现在 `overall = red` 的「已经交了钱？」区块**。黄灯、绿灯、未知**不显示这一块**——它们没有「已经交了钱」的前提，显示 110 反而会让用户误以为自己被骗了。**这是设计意图，不是遗漏**（前端自动化曾把它当缺陷报过一次）。

## 七、留痕与对外口径

- 所有申诉工单留痕（时间、内容、处置），保存期限【待老板确认：建议 2 年】，仅内部可见。
- 对外的统一回复模板（示例）：

> 您好，我们已收到您对报告编号 XXX 的申诉。本产品仅依据用户上传的截图内容做风险提示，不代表对任何企业的评价。经复核：〔结论〕。如您对结论有异议，可补充材料至【邮箱】。感谢您的反馈。

## 八、页面自检清单

- [ ] 「我的」和报告页各有一个申诉入口
- [ ] 企业无需登录即可申诉（有独立提交路径）
- [ ] 表单必填项齐全，联系方式注明「仅用于回复」
- [ ] 高危报告提示常驻、不可关闭；110/96110 为拨号按钮，12333 为下方单独文字（D21）
- [ ] 7 个工作日 SLA 有内部台账可查
- [ ] 对外回复模板已定稿，客服可直接用

## 九、待老板/律师确认

1. 申诉邮箱与客服责任人（**必须有人真的看**，否则承诺 7 天答复是空头承诺）；
2. 企业申诉要求的证明材料是否收集身份证号（涉及敏感个人信息，建议改为「营业执照即可」）；
3. 加急下架（24 小时）的授权人是谁；
4. 留痕保存 2 年是否符合最小必要原则。
