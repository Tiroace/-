## 〇、先说一个必须立刻知道的硬事实（会影响整个提审策略）

我把微信官方《开放的服务类目》整份下载下来核对（275KB 原文，逐条看过），**个人主体开放的服务类目里没有「求职/招聘」这一类**：

- 非个人主体有：【生活服务 - 求职/招聘】、【商业服务 - 第三方人力资源服务】；
- **个人主体只有 8 个大类**：物流服务、教育服务、生活服务、餐饮服务、旅游服务、**工具**、商业服务、体育；
- 其中【工具】个人主体可选的具体类目只有 11 个：记账、日历、天气、办公、图片处理、计算器、报价/比价、**信息查询**、预约/报名、健康管理、备忘录——**没有一个与求职招聘相关**。

来源：[微信小程序开放的服务类目](https://developers.weixin.qq.com/miniprogram/product/material/)、[平台运营规范 2.5.7 类目不符行为](https://developers.weixin.qq.com/miniprogram/product/)

**这意味着一件事**：我们的产品必须**彻底按「信息查询工具」定位**，不能有任何一个功能看起来像「招聘服务」。具体到文案与功能：

| 不能有（否则判类目不符） | 必须这样写 |
| --- | --- |
| 招聘、求职、找工作、投简历、内推、岗位推荐 | 检查你收到的**招聘信息**有没有风险点（信息 = 用户自己上传的截图） |
| 帮企业招人、职位发布、简历服务 | 不提供任何一方撮合服务 |
| 用户互相交流的社区（求助广场） | **保持关闭**（个人主体还涉及【社交-社区/论坛】类目，个人主体没有这个类目） |

这条已同步合规助理：**类目建议填【工具 - 信息查询】**，并在提审说明第一句就说清「本产品不提供招聘服务，只对用户自己上传的招聘信息截图做风险提示」。

## 一、小程序名称 + 2 个备选 + 查重结论

### 1.1 命名规则（官方口径，先对齐）

依据[平台运营规范 2.2 基本信息规范](https://developers.weixin.qq.com/miniprogram/product/#基本信息规范)：

| 规则 | 原文要点 |
| --- | --- |
| 名称要能准确描述功能 | 名称、logo、简介相互关联，不得误导用户对功能范围的理解 |
| 不得含商业化用语 | 「免费」「最高级」「国家级」等广告法禁用词 |
| 不得与其已有小程序/公众号重名或混淆 | 无正当理由不能重名 |
| **不得使用广义归纳类、普遍且无识别性的词汇** | 如「短裤短裙」这类要改成「品牌+功能描述」 |
| 不得堆砌热门搜索词 | 与自身服务无关的关键词不行 |
| 不得使他人误认与腾讯/国家机关有关 | 2.5.14 混淆行为 |

**对我们最关键的两条**：① 不能只由通用词构成（比如只叫「招聘避雷」就危险）；② 名称与功能必须对得上（我们做的是「截图风险提示」，不是「招聘」）。

### 1.2 推荐名称与备选

| 顺位 | 名称 | 字数 | 合规分析 | 风险 |
| --- | --- | --- | --- | --- |
| **主选** | **面试请等等** | 5 | 「面试」是场景词不是行业词；「请等等」是辨识度高的拟人表达，不属通用词堆砌；不含「招聘」「求职」等行业词，**天然规避免费招聘服务类目的联想**；与产品调性（黄灯=请等等）一致 | 低。唯一风险是「请等等」较口语，需确认是否被大量近似名称占用 |
| 备选一 | **截图看看** | 4 | 纯功能描述（传截图→看结果），无行业词，辨识度中等 | 中。偏通用，「看看」二字可能被判定为无识别性 |
| 备选二 | **面试前看一眼** | 6 | 场景化描述，与产品核心动作（面试前查一下）完全对应，无行业词 | 中。字数偏长，且「看一眼」略口语，可能被认为描述性过强 |

> **建议顺序：面试请等等 → 截图看看 → 面试前看一眼。** 主选失败再依次启用。
> 我更推荐的其实是**主选**：它是唯一一个「不像招聘、也不像通用工具」的名字，类目审核时最安全。

### 1.3 查重结论（诚实说明：我查不了）

**必须说清楚**：微信的名称查重**只能在注册时的后台实时校验**，没有任何公开接口可以查。我用搜索引擎试过，返回的是无关结果，不可用。所以：

**查重结论 = 未查重（无法离线核实），必须在注册时由后台校验。**

这不是推脱——名称是否可用**只有那一刻的官方后台说了算**。我们能做的是：

1. 准备 3 个名字（已备），一个被占用立刻换下一个；
2. 注册前先自查商标（老板已列待办）；
3. 三个名字都撞车时，按同一逻辑再出：保留「面试」+ 换一个拟人化词，如「面试别急」「面试慢点」。

> **个人助理注意**：名称和查重是在小程序的**注册流程里一次填完的**，请把这一步放进《老板操作单》里，**三个名字按顺序写在同一张纸上**，撞车时老板直接换下一个，不用回来问。

## 二、小程序简介（定稿）

**官方要求**：简介要与实际服务一致，不能有隐藏类目（[2.3 功能设置规范](https://developers.weixin.qq.com/miniprogram/product/#功能设置规范)）。**D39 后本产品纯免费，简介里不提任何付费**——《小程序支付及退款规范》2.14 对不涉及支付的产品不适用。

### 2.1 定稿版本（主推荐，84 字）

```
上传招聘信息截图，自动比对规则库与套路库，逐项提示押金、刷单、培训贷等风险点，并给出核实方法与要问的问题。仅供参考，不代表对企业评价。不提供招聘、求职、投递等撮合服务。
```

**为什么这样写**：
- 第一句就说清「做什么」——上传截图、逐项提示，与【信息查询】类目吻合；
- 主动声明**不提供招聘服务**，这是个人主体最容易被判类目不符的点，提前挡掉；
- 「仅供参考，不代表对企业评价」是我们所有文案的固定免责口径（D20 同源），简介里也要有；
- 不含「AI」「智能」字样（路线令 D19 约束）。

### 2.2 备用版本（更短，71 字，若字数受限）

```
把招聘信息截图传上来，自动检查有没有押金、刷单、培训贷等风险，并告诉你要问 HR 什么、怎么核实。仅供参考。本产品不提供招聘、求职、投递服务。
```

### 2.3 简介的三个硬约束（给前端和合规助理对照）

1. **不出现**：招聘平台、求职服务、职位、内推、简历、投递、AI、智能、最准、100%；
2. **必须有**：不提供招聘服务的声明 + 仅供参考的声明；
3. **必须与页面一致**：简介说「6 项检查」页面就得是 6 项；说了「核实方法」报告里就得有；不一致会被判 2.3 功能设置规范第 1 条（实际服务须与简介一致）。

## 二之三、类目说明（提审填表用，第 4 关定稿）

**建议类目：工具 → 信息查询**（个人主体可选，见 §〇 的类目实测）。

| 项 | 内容 |
| --- | --- |
| 一级类目 | 工具 |
| 二级类目 | 信息查询 |
| 选择依据 | 官方《开放的服务类目》个人主体【工具】下共 11 项：记账/日历/天气/办公/图片处理/计算器/报价比价/**信息查询**/预约报名/健康管理/备忘录。本产品做的是「对用户上传的文字信息做规则比对与提示」，属**信息查询**，不是招聘服务 |
| 为什么不能选招聘类 | **个人主体根本没有【求职/招聘】类目**（该类目仅非个人主体开放）。硬选会被判 2.5.7 类目不符，处理是「限期调整，到期封禁能力直至下架」 |
| 类目与功能一致性 | 首页核心功能=上传截图→出检查结果，与「信息查询」吻合；无职位发布、无简历、无撮合、无社区（广场关闭） |
| 收费情况 | **不收费**（D39），不涉及虚拟支付类目要求 |

**审核员可能追问的三个问题，准备好答案**：

1. **「这算不算招聘服务？」** → 不算。我们不发布职位、不收简历、不做匹配推荐；用户上传的是**他自己收到的**招聘信息截图，我们只回答「这条信息里有没有风险写法」。
2. **「为什么是工具类？」** → 功能本质是**文字信息比对与查询**，与「招聘平台的撮合服务」是两种不同的服务形态。
3. **「会不会变成社区？」** → 不会。求助广场功能**开关关闭、入口不可见**，个人主体不做用户发布内容。
