## 一、报告页结构（v2，自上而下）

```
① 顶部      （示例报告才显示：示例报告 · 内容是虚构的，不指向任何公司）
② 结论区    三种灯 + 结论标题（随 overall 变）+ 副标题统计「N 项红灯，N 项黄灯，N 项绿灯」
③ 依据行    「依据你上传的 2 张截图，10 月 30 日 15:20 检查」
④ 6 项检查  2 列网格：维度名 + 小灯 + short（灰灯显示「截图里没提到」）
⑤ 具体发现  findings 每条一卡，按红→黄→绿排序
⑥ 面试前问 HR   questions_to_ask + 复制按钮
⑦ 自己也能核实  how_to_verify
⑧ 已经交了钱？  仅 overall=red 时出现，拨 110 / 96110
⑨ 免责声明   D20 定稿原文 + 判断不准入口
⑩ 底部       提醒朋友 / 再查一份
```

## 二、4 种 overall 的结论区（颜色 + 标题 + 副标题规则）

| overall | 结论区背景 | 亮灯 | 结论标题（一字不改） |
| --- | --- | --- | --- |
| red | `$red-soft` | 红灯亮 | `这份工作，`换行`建议先别去` |
| amber | `$amber-soft` | 黄灯亮 | `先问清楚，`换行`再决定去不去` |
| green | `$green-soft` | 绿灯亮 | **`截图里没看到明显风险`**（**D16 定稿**，不用设计稿原句） |
| unknown | `$surface` | 三灯全暗 | `截图信息不够，再补一张` |

**副标题统计规则**：`N 项红灯，N 项黄灯，N 项绿灯`——只统计 `dimensions` 里红/黄/绿三种灯，**灰灯（`none`）不计入这句**。
- 例（示例报告）：`2 项红灯，2 项黄灯，1 项绿灯`（另 1 项灰灯在格子里显示「截图里没提到」）。
- 某灯为 0 时**整段省略**该灯，例：0 红时说 `2 项黄灯，4 项绿灯`，不写「0 项红灯」。
- `unknown` 态不显示这句统计，改显示：`截图里没读到岗位、薪资、公司这些关键信息`。

### 2.1 结论文案的硬性红线

| 规则 | 说明 |
| --- | --- |
| `green` 禁止写「安全」「没问题」「放心去」「可以放心」 | green 标题固定为 **D16「截图里没看到明显风险」**（原设计稿「看起来没问题，可以去」已弃用，因为含「没问题」）；`summary` 里同样不得出现上述词 |
| `unknown` 禁止猜 | 不得出现「大概率没问题」「应该没问题」 |
| 任何结论不得把公司名和定性词连用 | 「某公司在骗人」这类一律视为缺陷 |
| 不得出现「骗子」类定性词（见 §六） | 全页面零命中 |

## 三、6 个维度（固定顺序、固定名称、灯色文案）

| 顺序 | key | 名称（界面显示） | 看什么 | 红灯 short 示例 | 黄灯 short 示例 | 绿灯 short 示例 | 灰灯 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | `fee` | `收费与借贷` | 押金、培训费、贷款、垫付、索要银行卡或验证码 | 要先交押金 | 提到收费 | 没提要钱 | 截图里没提到 |
| 2 | `work` | `工作内容` | 刷单、拉人头、下载陌生 App、境外工作 | 点赞刷单 | 工作说不清 | 工作写清楚 | 截图里没提到 |
| 3 | `title` | `岗位名称` | 名称与实际职责是否一致 | 名不副实 | 名字有点虚 | 名实相符 | 截图里没提到 |
| 4 | `pay` | `薪资待遇` | 区间是否离谱、底薪提成是否写清、和要求是否匹配 | 高得不合常理 | 薪资没写清 | 薪资写得清 | 截图里没提到 |
| 5 | `company` | `公司信息` | 有没有全称、地址；联系人是不是个人号 | 查不到公司 | 信息不全 | 有全称和地址 | 截图里没提到 |
| 6 | `contract` | `合同社保` | 劳动合同、试用期、社保 | 不交社保 | 没写清楚 | 写清楚了 | 截图里没提到 |

**规则**：
1. `dimensions` 必须 **6 项全在**，顺序按上表固定，前端不得按灯色重排。
2. `short` **≤6 字**（后端保证，前端不截断）。
3. 灰灯（`none`）**固定文案 `截图里没提到`**，不许写「正常」「无风险」「待补充」等——灰灯的含义是「没读到」，不是「没问题」。
4. 灰灯维度对应的问题**必须自动补进 `questions_to_ask`**（后端做，前端不补）。标准追问池：

| 维度 | 灰灯时自动补的问题（原文） |
| --- | --- |
| `fee` | 入职前要交任何费用吗？押金、服装费、培训费都算。 |
| `work` | 这个岗位每天具体做什么？有没有业绩要求？ |
| `title` | 这个岗位具体叫什么？平时主要做什么工作？ |
| `pay` | 底薪多少？提成怎么算？有没有写进 Offer？ |
| `company` | 公司全名叫什么？办公地址在哪里？ |
| `contract` | 签的是劳动合同吗？试用期多久，交不交社保？ |

5. 6 维顺序在页面上**不因 overall 变化**；`unknown` 态也显示 6 项（全部灰灯）。

## 四、findings（具体发现）文案规范

### 4.1 卡片结构（固定）

```
[小灯]  [title 4–8 字]   [来源标签]
「[context 整句，其中 evidence 高亮]」
[reason 大白话解释]
```

### 4.2 来源标签（只有两种，前端不得自创）

| `source` | 界面标签（一字不改） | 含义（不必展示，内部口径） |
| --- | --- | --- |
| `rule` | `规则命中` | 词库/正则直接命中，属硬证据 |
| `pattern` | `套路库匹配` | 与套路库里的话术样本语义相近 |
| ~~`llm`~~ | ~~`AI 推理`~~ | **已删除（路线令：不用大模型，`source` 只剩 rule/pattern）** |

> 用户看到三个标签就能理解「这条结论是怎么来的」。**每条 finding 必须带且只带一个标签**。

### 4.3 原话高亮规则（前端照做）

| 项 | 规则 |
| --- | --- |
| 展示文本 | 用 `context`（**包含 `evidence` 的整句**），不是只显示 `evidence` |
| 高亮 | `context` 里的 `evidence` 部分用对应灯的 `-mark` 色（红 `$red-mark` / 黄 `$amber-mark` / 绿 `$green-mark`） |
| 包裹符 | 整句外层加「」引号，示例：`「入职前需交 300 元工装押金，转正后全额退还」` |
| 找不到 evidence | 若 `evidence` 不在 `context` 中（数据异常），**整条 finding 不上屏**并告警——这是证据可追溯的底线 |
| 脱敏 | `evidence`/`context` 已由引擎脱敏（手机号、微信号、身份证号等）；**前端不得还原** |
| `title` | 4–8 字，不得超长；超长由后端修正，前端截断算缺陷 |

### 4.4 排序

按灯色 红 → 黄 → 绿；同灯色内按 6 维度顺序（`fee`→`work`→`title`→`pay`→`company`→`contract`）；再同则保持后端数组顺序。**`green` 的 finding 也要显示**（照实说绿灯，用户才信）。

### 4.5 `reason` 写法

- 大白话，平均句长 ≤25 字，不用「鉴于」「基于」「涉嫌违反」这类书面语；
- 需要时给法条依据：如 `正规公司不会在你入职前收钱。《劳动合同法》第九条规定，用人单位不得以任何名义向劳动者收取财物。`
- **不得点名公司**；主语只能是「这条招聘信息」「对方」「这类做法」。

## 六、禁用词清单（v2，双层过滤）

### 6.1 一级禁用（出现即阻断，属缺陷）

| 禁用词 | 原因 |
| --- | --- |
| 骗子公司 / 黑心企业 / 无良公司 / 垃圾公司 | 对企业定性，名誉侵权 |
| 骗子（指特定公司或个人时） | 同上；描述「这类做法常见于诈骗」属允许用法，主语不能是具体主体 |
| 100% 识别 / 百分百准确 / 绝不漏判 / 一查一个准 | 夸大能力 |
| 最准 / 最权威 / 第一 / 唯一 | 绝对化用语 |
| 官方认证 / 权威认证 | 无依据 |
| 曝光 / 打假 / 揭穿 | 隐含事实认定 |
| 挂出来 / 挂网上 / 让大家都知道 | 诱导传播 |
| 免广告 / 去广告 / 无广告 / 跳过广告 | 平台红线（见 09 号文档） |

### 6.2 二级（允许但受限）

| 词 | 规则 |
| --- | --- |
| 风险提示 / 疑似 / 建议核实 | ✅ 鼓励 |
| 骗局 / 陷阱 | 只能描述「这类手法」，不得接公司名 |
| 这家公司 | 禁止与定性词连用 |
| 安全 / 没问题 / 放心 | 禁止用于 `green` 结论与 `short` |

### 6.3 灰灯专用禁止写法

灰灯只能说 `截图里没提到`。以下**禁止**用在灰灯：`正常`、`无风险`、`待补充`、`未发现`、`暂无`、`没问题`。

- 每份报告**逐次展示**，不可关闭、不可折叠进弹窗；

- 律师改字则升 v1.1，**上线后冻结**。
