## 一、先说红线：「免广告」类词零出现

### 1.1 黑名单词（全产品、全截图范围内禁止出现）

| 黑名单词 | 说明 |
| --- | --- |
| 免广告 | 抖音明确禁止「付费免广告」 |
| 去广告 | 同上 |
| 无广告 | 同上 |
| 跳过广告 | 同上 |
| 看广告不受限 | 变相「去广告」 |
| 不想看广告就开会员 | 把会员和广告绑定 |
| 广告特权 | 同上 |
| 干净版 / 纯净版 | 隐含「去广告」 |

**验收口径（与任务书 §9 一致）**：全部文案、页面、截图、提审材料，上述词**检索命中数 = 0**。

**替代写法**：所有会员权益只用两个维度表达——**「每天最多查几次」** 和 **「检查记录保存多少天」**。

### 1.2 会员**不是**什么（写进会员页底部小字，也是客服口径）

> 会员只影响「每天能查几次」和「检查记录保存多久」。

**不写**「会员免广告」「会员不影响看广告的入口」——第一句违规，第二句等于变相承认。**什么都不写**，因为看广告拿次数对所有人都开放，会员依然可以看。

### 2.1 关键校验（给前端/测试）

1. 价格**不得写死在前端**，必须读 `/plans`；`/plans` 里没有的套餐不显示。
2. 「约 ¥X 一天」由 `价格 ÷ 天数` 前端算并保留两位小数；**年卡不出现**（找工作不需要年卡，且任务书 §6.3 明确不做）。
3. `一次性购买，到期不自动续费。` 这句在**可用态（A 态）必须显示**；不可用态（B 态）不显示（见 2.2）。
4. 支付成功提示：`会员已开通`，然后返回来源页。

### 2.2 付费可用性两态（按开关走，不写死 iOS）

> **口径变更（Chief 2026-10-31）**：当前先做微信，**微信 iOS 虚拟支付是否可开仍在核实（T1W-W3）**，因此文案按**开关两态**写，前端不得写死「iOS 一定隐藏」。
> 判定来源：**服务端 `/plans` 返回的 `payable`（布尔）+ `unavailable_reason`**；前端不自己判断机型，只认服务端。

| 态 | 触发条件 | 会员页表现 | 我的页会员条 | 弹窗会员卡 |
| --- | --- | --- | --- | --- |
| **A 可用** | `payable = true` | §二表格全部文案正常显示 | 显示 | 显示 |
| **B 不可用** | `payable = false` | 整页空态（见下），无任何价格/付费字眼 | 隐藏 | 整卡隐藏 |

**B 态空态文案**：

- 标题：`这台手机暂时不能开通会员`
- 正文：`你仍可以免费查 3 次，也可以看广告再换次数。`
- 按钮：`返回`

**B 态硬约束**：页面不得出现任何价格、货币符号、套餐名、付费字眼。→ 「一次性购买，到期不自动续费」含付费信息，B 态**也不显示**。

**默认值（重要）**：微信 iOS 未核实前，**服务端按 B 态兜底下发**（宁可少卖，不可违规）；T1W-W3 核实可开后切 A 态。安卓端待 T1W-W4 核实后单独配置，**两端可不同态**。

| 位置 | 文案（照抄） |
| --- | --- |
| 标题 | `免费次数用完了` |
| 引导句 | `选一种方式，继续检查。` |
| 看广告项 主 | `看一段广告，再查 1 次` |
| 看广告项 副 | `看完就到账，今天还能看 5 次`（`5` 来自 `/me` 的 `ad.remaining_today`，**不得写死**） |
| 看广告按钮 | `看广告` |
| 会员卡片 主 | `开通会员，找工作期间放心查` |
| 会员卡片 副 | `每天最多查 20 次，周卡 ¥6.9 起`（价格来自 `/plans`） |
| 会员卡片按钮 | `看看会员` |
| 底部说明 | `会员是一次性购买，不会自动续费。` |

### 3.1 状态分支（前端按这个做，测试按这个验）

| 状态 | 显示 | 隐藏 |
| --- | --- | --- |
| 今天还有广告次数（`remaining_today > 0`） | 看广告项（含「今天还能看 N 次」） | — |
| 到达当日上限（`remaining_today = 0`） | 仅会员卡片 + 底部说明 | **整个看广告项隐藏**，不得显示「今天不能看了」这类负面提示 |
| 广告无填充 / 加载失败 | **直接 +1 次并关闭弹窗**，提示「本次没有广告，已送你 1 次」 | 不得让用户重试、不得显示失败弹窗 |
| 会员卡片，B 态（`payable=false`） | 整卡隐藏，**不出现价格与任何付费字眼** | 卡片、价格、`看看会员` |
| 会员卡片，A 态（`payable=true`） | 会员卡片正常 | — |

### 3.2 广告流程的合规语（用户主动点击才请求）

- 弹窗本身**不预创建、不自动播放**广告；只有点了 `看广告` 才调 `tt.createRewardedVideoAd`。
- 看完（`isEnded === true`）才调 `POST /ad/reward`；中途关闭不发次数，也不提示用户「再看一次才能拿」。
- 平台要求：广告拉不出来**必须直接给奖励**，这条已写进上表。

### 3.3 严禁出现的写法

| ❌ 禁止 | ✅ 正确 |
| --- | --- |
| 「看完广告，解锁完整功能」 | 「看一段广告，再查 1 次」 |
| 「开通会员，从此不看广告」 | 「开通会员，每天最多查 20 次」 |
| 「不看完就不能继续」 | 关掉广告后弹窗仍在，用户可以选会员或离开 |
| 「还剩 1 次广告机会，别浪费」 | 「今天还能看 N 次」（中性陈述） |

## 四、会员服务协议要点（新增，P0，随会员页上线）

「开通即表示同意《会员服务协议》」这句要求**协议真的存在**。R1 先出一版要点，全文由律师基于原《用户协议》拆分：

1. **服务内容**：会员为一次性购买的检测额度与保存时长服务，**不含任何与广告相关的权益**（措辞需律师改写为合规表述，此处不写「免广告」字样）。
2. **价格与支付**：以购买页实时显示为准；支付由平台代收；**不自动续费**，到期失效。**当前设备不可付费时（`payable=false`），不展示购买入口。**
3. **虚拟商品退款**：按平台规则不支持退款，法律另有规定除外。
4. **每日上限**：会员每日检测次数有上限，用于防止批量滥用，上限可在后台调整并公示。
5. **公平使用**：不得用脚本、模拟器等批量调用，违者限制或终止服务。
6. **失效处理**：到期后会员权益失效，已生成的报告按免费用户规则（7 天）处理。

> 待律师确认：第 1 条如何在不出现「免广告」字样的前提下把「会员权益与广告无关」写清楚；第 3 条与消保法关系。
