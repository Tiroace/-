# 真实截图入测试集的脱敏规则（给软件测试者）

> **【内部使用，不得对外展示】** 依据《路线调整令》第四节（测试截图来源已授权、真实截图打码、只用于内部测试）+ 隐私政策 §3.1。
> 起草：产品经理 ｜ 日期：2026-10-31 ｜ 版本：v1.0
> **一句话**：打码只打「跟识别结论无关的个人身份信息」，**凡是会影响判断的招聘内容一个字都不能动** —— 否则测出来的准确率是假的。

---

## 一、总原则（三条，先记）

1. **打码不能破坏证据**：我们要测的是「程序能不能认出这个风险」。删掉一句带风险的话，这张图就从「正例」变成了「反例」，测试集会直接失真。
2. **只动身份、不动话术**：手机号、微信、QQ、身份证、银行卡、门牌号、人名 —— 换成等长的假值；**收费名目、金额、岗位名称、职责、薪资写法、公司名，原样保留**。
3. **原位替换、保持长度和样式**：用「同长度、同字体、同位置的假值」覆盖，不要涂黑大块、不要裁剪、不要 P 图变形——涂黑会让 OCR 读不到上下文，测出来的 CER 也不准。

---

## 二、逐项打码规则

| 类别 | 打不打码 | 怎么打（**保持长度**） | 说明 |
| --- | --- | --- | --- |
| 手机号 | ✅ 打 | `13812345678` → `13800138000` | 11 位换成真实运营商测试号段格式；**不要改成 `138****5678`**——星号会让 OCR 识别率测试失真，也不能测「程序能否识别出手机号」这条规则 |
| 座机 | ✅ 打 | 区号保留，后 8 位换成 `00000000` | |
| 微信号 | ✅ 打 | 换成 `wx_abc12345` 这类同长度假号 | 但要**保留「V信 / 薇信 / 威信」这类写法本身**——这正是变形写法表的测试目标，不能规整 |
| QQ 号 | ✅ 打 | 换成 `123456789` | |
| QQ 群号 | ✅ 打 | 同上 | |
| 身份证号 | ✅ 打 | 换成 `110101199001011234`（结构合法但非真人） | 前 6 位地区码可用真实的，后 12 位换掉 |
| 银行卡号 | ✅ 打 | 换成同长度测试号 `6222000000000000000` | |
| 人名（HR、面试官） | ✅ 打 | **姓氏保留、名换掉**：`王经理`→`赵经理`，`莉莉`→`小雅` | 保留「XX经理」「XX姐」这类称呼结构，因为它是话术特征 |
| 门牌号 | ✅ 打 | `XX路 88 号楼 3 单元 502` → `XX路 88 号楼 3 单元 601` | 保留「路 + 楼 + 单元」结构 |
| 车牌号 | ✅ 打 | 省份简称 + 换数字 | |
| 邮箱 | ✅ 打 | `abc@qq.com` → `xyz@example.com` | |
| **公司名** | ❌ **不打码，保留** | — | 公司名是判断「公司信息」维度的核心依据；也是「XX有限公司」这条规则的命中条件。删了这条维度就永远是灰灯，测不出来 |
| **职位名** | ❌ 保留 | — | 「储备干部」「管培生」是岗位名称维度的测试目标 |
| **收费名目与金额** | ❌ 保留 | — | 「押金 300 元」「服装费」是收费维度的硬证据 |
| **薪资写法** | ❌ 保留 | — | `8000-20000`、`8k-2w`、`日结200-500` 是薪资解析的测试目标（路线令要求支持这些写法） |
| **职责描述** | ❌ 保留 | — | 「负责电话回访」是岗位名实不符的依据 |
| **变形写法** | ❌ 保留 | — | 「押 金」「V信」「扣扣」必须原样保留，这是规整表要处理的对象 |
| 背景里的第三方内容（别人的聊天记录、他人照片） | ✅ 裁掉或打码 | 只保留与本条招聘相关的那一段 | 与判断无关的他人隐私，一律不进测试集 |

## 三、制作流程（每张图都走一遍）

1. **先复制原件**到 `data/testset/_raw/`，**原件只读不改**；
2. 按上表打码 → 存到 `data/testset/images/`；
3. **肉眼复核**：放大看，确认打码值可读（OCR 能读到）、长度一致、没有遮盖上下文；
4. 在 `index.jsonl` 里记：`track: "real"`、`source.url`、`collected_at`、`masked: true`、`mask_fields: ["phone","wechat"]`；
5. 同一条话术**至少保留一份未打码的原始文本**，放在 `data/testset/_raw_text/`（内部只读），用于核对我们打码有没有改坏内容。

---

## 四、什么算「破坏了证据」（出现即作废重做）

| 情况 | 为什么作废 |
| --- | --- |
| 涂黑整块、色块遮挡 | OCR 读不到上下文，CER 和召回都失真 |
| 把手机号改成 `138****5678` | 星号是「已脱敏」的标志，但会让「识别手机号」这条规则测不出来 |
| 删掉公司名 | 公司信息维度永远灰灯，没法评 |
| 把「V信」规整成「微信」再存 | 变形写法表的测试目标被毁掉 |
| 把薪资 `8k-2w` 改写成 `8000-20000` | 薪资解析规则测不到真实写法 |
| 裁掉聊天记录里的提问，只留回答 | 上下文没了，证据校验（context 包含 evidence）会失败 |
| 用 AI 或滤镜把模糊截图锐化 | 改变了原始识别难度，测出来的不是真实场景 |

## 五、四条红线（路线令第四节 + 隐私要求）

1. **不批量爬取、不绕登录或反爬、不用别人的账号**；
2. 公开投诉平台（黑猫投诉等）**只人工少量摘录**，只用于内部测试，**不对外展示**；
3. 真实截图**只在内部使用**，不进产物、不上传任何外部服务（**包括不能发给第三方 OCR 在线工具试效果**，因为一期是本地 OCR）；
4. 采集到的内容**不对外展示**，测试报告里如果要举例，用打码后的合成图。

---

## 六、什么时候可以不打码

只有一种情况：**完全由我们编造的合成图**（`track: synthetic`），本来就是假数据，不需要打码；
但合成图里如果用了真实案例的话题，**也不得出现真实公司名、真实人名**。

---

## 七、抽查机制

- 每批 50 张，抽 5 张给产品经理复核「打码有没有改坏判断」；
- 发现 1 张改坏了 → 该批全部重做。

> 有问题直接问我，不要边收边猜——一张图改坏了，评测数字就是假的，后面调阈值全白做。
