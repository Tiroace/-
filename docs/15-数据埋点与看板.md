# 数据埋点与运营看板（D7 之后、上线之前）

> 依据：老板 2026-10-31 要求。原则：**只统计行为，不采集任何个人信息**（无手机号、无定位、无设备指纹留存、截图不落盘）。

## 一、要统计的指标

| 指标 | 定义 | 用途 | 来源事件 |
| --- | --- | --- | --- |
| 上传次数 | 提交分析任务的次数（含失败） | 漏斗起点 | `analysis_created` |
| 检查完成率 | `done` / `created` | 产品可用性 | `analysis_created` / `analysis_finished` |
| 失败率 | `failed` / `created`，按错误码拆分 | 稳定性 | `analysis_failed`（带 error_code） |
| 红/黄/绿占比 | 报告 `overall` 分布 | 识别结果结构是否合理 | `analysis_finished`（带 overall） |
| 「判断不准」比例 | 反馈数 / 完成数 | 准确率真伪信号 | `feedback_submitted`（type=inaccurate） |
| 看广告次数 | 激励视频请求与奖励发放 | 变现漏斗 | `ad_requested` / `ad_rewarded` |
| 会员转化率 | 付费成功用户 / 活跃用户（按周期） | 变现 | `order_paid` |
| 次日留存 | 次日有任意事件行为的用户 / 当日新增 | 留存 | 每日活跃（按匿名 user_id 聚合） |
| 平均耗时 | 分析完成耗时分位（p50/p95） | 速度门槛监控 | `analysis_finished`（duration_ms） |

## 二、事件模型（不含 PII）

```
events(id, user_id_hash, event, props_json, created_at)
```

- `user_id_hash`：只存 `sha256(user_id + 每日盐)`，**每日换盐**，不可逆推个人；不存 openid 明文。
- `props_json` 只允许白名单字段：task_id、error_code、overall、duration_ms、ad_unit_id、plan、amount_fen、feedback_type。
- 禁止写入：手机号、微信/QQ 号、身份证、银行卡、定位、截图内容、设备指纹明文。
- 保留期：行为事件 180 天；看板只做聚合，不做个体追踪。

## 三、采集方式

- 后端在关键路径打点（`analysis.py` / `ads.py` / `orders.py` / `feedback.py`），统一写 `events` 表，异步批量落库，不阻塞主流程。
- 前端不上报任何设备信息；只在后端埋点。
- 开发环境默认关闭（`QBL_ANALYTICS=0`），生产开启。

## 四、看板

- 后台新增 `/admin/dashboard`：今日/近 7 日/近 30 日三档；核心 8 个指标 + 错误码分布 + 耗时分布。
- 只读、需管理员令牌；不提供个体明细导出。
- 排期：D7 之后、上线之前（与社区补齐并行，估 12h）。

## 五、验收

- 用测试流量跑 100 次分析，看板数字与测试记录一致；
- 全库扫描 `events` 表，无手机号/证件号/定位等 PII（硬断言）；
- 埋点失败不影响主流程（异步、失败只记日志）。
