# 求助广场（R3）接口与数据表

- 依据：改版任务书 §11.4；`docs/09-改版实施计划.md` §四
- 负责人：软件开发者
- 状态：后端骨架（R3 第一步），**开关默认关闭**（D14），前端页面 R3 再做
- 代码：`backend/app/routers/community.py`、`backend/app/community/`、`backend/app/db.py`
- DDL：`backend/sql/community.sql`（SQLite 可执行，语法保持 MySQL 兼容）

## 一、开关与可见性

| 项 | 规则 |
| --- | --- |
| 开关 | 环境变量 `QBL_FEATURE_COMMUNITY=1` 才开启；默认 `0` |
| 关闭时 | 所有 `/community/*`（GET/POST 一律）由**中间件在 body 校验之前**统一返回 404 `NOT_FOUND`（D-07），不泄漏存在性 |
| 后台 | 敏感词与审核接口在 `/admin/*`，同样受开关控制（避免未开的功能漏入口） |
| 资质 | 社区涉及信息发布类资质与安全评估，未核实前不上线；社区页面先不放广告 |

## 二、数据表（6 张）

> 举报表建为 **`post_reports`**：`reports` 已被分析报告占用，避免同名冲突；上线 MySQL 时按本文档字段迁移。

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `posts` | id、user_id、report_id、company、position、city、question、anonymous、risk_overall、status、images、vote_up、vote_down、report_count、**reviewed_by、reviewed_at、reject_reason**、created_at、updated_at | 帖子。`status`：pending→approved/rejected，举报满 3 次→hidden；审核人/时间/驳回原因都落库 |
| `votes` | id、post_id、user_id、value、reason、**counted、risk_reason、device_hash、ip_prefix**、created_at；**UNIQUE(post_id,user_id)** | 一人一帖一票可改；D18 可疑票 `counted=0` 只留记录不计展示；设备号只存哈希 |
| `experiences` | id、post_id、user_id、content、status、**reviewed_by、reviewed_at**、created_at | 经历，先审后发；状态机同帖子（无 hidden） |
| `post_reports` | id、post_id、user_id、reason、created_at；**UNIQUE(post_id,user_id)** | 举报，同一人一次；满 3 次自动隐藏 |
| `appeals` | id、post_id、company、contact、content、status、sla_hours、created_at、handled_at | 企业申诉，`sla_hours=24` |
| `sensitive_words` | id、word、level(block/review/mask)、kind(word/regex)、prompt、as_type、category、created_at；**UNIQUE(word,kind)** | 敏感词库 v1（产品交付 132 条：block 80 / rewrite 42 / mask 10），后台可热更 |

索引：`posts(status, created_at)`、`posts(user_id)`、`votes(post_id)`、`experiences(post_id,status)`、`appeals(status,created_at)`。

## 三、接口（共 13 个）

鉴权：`/community/*` 需要用户 token；`/admin/*` 需要 `X-Admin-Token`。

### 3.1 用户侧

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/community/posts` | 列表：`sort=latest/active/voted`、`q` 搜索（公司/岗位/城市/提问）、`limit≤20`、`cursor`；只返回 approved |
| POST | `/community/posts` | 发帖：先审后发（status=pending）；敏感词+模型两层、图片内容安全、隐私打码 |
| GET | `/community/posts/{id}` | 详情：approved 可看；本人可看自己的 pending；其他人 404 |
| POST | `/community/posts/{id}/vote` | 投票 `{value:1/-1/0, reason?}`：一人一票可改、发帖人不能投自己、新号 24h 禁投 |
| POST | `/community/posts/{id}/experiences` | 补充经历（先审后发） |
| GET | `/community/posts/{id}/experiences` | 经历列表（approved） |
| POST | `/community/posts/{id}/report` | 举报 `{reason?}`；同一人一次；满 3 次自动 hidden |
| POST | `/community/appeals` | 企业申诉 `{post_id?, company, contact?, content}`，返回 `sla_hours=24` |

### 3.2 后台

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/admin/community/posts?status=pending` | 待审列表（也可 approved/rejected/hidden），返回审核人/时间/驳回原因 |
| POST | `/admin/community/posts/{id}/approve` | **D-08**：审核通过（pending→approved），可带 `{operator}` 记录处理人 |
| POST | `/admin/community/posts/{id}/reject` | **D-08**：驳回（pending→rejected），可带 `{operator, reason}` |
| POST | `/admin/community/posts/{id}/review` | 兼容入口：`{action: approve/reject/hide}` |
| GET | `/admin/community/experiences?status=pending` | 待审经历列表 |
| POST | `/admin/community/experiences/{id}/approve` | 经历审核通过 |
| POST | `/admin/community/experiences/{id}/reject` | 经历驳回 |
| GET | `/admin/community/votes?counted=0` | **D18**：查可疑票（设备摘要/IP 网段/原因/关联帖子状态），不返回明文设备号 |
| GET | `/admin/sensitive-words` | 敏感词列表 |
| PUT | `/admin/sensitive-words` | 整体替换 `{words:[{word, level, kind?, prompt?, as_type?}]}`，level=block/review/mask |

### 3.3 错误码（本模块新增）

| code | HTTP | 含义 |
| --- | --- | --- |
| `NEW_ACCOUNT_RESTRICTED` | 403 | 新号 24h 内禁止发帖/投票/补充经历 |
| `CONTENT_BLOCKED` | 400 | block 级敏感词/外链/模型审核未过（`detail.layer` 标明哪一层） |
| `NEEDS_REWRITE` | 400 | rewrite 级词命中：请改成描述事实后再提交（`detail.prompt` 给具体提示） |
| `NOT_FOUND` | 404 | 帖子不存在/已隐藏/社区未开放 |
| `FORBIDDEN` | 403 | 给自己的帖子投票等 |

## 四、敏感词词表 v1（产品交付，已接入）

- 种子文件：`lexicon/sensitive_words_v1.json`（源自 `docs/06-合规与文案/sensitive_words_v1.json`，132 条）。
- 启动灌库：`backend/app/community/sensitive_seed.py`，**表为空才灌**，不覆盖运营热更。
- 级别映射：`block`→block（直接拒收）；`rewrite`→**review**（提示改写后重交）；`mask`→mask（正则打码后放行）。
- 正则类（10 条）：手机号、身份证、银行卡、微信、QQ、群号、邮箱、门牌号、车牌、外链（外链是 block 级正则）。
- 热更：`PUT /admin/sensitive-words` 直接改库，下一次请求生效，**不用重启**；后台可分别配置 word/regex、prompt、as_type。
- 覆盖范围：发帖（提问/公司/岗位/城市）、补充经历、企业申诉三处写入口都过同一套审核。

## 五、发布前过滤（三道）

1. **敏感词 + 模型两层**（`community/moderation.py`）：先查 `sensitive_words`（level=block 直接拒），再走第二层模型审核——本机没云账号，用本地规则降级（D13 同口径：外链、扫码/加V引流、日结招工广告），接云内容安全只换 `model_check`。
2. **隐私打码**（`community/privacy.py`）：手机号、身份证、银行卡、微信/QQ、门牌号、人名（「王经理」→「王**经理」）在**入库前**打码。
3. **图片内容安全**：发帖携带 `image_ids` 时校验归属/有效期，并再过一遍内容安全（上传时已过第一道，这里是第二道）。

## 六、排序口径映射（前端注意）

任务书 §11.2 写的是「最新 / 参与最多 / 我投过的」，接口参数用的是英文值：

| 任务书说法 | 接口参数 |
| --- | --- |
| 最新 | `sort=latest`（默认） |
| 参与最多（按票数） | `sort=active` |
| 我投过的 | `sort=voted` |

没有 `hot` 这个值；传别的值会被 422 参数校验拦下。前端已按实现值对齐，这里留档避免再踩。

## 七、防刷口径与配置项（D18）

**口径（按任务书 §11.2 原文）**：同设备 / 同网段短时间大量投票 → **可疑票照常收下、不计入展示、保留记录备查**。不是入口拒绝，也不静默丢弃。

| 项 | 值 |
| --- | --- |
| 窗口期 | `QBL_COMMUNITY_VOTE_WINDOW_MINUTES`，默认 **10 分钟** |
| 同设备阈值 | `QBL_COMMUNITY_VOTE_DEVICE_LIMIT`，默认 **5 票**（第 6 票起为可疑票） |
| 同 /24 网段阈值 | `QBL_COMMUNITY_VOTE_IP_LIMIT`，默认 **20 票**（放宽，避免公司/校园网误伤） |
| 设备标识 | 请求头 `X-Device-Id`（前端传）；**缺失时退回 openid+IP**，不报错 |
| 存储 | `votes.counted`（1/0）、`votes.risk_reason`（`device_flood` / `ip_flood`）、`device_hash`（SHA256 前 32 位，不存明文）、`ip_prefix`（/24，IPv6 取 /64） |
| 展示口径 | 公开列表/详情/排序只统计 `counted=1` 的票；`votes` 表保留全部票 |
| 用户侧 | 接口照常返回成功（不提示被风控），自己的「已投/可改」状态正常；改票不新增记录 |
| 后台 | `GET /admin/community/votes?counted=0` 查可疑票 |

实现位置：`backend/app/routers/community.py` 的 `vote()`、`_vote_identity()`、`_vote_risk()`；表结构见 `backend/sql/community.sql`（`votes` 四列，老库自动迁移）。

## 八、风控规则（已实现）

- 一人一帖一票，可改票；发帖人不能投自己。
- 新注册账号 24 小时内禁发帖/禁投票/禁补充经历（`QBL_COMMUNITY_NEW_ACCOUNT_HOURS` 可调）。
- 举报同一人只能一次；满 3 次自动隐藏（`QBL_COMMUNITY_REPORT_HIDE_THRESHOLD`）。
- 企业申诉 24h SLA（`QBL_COMMUNITY_APPEAL_SLA_HOURS`），状态 open/handled/rejected。
- 先审后发：帖子、经历默认 pending，审核通过才可见。
