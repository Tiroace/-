## 二、报告 JSON v2（引擎契约，替换旧 §4.3）

```json
{
  "is_job_posting": true,
  "overall": "red | amber | green | unknown",
  "summary": "一句话结论，30 字以内",
  "dimensions": [{"key": "fee", "level": "red|amber|green|none", "short": "≤6 字"}],
  "findings": [{"level":"red|amber|green","dimension":"fee","title":"4–8 字","evidence":"截图原文","context":"包含 evidence 的整句","reason":"大白话","source":"rule|pattern|llm","pattern_id":null,"rule_id":null}],
  "questions_to_ask": ["..."],
  "how_to_verify": ["..."],
  "prompt_version": "v2.0",
  "pattern_db_version": "2026-10-30"
}
```

- `dimensions` 必须 6 项且齐全：`fee` 收费与借贷、`work` 工作内容、`title` 岗位名称、`pay` 薪资待遇、`company` 公司信息、`contract` 合同社保。
- 流程：OCR 切句 → 规则词库 → 套路向量召回 Top5 → 大模型（带 6 维度）→ 证据校验（`evidence` 必须在 OCR 原文、绿灯也要）→ 等级校准 → 灰灯补追问 → **后端按规则算 overall**（有红→red，否则有黄→amber，否则 green，非招聘/信息太少→unknown）。
- 旧 v1 报告（`risk_level`/`risks`）**作废**：前端/后端/测试同批切 v2；原型期库可清空，正式上线前补迁移脚本。

## 三、套路库（patterns）

- 表：`patterns`（id、名称、维度、等级、为什么危险、怎么办、状态、来源、更新时间）、`pattern_examples`（id、pattern_id、话术原文、向量）、`pattern_hits`（pattern_id、report_id、命中时间，不存用户截图）。
- 首批 50 个套路、每个 5–10 条话术样本，来源公开反诈宣传与新闻案例；运营可增删。
- 匹配：每句 OCR 文本做向量检索取 Top5，超阈值进候选；阈值用测试集调。
- **降级方案（D13）**：本机没有云向量服务与账号，先在 `embedding` provider 接口后实现本地轻量检索（字符 n-gram + TF-IDF/BM25 余弦），表结构与接口按正式设计；拿到云向量服务只换实现，不动上层。

## 四、求助广场（§11）

- 页面：求助广场（搜索/排序/帖子卡/发起求助）、求助详情（投票+理由标签+经历列表+举报+企业申诉）、发起求助（关联检查记录、自动打码可补充、公司/职位/城市/提问≤200 字、匿名、勾选真实经历）。
- 规则：一人一帖一票可改、发帖人不能投自己、不换算公司评分/不做排行榜、新注册 24h 内不能投/发/写、同设备同 IP 段异常投票进风控不计展示。
- 过滤三道：发布前（敏感词+大模型两层、隐私打码、平台内容安全、先审后发）、展示中（标注「来自用户分享，只代表个人经历」）、事后（举报 3 次自动隐藏、企业申诉 24h、违规禁言封号）。
- **开关默认关闭（D14）**：`FEATURE_COMMUNITY=false`，页面对用户不可见；资质核实通过后再开。
- 合规待核实（律师+平台）：信息发布类增值电信业务许可、安全评估、允许用户发布内容的类目与资质、后台实名方案；社区页面先不放广告。

## 五、视觉落地要点

- `design-tokens.scss` 全量放进 `uni.scss`；页面只用变量，不写死色值（验收项）。
- 设计稿 390 宽：`rpx = 设计稿 px × 750 ÷ 390 ≈ ×1.92`。
- `pages.json`：每页 `backgroundColor #0E1620`、`navigationBarTextStyle white`；tabBar `#121C27 / #8090A0 / #FFC93C`，选中/未选中两套 81×81 PNG。
- 导航栏：`navigationStyle: custom`、`uni.getMenuButtonBoundingClientRect()` 算高度；底部 `env(safe-area-inset-bottom)`。
- 灯组件统一：`red #FF5A47 / amber #FFB21E / green #34D07F / off #3A4756`，光晕 `0 0 22px`，只给灯用。
- 禁止：蓝色、渐变、卡片阴影、emoji、满屏小灰字、首页一打开推会员。

## 九、数据库：现状与社区表怎么建

**现状（2026-10-31）**
- 后端当前用 **SQLite 单文件** `D:\qiuzhibilei\var\backend\qbl.db`，建表在 `backend/app/db.py`，启动时 `CREATE TABLE IF NOT EXISTS` 自动建。
- 已有 13 张表：`users`、`quota_ledger`（额度流水）、`analysis_tasks`、`reports`、`uploads`、`ad_rewards`、`orders`、`memberships`、`feedback`、`patterns`、`pattern_examples`、`pattern_hits`（后三张是套路库）。
- `reports` 表目前还留着 v1 的 `risk_level` 列（兼容期，v2 内容在 `report_json` 里），上线前清理。

**社区 6 张表（按任务书 §11.4，R3 建）**
| 表 | 关键字段 | 约束/索引 |
| --- | --- | --- |
| `posts` | id、user_id、匿名昵称、report_id、公司名、职位、城市、提问、打码图地址、status（审核中/已发布/已隐藏/已删除）、created_at | idx(status, created_at) |
| `votes` | id、post_id、user_id、choice（去/不去）、reason_tag、updated_at | **unique(post_id, user_id)**、idx(post_id) |
| `experiences` | id、post_id、user_id、内容、status、useful_count、created_at | idx(post_id, status) |
| `reports` | **举报**：target_type、target_id、reporter_id、reason、result、handled_at | idx(target_type, target_id) |
| `appeals` | **企业申诉**：company、材料地址、target_id、result、handled_by、handled_at | idx(target_id) |
| `sensitive_words` | word、level（拦截/提示改写）、updated_at | unique(word) |

**建法**
1. 与现有表一样写在 `backend/app/db.py`，`CREATE TABLE IF NOT EXISTS`，带 `created_at` 默认值与 `status` 状态机；SQLite 语法保持 MySQL 兼容（不写 SQLite 特有函数）。
2. 社区接口全部挂在 `FEATURE_COMMUNITY` 开关后（D14 默认 false）：开关关闭时接口返回 404、页面隐藏，表照样建好，方便 R3 联调。
3. 生产按任务书 §5.2 换 **MySQL 8**：只换实现层（连接串/ORM），DDL 与索引同步维护一份 `backend/sql/` 迁移脚本；上线前跑一次迁移。
4. 敏感词与打码：`sensitive_words` 词库后台可增删；发帖流程里先敏感词+大模型两层，再平台内容安全，最后先审后发。
