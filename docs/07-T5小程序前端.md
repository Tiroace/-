脚本做的事（顺序固定）：

1. `-Build` 时先跑 `uni build -p mp-weixin`
2. 检查 `dist\build\mp-weixin\app.json` 是否存在；**不存在就报错退出，并给出三条构建命令**，绝不猜目录
3. `-Restart` 时先 `cli.bat quit`
4. `cli.bat open --project <dist\build\mp-weixin> --port 9420 --lang zh`
5. 非 0 退出码时提示三种常见原因（IDE 已开、服务端口没开、端口被占用）

**为什么必须是产物目录**：工程根 `D:\qiuzhibilei` 没有 `app.json`，IDE 会报「在项目根目录未找到 app.json」。
**为什么必须固定 9420**：普通方式双击启动 IDE 会分配随机端口，`miniprogram-automator` 连不上；必须 CLI 带 `--port` 启动。

> 脚本位置说明：Chief 让我放 `scripts/`，但 `scripts/` 属于软件开发者，我只写 `miniprogram/` 和 `docs/07`，所以放在 `miniprogram/scripts/`。需要的话软件开发者可以做个转发。

> 实测（2026-10-31 02:10）：产物缺失分支退出码 1 且提示正确；正常分支输出 `√ IDE 已启动，HTTP 服务地址 http://127.0.0.1:9420` + `√ open`，退出码 0；9420 在监听，`.ide-status = On`。

### 2.1 前端用到的 9 个端点（契约共 12 个，`/admin/*` 前端不接）

| 契约 | 方法/路径 | 前端调用处 | mock 状态 |
| --- | --- | --- | --- |
| 2.1 | `POST /auth/login` | `services/session.js` → `api.loginByCode` | ✅ 对齐 |
| 2.2 | `GET /me` | `services/session.refreshUser` | ✅ 对齐（含 `ad.today_count`/`remaining_today`） |
| 2.3 | `POST /analysis` | 首页「开始分析」 | ✅ 对齐（D9：JSON `image_ids` + `Idempotency-Key`） |
| **2.3a** | `POST /analysis/upload` | 首页逐张上传 | ✅ 对齐（D9：multipart 单图，字段名 `image`） |
| 2.4 | `GET /analysis/{id}` | 分析中页轮询、报告页、我的页 | ✅ 对齐 |
| 2.5 | `GET /reports` | 我的页历史报告 | ✅ 对齐 |

| 2.9 | `POST /feedback` | 报告页「判断不准」、文档页反馈/申诉 | ✅ 对齐 |
| **新增** | `GET /plans` | 会员页套餐与权益 | ✅ 对齐（不再写死价格） |

不接的 3 个：`POST /pay/notify`（平台回调，客户端不调）、`/admin/*`（后台）。

### 2.2 关键对齐点

| 契约要求 | 前端实现 |
| --- | --- |
| 响应封套 `{ok,data,request_id}` / `{ok:false,error:{code,message,detail}}` | `services/mock.js` 统一造封套；`api.js` 的 `unwrap()` 拆包，失败抛 `ApiError(code,message,detail)` |
| 按 `error.code` 分支，不按文案 | 首页 `handleAnalysisError()` 按 `QUOTA_EXHAUSTED`/`VALIDATION_ERROR`/`RATE_LIMITED`/`CONTENT_BLOCKED` 等分支 |
| `POST /analysis` **不等结果**，立即返回 `{task_id, poll_after_ms}` | 首页拿到 task_id 就跳「分析中」，绝不同步等报告 |
| **D8：创建响应 status 允许 `pending` 或 `running`，不得是 done/failed、不得带报告** | 首页判断 `res.status !== 'pending' && res.status !== 'running'` 才算异常；mock 也只会返回这两种 |
| 状态机 `pending → running → done/failed` | 分析中页按服务端 `poll_after_ms` 轮询，终态停止 |
| **`background_mode` 严格以服务端为准** | 服务端字段是布尔值就只认它；**只有字段缺失时**才用本地 30 秒兜底，不取「或」 |
| 失败退次数 | 分析中页收到 `status=failed` 后刷新余额并提示「次数已经退回」 |
| 余额只有 `quota.balance` | 全站统一 `quota.balance`，每次接口返回都同步到页面 |
| `POST /ad/reward` 入参 `{request_id, ad_unit_id, result}` | 首页按广告结果映射 `result`：看完→`completed`、兜底→`no_fill`、其它→`error` |
| `no_fill`/`error` 也必须发次数 | 前端不做拦截，直接提交，由服务端决定；`granted=false` 时才提示 |
| **D9：多图两步上传** | `uploadImage()` 逐张 `POST /analysis/upload`（name=`image`）拿 `image_id`，再 `POST /analysis{image_ids, idempotency_key}`；按钮显示「正在上传第 1/3 张…」 |
| **`GET /plans`** | 会员页套餐、价格、权益、iOS 可用性全部由接口下发；`rightsList` 不再是写死常量 |
| `pay_params` 是占位 | 会员页只用于走流程，注释明确「不可用于真实扣款」 |
| `evidence` 已是脱敏版 | 报告页原样展示，不做还原；示例数据里也确保没有完整手机号 |
| `Idempotency-Key` | 首页每次提交生成 `newRequestId()` 作为幂等键 |

### 2.3 前端还没接的（需要后端配合）

1. **`/reports` 分页**：前端目前一次取 20 条（`limit=20`），未做滚动加载。
2. **`ocr_text` 旁路**：本机没有云 OCR，真联调时靠这个旁路才能跑到 `done`。正式版后端删掉后前端同步删。
3. **`platform_mode` 口径**：登录返回 `dev`，`/me` 返回 `mock`（见 2.4 第 3 条），要后端统一。

> 原先 backlog 里的「套餐列表接口」「`today_count`」「多图上传」三项已在 v0.3 落地。

## 三、§6.2 激励视频硬规范逐条落点

| 规范原文 | 代码落点 | 自测用例 |
| --- | --- | --- |
| 用户主动点按钮才创建广告请求，不提前创建、不自动播放 | `adGuard.runRewardedFlow()` 只在点击事件里调用；模块加载时不创建任何广告实例 | A1、A3 |
| 一个页面最多一个激励视频 | `runningMap` 按 pageKey 去重，重复点击返回 `running` | B2 |
| 同一个奖励不能要求连看多条广告 | 一次 `runRewardedFlow()` 只调起 1 条，结果只对应 1 次奖励 | B4 |
| 60 秒内最多调起 5 次 | 滑动窗口 `windowMap`，超限返回 `rate-limited` | B3 |
| 广告拉不出来（没填充、版本太低）必须直接给奖励 | 任何失败都返回 `{ granted: true, fallback: true }`；没配广告位也走这条 | B1、B5、A1、A5、A6 |
| 看广告前说清规则、按钮写清「看广告」 | 弹窗按钮「看广告，换 1 次」+ 副标题「看完 1 条广告，增加 1 次检测」 | — |
| 禁止诱导点击、强制看广告才能走下一步 | 任何流程都不以看广告为前置；「先不用」可直接关闭弹窗 | — |
| 付费免广告违规 | 会员页文案明确「会员权益仅含检测次数与保存时长，与广告无关」 | C4 |

**兜底防滥用**：前端兜底发奖励，防滥用靠服务端 `/ad/reward` 的每日上限校验（T4 实现）；客户端把 `reason` 和 `fallback` 一并上报。

## 六、遇到的问题

### 1. ~~微信开发者工具 CLI 打不开项目~~ → 已解决（v0.3）

**真因（两件事叠加）**：

1. **IDE 用普通方式（双击）启动时没有 HTTP 服务端口**，`.ide-status` 一直是 `Off`，CLI 连不上。
   必须用 `cli.bat open --port <固定端口>` 启动，端口才会固定下来。
2. **工程目录开错了**：开了仓库根 `D:\qiuzhibilei`，那里没有 `app.json`，模拟器直接报错。

**解决**：写 `miniprogram/scripts/open_wechat_ide.ps1`，固定「构建产物目录 + 端口 9420」两件事，
以后不再手敲命令、也不会再开错目录。加 `-Restart` 可强制用固定端口重开（端口被随机化时用这个）。

**给测试者的约定**：automator 固定连 `http://127.0.0.1:9420`；IDE 由测试者/Chief 统一操作，
前端只提供产物路径 `D:\qiuzhibilei\miniprogram\dist\build\mp-weixin`。

**遗留教训**：PowerShell 5.1 读 UTF-8 无 BOM 的 .ps1 会按 ANSI 解析、中文变乱码并报语法错误。
本脚本已存为 **UTF-8 with BOM**，以后写 .ps1 都要注意。
