## 二、三张为什么脚本拍不了

不是偷懒，是这三种状态**在自动化环境里造不出来**：

### #03 上传流程
规范要求「点选图后」的画面（预览 + 「截图仅用于本次分析」）。
脚本只能把页面停在首页，`wx.chooseMedia` 是真机系统弹窗，自动化点不了。
**实测证据**：脚本能拍到的只有首页，与 #01 字节数完全相同（66892），是重复图，不能交。

### #04 分析中
分析页需要 `task_id` 才显示三段文案，没有任务时弹「没有检查任务」空态（**已实拍到这个空态**）。
`task_id` 来自真实上传链路；页面实例上拿不到服务模块
（实测 `page.$vm.$scope` 只有生命周期方法，没有 api 引用），无法从脚本注入。

### #13 次数用完弹窗
弹窗只在次数真的消耗到 0 时出现。mock 初始给 3 次，脚本没法把次数用光。

第一版对 #13 用了宽松匹配：「首页有『还能免费查』」就算通过。

## 七、本机构建与环境记录

- 提审包构建通过：**23 项构建后检查全过**，`appid = 正式 AppID（wx807821c2d1fb9f3b）`
- 自检：check:r1 54/54、test 47/47
- **IDE 启动卡死修复**（这次花了 30 多分钟，记下来）：
  CLI 一直报 `IDE may already started at port 9420`，但实际没有 IDE 在跑。
  根因是 `%LOCALAPPDATA%\微信开发者工具\User Data\**\Default\.ide` 这三个文件里存着端口号 9420，
  是上次运行留下的死记录。**正确顺序**：
  1. `taskkill /T /F` 清掉全部「微信开发者工具」进程；
  2. 确认 9420/9422/64750 都空闲；
  3. `cli.bat open --project ...` 让 IDE 自己起来（它会监听 9420）；
  4. 等 IDE 写出 `.ide` 文件（约 30–60 秒）；
  5. 再 `cli.bat auto --port 9420 --auto-port 9422`。
  **教训**：直接删掉 `.ide` 文件没用——CLI 会报「reading IDE port file」失败，
  必须让 IDE 自己重新写出来。我试过删+备份，最后是还原备份、等 IDE 启动才通。
