## 四、示例数据是怎么来的

`miniprogram/scripts/gen-example-reports.py` 直接调引擎 v2 `analyze()`，
从 `data/testset` 取样本跑出真实报告（unknown 用非招聘文本），写入
`src/common/exampleReports.js`。

实测跑出来的结果：

```
red     → fee=red,work=red,title=none,pay=none,company=none,contract=none  findings: 4
amber   → fee=none,work=none,title=amber,pay=amber,company=green,contract=none  findings: 3
green   → fee=none,work=none,title=none,pay=green,company=green,contract=none  findings: 2
unknown → 6 维全灰  findings: 0
```

**不是编的示例**，是引擎真实输出，所以报告页展示的就是真报告形态。

## 六、遇到的问题

### 1. 测试者报的「App.vue 20 处写死色值 / 16 次蓝色」已过时

复扫结果：`App.vue` **0 处**写死色值、0 处蓝色。
上一轮 R1 我已经把 App.vue 整篇重写成深色变量版，测试者的数字应该是扫的旧构建或旧快照。
本轮真正剩下的是 `constants.js` 的 5 个 v1 浅色底（`#FDECEA` 等），已改成变量名映射，现全项目 **0 处写死色值**。

建议测试者以 `pnpm check:r1` 的输出为准，它会给出精确定位。

### 2. `data/examples/` 目录还没建

开发者说会出「4 种 overall 的标准示例 JSON」，但我检查时 `data/examples/` 不存在。
我没等，直接用引擎 `analyze()` 跑了 4 份真实报告。开发者出标准示例后，可以对比一下有没有差异；
如果他的示例更贴近设计稿，我把脚本的取数换过去即可（脚本在 `scripts/gen-example-reports.py`）。

### 3. 自动化截图仍不可用

同上轮：9422 上的自动化窗口是空状态（`getCurrentPages()` 返回 `[]`），需要重新
`cli.bat auto --auto-port 9422`。`shot-pages.mjs` 和 `make-compare.py` 都已备好，端口通了直接跑。

### 4. 报告页示例数据的 unknown 是我构造的文本

测试集里没有 unknown 样本，我用「今天天气真好，我们去公园散步吧」这种非招聘文本喂引擎，
引擎正确判了 unknown 且 6 维全灰。这符合「非招聘截图 → unknown」的规则。
