# 示例报告样本与生成器加固（D3 收尾）

日期：2026-10-31　负责人：前端开发者（生成器/断言）、软件测试者（反向验证）

## 一、背景

前端排查发现：`gen-example-reports.py` 用 `r.get("overall")` 选测试样本，但 `data/testset/index.jsonl` 的标签是嵌套结构 `label.overall`，导致 4 种 overall 一个都选不到，**另外 3 份静默退回 `data/examples/` 的旧 v2 示例**，脚本仍然打印「成功」。已修 `label_overall()` 兼容嵌套/平铺两种写法，并去掉脚本里写死的 `v2.0`。

我在复核时又发现两处残留风险，本文件是处置口径。

## 二、决定：示例改用独立固定样本

对外示例（首页「先看一份示例报告」4 个入口 + 报告页「示例报告」标记）一律用 `src/scripts/example-samples.json` 的固定样本，**不再从 `data/testset/` 取材**：

1. **示例是产品内容，不能和评测集耦合。** 评测集换样本、调规则不应该改变对外展示的示例；否则示例会随评测资产漂移，且每次都要跟着重拍截图。
2. **页面标注「内容是虚构的，不指向任何公司」必须为真。** 原 green 示例来自 T015 构造样本，公司名「青岛海联信息技术有限公司」无法核实是否真实存在（检索无结论）。按合规口径「找不到来源就写待核实」，产品内容不能赌；公司名一律显式带「示例」——现用「青岛示例信息技术有限公司」。
3. **unknown 不再用「今天天气真好，我们去公园散步吧」。** 改成真实上传里最常见的「信息不足」场景：只有面试邀约、没有岗位/薪资/公司信息的聊天截图。这同时符合该状态的文案「信息不足，再补一张截图」。

red / amber 两份样本与现行示例同源（T001 去掉已失效的微信号、T008 原样），引擎输出与现有示例逐字段一致，只有 green 的公司名和 unknown 一份变化，截图重拍范围最小。

## 三、四份固定样本与引擎实测（2026-10-31，引擎 RULES_VERSION=v3.0）

| key | 样本内容 | 引擎 overall | findings | 维度灯 |
| --- | --- | --- | --- | --- |
| red | 刷单返利 + 垫付货款 | red | 4 | fee=red, work=red |
| amber | 储备干部/电话销售/底薪低提成高 | amber | 2 | pay=amber, company=green |
| green | Java 后端，公司名带「示例」 | green | 2 | company=green, pay=green |
| unknown | 面试邀约聊天（无岗位/薪资/公司信息） | unknown | 0 | 全 none，is_job_posting=true |

样本原文见 `src/scripts/example-samples.json`。

## 四、生成器加固要求（前端）

1. **只读固定样本文件**，删除 `load_standard()` 对 `data/examples/` 的依赖；任一 key 缺失、样本文件不存在、引擎抛异常，打印原因并 `exit 1`，**禁止用旧示例补齐**。
2. 跑完逐份断言 `report.overall == key`，不相等 `exit 1`（防止规则变动后把红报告塞进 amber 的 key 里）。
3. 生成文件头注释、`rules_version` 取 `engine.prompts.RULES_VERSION`（已做，保留）。

## 五、断言收紧（`src/scripts/check-r1.mjs` 第 22 组）

现在这组断言有两处空档：只检查「所有 versions 都等于引擎版本（共 N 份）」——**3 份也能过**；「4 种 overall 齐全」是全文搜 `"red"` 等字符串——维度灯里本来就有 `red/amber/green`，**错位也能过**。且注释写着「示例必须是引擎现跑的，不能退化成读旧示例」，但没有任何断言约束这一点。收紧为：

1. 恰好 4 份，`"overall"` 取值集合 = `{red, amber, green, unknown}` 且各出现 1 次；
2. `rules_version` 条目数 = 4，且全部等于 `engine/prompts.py` 的 `RULES_VERSION`；
3. 每份的 `overall` 与它所在 key 一致（key 名 = 外层键）；
4. 示例中的公司名必须含「示例」。

## 六、反向验证（测试者）

1. 删掉 `example-samples.json` 里任一条 → 生成器必须非 0 退出，且不得写出旧数据；
2. 把 green 样本改成一条 red 文本 → 生成器必须非 0 退出（overall ≠ key）；
3. 上面两步都恢复后，重新生成、重跑 `check:r1` 全绿。

## 七、后续清理

`data/examples/report_*.json` 是 v2 旧标准示例，生成器不再使用。由软件开发者确认无其他引用后归档或删除（其 README 还写着「测试截图按这四份跑」，与现状不符），避免下次又被当数据源静默读回来。

## 八、验收

- `python src/scripts/gen-example-reports.py` 退出码 0，打印 4 行且 key/overall 一致；
- `npm run check:r1` 收紧后全绿；
- 首页 4 个示例入口可打开、报告页顶部「示例报告 · 内容是虚构的，不指向任何公司」在；
- green/unknown 示例截图重拍（首页入口 + 报告页各一张）。
