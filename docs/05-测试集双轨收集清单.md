# 测试集双轨 · 收集清单与标注格式

- 编写：软件测试者
- 依据：路线调整令第九节、`docs/12-路线调整执行计划.md`
- 目标：**300 张**（真实 ≥120，合成补足）
- 合规底线：真实截图**打码后仅内部使用**；禁止批量爬取、禁止绕登录、禁止用他人账号

---

## 一、双轨定义

| 轨道 | 来源 | 目标数量 | 用途 | 授权要求 |
| --- | --- | --- | --- | --- |
| **real** | 公开反诈案例、新闻报道、用户授权提供 | **≥120** | 验真实场景准确率（唯一有对外说服力的口径） | 需老板授权来源口径 |
| **synthetic** | 开发者渲染器生成（D3–D4） | 补足至 300 | 覆盖长尾形态（变形写法、模糊、截半） | 无需授权，但**不得混入真实评测结论** |

**硬规定**：报告里真实/合成**必须分开统计**，禁止合并成一个数字对外说。

---

## 二、标注格式（JSONL，一行一条）

```json
{
  "id": "R0001",
  "track": "real",
  "source": {
    "type": "public_case | news | user_consented | synthetic",
    "url": "https://...",
    "collected_at": "2026-10-31",
    "note": "来源说明，便于复核时回查"
  },
  "image": "data/testset/images/R0001.png",
  "ocr_text": "data/testset/ocr/R0001.txt",
  "masked": true,
  "label": {
    "overall": "red",
    "dimensions": {
      "fee": "red", "work": "amber", "title": "none",
      "pay": "none", "company": "none", "contract": "none"
    },
    "expected_findings": [
      {"dimension": "fee", "evidence": "入职需缴纳服装费 980 元"}
    ]
  },
  "style": "job_detail | chat | mixed",
  "difficulty": "easy | medium | hard",
  "notes": "标注时的判断依据"
}
```

### 字段约束

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 真实轨道 `R` 开头，合成轨道 `S` 开头，**编码即区分轨道** |
| `track` | 是 | `real` / `synthetic`，与 id 前缀必须一致 |
| `source.type` | 是 | 真实图必填来源类型；合成图填 `synthetic` |
| `source.url` | 真实必填 | 可回查的原始地址 |
| `masked` | 是 | 真实图打码后为 `true`，未打码（罕见，如纯文字新闻）也标 `false` 并说明 |
| `label.overall` | 是 | `red` / `amber` / `green` / `unknown` |
| `label.dimensions` | 是 | **6 个维度全部给出**，未提到用 `none` |
| `style` / `difficulty` | 是 | 用于分层统计，看哪类难 |

## 三、收集清单（按来源类型）

### 3.1 公开反诈案例（优先，合规风险最低）

| 来源 | 可获数量估算 | 获取方式 | 注意 |
| --- | --- | --- | --- |
| 国家反诈中心公开案例 | 20–30 | 官网公开 content **手工复制文字**，由渲染器合成图 | 不抓图，只取文字要点 |
| 各地公安 / 人社部门公开通报 | 20–30 | 同上 | 记录原文 URL |
| 主流媒体招聘诈骗报道 | 30–40 | 同上 | 需注明媒体与日期 |

> **做法**：公开案例只取**文字描述的套路话术**，交给渲染器生成合成图，
> 这样既覆盖真实话术，又不涉及他人截图版权与隐私。**这类图归 synthetic 轨道**。

### 3.2 新闻报道截图（谨慎）

| 来源 | 数量估算 | 注意 |
| --- | --- | --- |
| 媒体已公开的诈骗截图（含马赛克） | 10–20 | 若已有媒体打码可直接用；否则**必须先二次打码** |

### 3.3 用户授权提供（最有价值，需老板协调）

| 来源 | 数量估算 | 要求 |
| --- | --- | --- |
| 老板或同事自己的招聘聊天记录 | 20–40 | 需本人书面同意；打码后使用 |
| 内测用户主动提交 | 视情况 | 协议里需写明可用于模型评测 |

### 3.4 合成补足

| 类型 | 数量 | 说明 |
| --- | --- | --- |
| 岗位详情页样式 | ~90 | 渲染器生成，含变形写法/模糊/截半 |
| 聊天记录样式 | ~90 | 同上 |

## 四、真实截图处理规范（合规红线）

1. **必须先打码再入库**：手机号、微信号、QQ、身份证、银行卡、人名、公司名（可选保留）、门牌号
2. **打码不可逆**：不保留未打码原图（如需复核，另存加密归档并记录）
3. **不落公开仓库**：`data/testset/images/` 已在 `.gitignore` 中排除
4. **禁止**：
   - 批量爬取招聘平台/社交平台
   - 绕过登录墙、验证码
   - 使用他人账号获取
5. **记录来源**：每条真实图必须有可回查 URL 或授权说明

---

## 五、标注流程

```
收集 → 打码 → 存图 + OCR 文本 → 双人标注 → 分歧仲裁 → 入库
```

- **双人标注**：测试者 + 产品/开发各一人，分歧项由 Chief 仲裁
- **仲裁记录**：分歧项单独记 `label_disputes.jsonl`，便于回溯标注口径
- **一致性要求**：至少抽 30 条做双人复核，一致率 <90% 需重训标注口径

## 六、评测口径（route 调整令要求）

| 指标 | 真实轨道 | 合成轨道 |
| --- | --- | --- |
| 整体结论准确率 | ✅ 必报 | 参考 |
| 6 维度级准确率 | ✅ 分开报 | 参考 |
| 高危召回 / 误判 | ✅ 必报 | 参考 |
| 证据可追溯率 | ✅ 必报（100%） | ✅ 必报 |
| **同图一致性** | ✅ 连跑 2 次结果完全相同 | ✅ 同 |
| 单次耗时 | ✅ ≤5 秒 | ✅ 同 |

> **对外只说真实轨道的数字**。合成轨道数字只用于内部看长尾覆盖，不能当"准确率"宣传。
