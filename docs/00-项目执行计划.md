## 二、不可动摇的原则

1. 优先级：合规红线 ＞ 识别准确率 ＞ 功能完整 ＞ 进度。
2. 每个任务包交付三样：产出物（代码/文档/配置）、自测结果、遇到的问题。
3. 需核实项一律以官方文档最新版为准；与本计划不一致的，以官方为准并在群里说明。
4. 资质、价格、预算、产品名不自行假设，全部进 `docs/02-待老板确认清单.md`。
5. 登记（生成式 AI）没下来之前只做受邀内测，不对公众上线。

## 六、周报机制

每周一次，老板在群里收：本周完成什么、下周做什么、有什么风险、哪些事需要老板拍板。

## 七、当前已知风险

1. **本机只有微信开发者工具，没有抖音开发者工具**。下派书首发平台是抖音，但本机只能跑微信端（uni-app 的 mp-weixin 构建）。抖音端本地联调要么装抖音开发者工具，要么真机调试。已进待老板确认清单。
2. **没有 DeepSeek API key**。T3 的模型层先做成可替换适配器 + mock，真实模型联调需老板提供 key（走安全卡片）。
3. **OCR / 内容安全需要云厂商账号**。原型阶段允许用本地 mock 文本跑通链路，真实准确率评测必须接真 OCR。
4. **测试集 300 张的来源需要授权**：公开反诈案例抓取、团队自行收集、正常招聘截图，涉及第三方个人信息，需老板确认渠道与合规口径。
5. **MySQL/Redis 未就绪**：本机有 MapleMySQL 服务但未启动，无 Redis；T4 原型期先用 SQLite + 进程内队列兜底（见 D2）。
6. **模型已换代**：需求书选的 `deepseek-v4-flash-vision-exp` 已于 2026-09-10 下线并路由到 V4.1-Flash。正式选型改 `deepseek-flash`（原生多模态，官方定价页已复核）；备案号与商用授权未核实，上线前必须向 DeepSeek 拿到书面材料。
7. **类目定向准入**：「工具 > AI工具 > AI工具」是定向准入，要内测申请表 + 第三方算法备案材料，审核 1~2 个工作日，一个月最多改 5 次类目，存在被拒风险，排期须前置。
8. **支付硬约束**：AI工具类目单笔交易 ≤300 元；虚拟商品必须走钻石支付/苹果支付；iOS 端不得展示价格与购买入口，也不得引导到站外或安卓支付。
9. **套路库质量**（2026-10-31 更新）：已补齐 50 个套路（每个 3–6 条话术样本），套路召回 76.19%（16/21）达标、精确率只有 42%——本地字符 TF-IDF 降级方案的短板，候选还要过模型与证据校验，暂不阻塞；接云向量服务后重调阈值并重报召回/精确率，不允许靠压低阈值硬凑召回。

## 八、决策记录

- **D1 报告脱敏分层**（2026-10-31）：证据校验 / 等级校准时用未脱敏 OCR 原文，`report.py` 输出前对 `evidence`、`summary`、`reason` 等全部字段脱敏；评测口径拆成「脱敏前证据可追溯率」与「输出层 PII 零泄漏」两条，后者为硬断言。依据：下派书 §8 要求报告里的手机号一律脱敏。
- **D2 T4 数据层**（2026-10-31）：原型期用 SQLite + 进程内任务队列，表结构按 §5.3 八张表、接口按 §5.4 十一项设计；换 MySQL/Redis 只换实现。额度只走流水汇总，不允许直接改余额。
- **D3 本地测试目标端**（2026-10-31）：本机只有微信开发者工具，本地自动化测试跑 uni-app 的 mp-weixin 构建；抖音端要另装抖音开发者工具或真机调试，等老板拍板（docs/02 第 8 条）。
- **D4 团队编制**（2026-10-31）：Chief（执行总负责人/技术负责人）+ 软件开发者（引擎/后端）+ 前端开发者（小程序）+ 软件测试者（测试/提审）+ 产品经理（合规/文案）。不设架构师（架构已由下派书 §5 定死），不设专职 UI（MVP 用原生组件）。
- **D5 /analysis 异步化**（2026-10-31）：接口对外语义固定为「创建任务立即返回 task_id → 轮询 GET /analysis/{id}」，内部执行改为后台线程/队列（pending → running → done/failed）；接真实 OCR/多模态模型后预计超 30 秒，不允许阻塞 HTTP 请求。失败仍必须退次数，预扣与正式扣除的时序不变。
- **D6 模型选型**（2026-10-31）：正式模型名固定为 `deepseek-flash`（DeepSeek-V4.1-Flash-1017），旧名 `deepseek-v4-flash-vision-exp` 只可作兼容、不得写进正式代码与对客文档；引擎保留 provider 抽象，随时可切别的已备案厂商，但切换前必须先拿到备案与商用授权。
- **D7 iOS 与会员口径**（2026-10-31）：iOS 端不展示会员价格、不出现购买入口，文案「因相关规范，iOS 暂不可用」，不得引导到安卓/公众号/H5/网页支付；会员权益只列「检测次数」「历史保存时长」；「免广告/去广告/无广告/跳过广告」为文案黑名单，属硬性验收项。单笔订单金额 ≤300 元（30000 分）。
- **D8 创建响应状态口径**（2026-10-31）：`POST /analysis` 的响应里任务状态允许是 `pending` 或 `running`（后台线程可能已开跑），但**不得**是 `done`/`failed`，且响应不得携带报告。契约与测试都按这条改，禁止用 sleep 等 `pending` 的写法（会 flaky）。
- **D9 多图上传协议**（2026-10-31）：新增 `POST /analysis/upload`（multipart，单图字段 `image` → 返回 `image_id`、`hash`、`expire_at`），再 `POST /analysis`（JSON：`image_ids` 1–3 个 + `Idempotency-Key`）。原因：uni-app 的 `uploadFile` 单次只能传一个文件。原型期 `ocr_text` 旁路字段保留，正式版删除。
- **D10 平台优先级：先微信**（2026-10-31，老板指示）：现阶段开发、测试、提审全部以**微信小程序**为目标端；抖音端暂停投入（代码保留、不迭代、不验证、不申请类目）。影响：① T1 的抖音结论转为备查（docs/03）；② 新增微信侧规则核实（docs/08-T1W）；③ T0 的注册、备案、类目、流量主、支付改为按微信小程序走；④ 下派书 §5.1「抖音首发」暂缓，若后续恢复抖音首发需重新评估排期与资质；⑤ 平台差异代码保留 `platform=wechat|douyin` 配置，不能把抖音约束（如 iOS 隐藏会员、单笔 ≤300、钻石支付）硬编码进核心逻辑。
