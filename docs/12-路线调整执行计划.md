# 路线调整执行计划（一期去大模型版，7 天）

- 依据：《面试请等等 · 路线调整令》2026-10-31（**优先于之前所有文档**：改版任务书、项目任务下派书、T1 核实结论、路线冲突处一律以本令为准）。
- 一句话：一期**不用大模型、不用云 OCR、不做生成式 AI 登记、产品里不出现「AI」字样**；识别全部改成确定性程序（本地开源 OCR + 规则引擎 + 套路库匹配）。
- 交付：**7 天内**出「准确率报告 + 真机跑通录屏」。

## 一、和旧路线相比变了什么

| 项 | 旧 | 新 |
| --- | --- | --- |
| 识别 | 规则 + 大模型（deepseek-flash）+ 证据校验 | **纯确定性**：RapidOCR → 文本规整 → 六维规则 → 套路库 TF-IDF 匹配 → 按模板拼报告 |
| OCR | 云 OCR | **RapidOCR（Apache-2.0）本地 CPU**，长边缩到 1600；备选 PaddleOCR |
| 登记 | 生成式 AI 登记 3–4 个月（关键路径） | **不做**（不用生成式模型，不属《暂行办法》第二条/第二十二条范围）；删掉模型公示相关页面与任务 |
| 文案 | 有「AI 检查」「AI 服务说明」「AI 生成」标识 | 全部去 AI：「自动检查」「检查规则说明」「本报告由系统根据截图文字和规则库自动生成」 |
| 报告 JSON | `source` 含 llm；`prompt_version` | `source` 只剩 `rule`/`pattern`；`prompt_version` → `rules_version` |
| 测试集 | 等授权 | **自己收集 + 自己合成**，300 张（真实 ≥120，其余合成），真实/合成分开统计 |
| 5 秒 | 30 秒 | **单次检查（≤3 张图）5 秒内出结果** |
| 实时性 | 大模型不稳定 | 同一张图每次结果必须一致（确定性） |

## 三、验收门槛（不变 + 新增）

- 高危召回率 ≥ 90%；正常岗位误判高危 ≤ 5%（真实、合成分开统计）。
- 单次检查（1–3 张图）≤ 5 秒。
- 同一张图重复检查结果一致（确定性）。
- 每条发现都能指回 OCR 原文（证据可追溯 100%）；PII 输出层 0 泄漏。
- 报告 JSON 通过 schema（`source` 仅 `rule`/`pattern`，`rules_version` 存在）。

## 四、测试套改造（路线令第九节）

- **快速冒烟**：< 1 分钟，每次提交都跑（工具链检查 + 引擎关键用例 + 接口冒烟）。
- **全量**：每天跑一次（社区、风控、构建产物）。
- 找出最慢 10 条用例；社区与 IP 风控用例改为**共用一个服务实例**，不再每条起服务。

## 五、真机测试（路线令第七节）

- 今天用微信开发者工具「测试号」扫码在真机上跑（测试号不能测付费和广告）。
- 正式 AppID 要等老板执照与注册；拿到后补真机付费与广告测试。
- 主体注册后不能改，顺序固定：**先办执照 → 再注册小程序**。

## 六、风险与对策

1. **RapidOCR 中文识别率/速度**：已实测（2026-10-31）：单张合成图 2.4–2.8s（intra=8）、单张竖屏截图 3.9–5.2s；`scripts/ocr_demo.py` 在并发跑测试时首图 20.9s（含建模）、3 张 23.9s——**并发会严重污染耗时**，性能基准必须在安静环境测并标注并发状态。**本机达不到「3 张 ≤5 秒」**，对策：limit 800–1000 找 CER/耗时平衡；试 PP-OCRv5/PaddleOCR mobile + MKLDNN/OpenVINO EP；服务器选高主频多核并必测；若仍不达标，需老板确认放宽到 ≤8 秒或单张 ≤3 秒，不得自行改验收口径。
2. **300 张测试集工作量**：合成脚本先行（开发者出渲染器），真实截图按路线令第四节来源人工摘录，禁止批量爬取/绕登录；真实截图仅内部使用、先打码。
3. **规则引擎误判**：六维规则按路线令第三节先写死，再用测试集调；每条规则必须有正例/反例。
4. **确定性带来的文案生硬**：全部模板化，模板由产品经理审定（法条/问 HR 问题/核实方法）。
5. **测试号限制**：不能测付费/广告，这部分等正式 AppID，不算一期卡点。
