# 后端接口契约（T4 骨架 + 前端 mock 依据）

- 依据：需求书 §5.4 接口清单、§5.3 数据表、§6 商业化、§7/§8 合规
- 代码：`backend/`（FastAPI + SQLite 原型）
- 版本：v0.1（2026-10-31）
- 状态：**可运行骨架**，登录/支付是原型实现，词库/额度/报告/回调幂等已落实

> 前端（`miniprogram/`）按这份契约做 mock，字段名不要自创；后端改了字段必须同步改这里并通知前端。

## 一、通用约定

### 1.1 地址与启动

```bash
# 在 D:\qiuzhibilei 下
python -m pip install -r backend/requirements.txt
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
# 交互式文档：http://127.0.0.1:8000/docs
```

### 1.2 响应封套

所有接口都是同一个形状（HTTP 状态码表达结果类别，`ok` 字段给前端兜底判断）：

```json
{ "ok": true,  "data": { }, "request_id": "6c529d2a163544c1" }
{ "ok": false, "error": { "code": "QUOTA_EXHAUSTED", "message": "…", "detail": {} }, "request_id": "6c529d2a163544c1" }
```

- `request_id`：客户端可用 `X-Request-Id` 传入，不传由服务端生成；排查问题必须带上它。
- 时间统一 `YYYY-MM-DD HH:MM:SS`（本地时区，原型期）；金额统一「分」（`amount_fen`）。

### 1.3 鉴权

- 登录后拿 `token`，之后所有接口带 `Authorization: Bearer <token>`。
- 后台接口带 `X-Admin-Token: <token>`（原型期固定值，真实实现换后台账号 + 权限）。
- token 是 HMAC 自签，7 天过期；真实实现换成平台登录态 + 服务端会话。

### 1.4 错误码表（前后端共用的唯一口径）

| code | HTTP | 含义 | 前端动作 |
| --- | --- | --- | --- |
| `VALIDATION_ERROR` | 400 | 参数不合法 | 提示用户重试 |
| `UNAUTHORIZED` | 401 | 未登录/过期 | 重新登录 |
| `FORBIDDEN` | 403 | 无权访问（含非管理员） | 不展示入口 |
| `NOT_FOUND` | 404 | 资源不存在（含他人报告，不暴露存在性） | 提示不存在 |
| `QUOTA_EXHAUSTED` | 402 | 次数不足 | 弹「看广告换 1 次 / 开会员」 |
| `IDEMPOTENCY_CONFLICT` | 409 | 幂等键/平台单号已被他用 | 提示刷新后重试 |
| `ORDER_NOT_FOUND` | 404 | 支付回调的订单不存在 | 平台侧重推 |
| `AMOUNT_MISMATCH` | 400 | 回调金额与订单不符 | 拒绝发货，人工排查 |
| `SIGNATURE_INVALID` | 401 | 回调验签失败 | 拒绝 |
| `CONTENT_BLOCKED` | 422 | 图片未过内容安全 | 提示换图，**不扣次数** |
| `RATE_LIMITED` | 429 | 太频繁（分析 10 次/分钟） | 稍后再试 |
| `PLATFORM_ERROR` | 502 | 平台 code2session 调用失败（配了真实凭据但调不通） | 提示稍后重试 |
| `ANALYSIS_UNAVAILABLE` | 503 | OCR/云服务不可用 | 提示稍后，**已退次数** |
| `ANALYSIS_FAILED` | 502 | 模型失败/schema 两次不合格 | 提示稍后，**已退次数** |
| `INTERNAL_ERROR` | 500 | 服务内部错误 | 提示稍后 |

### 1.5 幂等要求（写死在实现里）

| 场景 | 幂等键 | 行为 |
| --- | --- | --- |
| 创建分析任务 | 请求头 `Idempotency-Key` | 同一用户+同一 key 返回第一次的任务，不再预扣 |
| 24 小时同图去重 | 图片 SHA256 | 同用户同组图 24h 内直接返回旧报告，不扣次数 |
| 广告奖励 | `request_id` | 重复提交返回第一次结果（`replayed=true`），不重复发放 |
| 支付回调 | `platform_order_id` | 重复推送返回已发货结果（`replayed=true`），不重复加会员 |
| 额度流水 | 每条流水的 `idem_key` 唯一索引 | 冲正/预扣/退回重复执行不会多记 |

## 二、接口逐个说明（12 个端点，覆盖 §5.4 的 11 个接口条目，`/admin/*` 展开为 3 个）

### 2.1 POST /auth/login — 平台 code 换登录态

请求：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `platform` | string | 是 | `toutiao` / `weixin` |
| `code` | string | 是 | `tt.login` / `wx.login` 拿到的 code（1–256 字符） |

响应 `data`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `token` | string | Bearer token |
| `user_id` | string | 用户 ID |
| `platform` | string | 平台 |
| `created_at` | string | 注册时间 |
| `is_new_user` | bool | 本次是否新建账号 |
| `quota.balance` | int | 剩余次数（新用户 3） |
| `membership.active` | bool | 会员是否有效 |
| `membership.plan` | string/null | `week`/`month`/`quarter` |
| `membership.expires_at` | string/null | 到期时间 |
| `membership.daily_limit` | int/null | 会员每日上限（20），非会员为 null |
| `checked_count` | int | 累计检查次数（报告数，未过期的） |
| `red_count` | int | 其中整体结论为 red 的次数 |
| `platform_mode` | string | `mock` / `live` / `dev`：登录走的是 Mock、真实平台 code2session，还是开发通道 |
| `dev_login` | bool | 是否走的开发登录通道（`code=mock`）。正式环境必须为 false |
| `ad` | object | 激励视频位：`mode`/`enabled`/`unit_id`/`daily_cap`/**`today_count`**/**`remaining_today`**；`mode=mock` 时前端不得发起真实广告请求 |

- 新用户首次登录自动送 3 次（流水 `register_bonus`，幂等键 `user:{id}:register`，重复登录不重复送）。
- 登录走平台适配层（`backend/app/platform/`）：配了 `QBL_TT_APPID`/`QBL_TT_SECRET` 才是真实 `code2session`，否则 `platform_mode=mock`；平台返回的 `session_key` 不落库。

**开发登录通道（B 关口联调 / 没有正式 AppID 时用）**：

| 项 | 规则 |
| --- | --- |
| 开关 | 服务端环境变量 `QBL_DEV_MODE=1` 才启用（`scripts\run_backend.ps1` 默认打开）；**生产必须为 0**，否则返回 403 `DEV_LOGIN_DISABLED` |
| 用法 | `code=mock` → 固定开发账号；`code=mock:<任意串>` 或请求头 `X-Debug-User: <串>` → 不同开发账号（方便并发/越权用例） |
| 标记 | 响应 `dev_login=true`、`platform_mode=dev`，前端/测试一眼可辨，不得在正式环境依赖 |
| 安全 | 只在开发环境开；生产关闭后 code=mock 直接 403 |

**CORS**：只放本机来源，正则 `^https?://(localhost|127\.0\.0\.1)(:\d{1,5})?$`，不开 `*`；跨域预检需带 `Origin` 且命中该正则。

### 2.2 GET /me — 用户信息、余额、会员状态

响应 `data`：同 2.1 去掉 `token` / `is_new_user` / `dev_login`；`ad.today_count`、`ad.remaining_today` 在这里也会返回（用户能看到今天还能看几次广告）；`checked_count`、`red_count` 给「我的」页统计用。

### 2.3a POST /analysis/upload — 上传单张截图（D9 第一步）

`Content-Type: multipart/form-data`，字段 `image`（单张，png/jpg/jpeg/webp，≤10MB）。

响应 `data`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `image_id` | string | `i_...`，建任务时传这个 |
| `hash` | string | 图片 SHA256（用于去重） |
| `size` | int | 字节数 |
| `expires_at` | string | 过期时间（默认 24 小时后，§8 原图不长期保存） |
| `safety` | object | 内容安全第一道闸结果：`passed`/`mode`/`note` |

- 上传**不扣次数、不建任务**；
- **内容安全两道闸**：第一道在这里（超限/可疑直接 422 `CONTENT_BLOCKED`，不入库）；第二道在分析链路内（引擎内容安全适配器）——任何一道拦下都不扣次数；
- `image_id` 只对上传者有效，他人使用或不存在 → 400 `IMAGE_NOT_FOUND`；已过期 → 400 `IMAGE_EXPIRED`。

### 2.3 POST /analysis — 创建分析任务（D9 第二步，立即返回）

请求（JSON，推荐）：

```json
{ "image_ids": ["i_...", "i_..."], "idempotency_key": "可选", "ocr_text": "仅原型期旁路" }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `image_ids` | string[] | 是（或用 `ocr_text`） | 1–3 个本人上传的 `image_id`，顺序即 `image_hashes` 顺序 |
| `idempotency_key` | string | 否 | 同一用户同一 key 只建一次任务；也可用 `Idempotency-Key` 头，body 优先 |
| `ocr_text` | string | 否 | **仅原型期**：没有云 OCR 时直接给 OCR 文本，正式版删除 |

**兼容**：旧的 `multipart/form-data`（`files[]` + `ocr_text`）仍接受，属于过渡兼容，T4 正式版删除。

**状态口径（D8）**：创建响应的 `status` 允许 `pending` 或 `running`，**不得是 `done` / `failed`，也不得带 `report`**；报告只能从 2.4 轮询拿（异步线程池可能在你收到响应前就已经把状态推进到 `running`，这是正常的，不是缺陷）。

响应 `data`（创建时）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `task_id` | string | 任务 ID，轮询用 |
| `status` | string | `pending` 或 `running`（D8；已完成预扣） |
| `poll_after_ms` | int | 建议轮询间隔（默认 1500ms） |
| `quota.balance` | int | 预扣后的余额 |
| `dedupe_hit` | bool | 命中 24 小时去重时为 true（不扣次数、直接带旧报告） |
| `idempotent_replay` | bool | 幂等重放时为 true |
| `report` | object/null | 仅 `dedupe_hit` 时可能直接带旧报告；正常创建不带 |

错误（在创建阶段就返回，不会建任务）：

| 情况 | HTTP/code | 额度 |
| --- | --- | --- |
| 次数不足 | 402 `QUOTA_EXHAUSTED`（`detail.balance`） | 不扣 |
| 参数不合法（图片数量/格式/大小、JSON 解析失败） | 400 `VALIDATION_ERROR` | 不扣 |
| `image_id` 不存在或属于他人 | 400 `IMAGE_NOT_FOUND` | 不扣 |
| `image_id` 已过期 | 400 `IMAGE_EXPIRED` | 不扣 |
| 同一分钟超 10 次 | 429 `RATE_LIMITED` | 不扣 |

**分析阶段失败的，从 2.4 轮询结果里拿**（`status=failed` + `error_code`），不占 HTTP 错误码；额度已自动退回。

额度三段式（`quota_ledger` 流水，余额 = SUM(delta)，任何地方不直接改余额）：

```
analysis_hold  -1（提交即预扣）→ 成功 analysis_mark 0（标记正式扣除）
                              → 失败 analysis_refund +1（退回）
```

响应 `data`：

### 2.8 POST /pay/notify — 支付平台回调（验签 + 幂等发货）

## 三、状态机

### 3.1 异步分析状态机时序（D5，前端与测试都按这个来）

```
前端                        后端                        额度流水
 |  POST /analysis          |                            |
 |------------------------->| 校验 → 去重 → 预扣 → 建任务  | analysis_hold -1
 |<-------------------------| 200 {task_id,status=pending,| 
 |                          |      poll_after_ms}        |
 |                          | 线程池取任务: pending→running |
 |  GET /analysis/{id}      |                            |
 |------------------------->| {status:running}           |
 |   每 poll_after_ms 轮询一次 |                            |
 |                          | 分析成功 → 存报告           | analysis_mark 0
 |<-------------------------| {status:done, report}      |
 |                          |                            |
 | 或：分析失败              |                            |
 |<-------------------------| {status:failed,error_code} | analysis_refund +1
```

规则（测试者按这五条写用例）：

1. **创建即预扣**：`POST /analysis` 返回时（`status` 允许 `pending` 或 `running`，D8）余额已经 -1，且**响应里不得有报告**；被 402/400/429 拒绝时**不扣**。
2. **状态单向**：`pending → running → done` 或 `pending → running → failed`，终态不可回退；不允许出现 `done` 后又变 `failed`。
3. **成功正式扣**：`done` 时流水补一条 `analysis_mark`（delta=0，仅留痕），余额保持预扣后的值。
4. **失败必退**：任何分析期失败（内容安全、OCR 不可用、模型失败、schema 不合格、PII 泄漏）都写 `analysis_refund +1`，`status=failed`，`report=null`。
5. **30 秒转后台语义**：`elapsed_ms > 30_000` 且仍在跑 → `background_mode=true`，前端转「后台处理中，完成后在历史里看」，**服务端不取消任务**；任务照常跑完变 `done`。阈值可用 `QBL_BACKGROUND_AFTER_SECONDS` 调（仅测试用）。

轮询约定：`poll_after_ms` 由服务端下发（默认 1500ms），前端按它轮询；`done`/`failed` 后 `poll_after_ms=null`，停止轮询。

### 3.2 其它状态机

- 订单：`pending` →（回调 paid）`paid` /（回调 failed）`failed` /（回调 refunded）`refunded`。
- 会员：无记录 → 有效 → 到期（`expires_at` 过期后按非会员算；续费从 max(现在, 原到期) 顺延）。
- 额度：只有流水，没有余额字段；`SUM(delta)` 就是余额。

## 四、与识别引擎的对接

- 报告 JSON 就是引擎 §4.3 的 schema，后端**原样存、原样返**，不做二次加工（否则证据可追溯率无法复核）。
- 报告里的 evidence 已由引擎在输出层脱敏（手机号/证件号打码）；脱敏前的原文留档在引擎 `trace.evidence_raw`，**不进 API**。前端展示一律用报告里的脱敏版，别自己去还原。
- 引擎错误码 → 后端错误码：`CONTENT_BLOCKED`→422（不扣）、`OCR_UNAVAILABLE`→503、`MODEL_FAILED`/`SCHEMA_FAILED`/`PII_LEAK`→502（这几种退次数）。异步化后这些错误通过 2.4 的轮询结果返回（`error_code`），不在创建接口抛。
- 后端关闭引擎内置的全局去重缓存，改为「按用户 24h + 图片哈希」在库里查（引擎缓存是跨用户的，直接用会把 A 的报告返回给 B）。
- 执行器：原型期进程内 `ThreadPoolExecutor`（`backend/app/worker.py`），**接口语义已按 Celery 版设计**；换 Celery + Redis 只改 worker，不改接口。
- **报告 v2（R1）**：`reports` 里存的是 v2 报告 JSON（`overall`/`dimensions`/`findings`/`prompt_version`/`pattern_db_version`），字段定义见 [`docs/04-识别引擎设计.md`](04-识别引擎设计.md) §二；`reports.risk_level` 列现在存 `overall`（red/amber/green/unknown），列名沿用不改。
- 套路命中：报告落库时把 `findings[].pattern_id` 写进 `pattern_hits`，首页「最近常见」按近 7 天真实命中排序。
- **旧 v1 报告作废**：`risk_level`/`risks`/`verdict` 字段不再返回，前端/测试同批切 v2，不做双版本兼容；原型期库可清空。
