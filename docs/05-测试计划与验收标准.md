### 1.2 优先级（沿用项目原则）

**合规红线 ＞ 识别准确率 ＞ 功能完整 ＞ 进度**。因此本计划的**阻断级**用例集中在合规与准确率两侧。

### 1.3 「可上线」的判定口径

必须**同时**满足：

1. A 关口指标达标（§二）
2. B 关口主流程全通（§三）
3. C 关口合规材料齐备、安全测试无高危（§四）
4. **全部阻断级缺陷关闭**（§六 缺陷分级）
5. 生成式 AI 登记完成（老板侧 T0，不在测试判定范围，但**缺它不得公开上线**）

### 3.3 已知测试缺口（待开发者补接口后关闭）

1. **B5 次数用尽**：需要 `analysis` 路由的「余额不足」分支用例。
2. **B2 上传校验**：非图片、超大、超过 3 张的拒绝逻辑未覆盖。
3. **并发**：两个请求同时预扣只应成功一个（`BEGIN IMMEDIATE` 已具备，缺并发用例）。
4. **报告 TTL**：普通 7 天、会员 30 天，过期后不可读取——未覆盖。

## 六、执行与回归机制

### 6.1 一键跑测试

```powershell
cd D:\qiuzhibilei

```

### 6.2 回归触发条件

以下任一发生，必须全量回归：

- 词库 `lexicon_v1.json` 改动
- 引擎任一模块改动（`engine/`）
- 提示词版本（`prompt_version`）变更
- 后端额度/支付相关改动

### 6.3 测试有效性自检（**必做**）

本项目已出现一次「测试全绿但没测到东西」的情况：Mock 模型自己就输出正确答案，
导致「证据校验」「等级校准」被整个关掉，47 条用例仍然全绿。

**对策**：关键防线必须有**对抗性用例**——用故意作恶的假模型去打（`tests/engine/test_pipeline_depths.py`）。
改动这些防线后，测试者要重跑变异验证：

| 变异 | 期望 |
| --- | --- |
| 关掉 `evidence.verify_risks`（全保留） | 至少 3 条红 |
| 关掉 `calibrate.calibrate`（不抬级、不兜底） | 至少 3 条红 |

2026-10-31 首轮变异验证结果：**均已生效**（各 3 红），恢复后 79 绿。
