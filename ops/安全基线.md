## 1. 密钥不进代码、不进群聊

### 1.1 规矩

| 规矩 | 落地方式 | 证据 |
| --- | --- | --- |
| 仓库里只有 `.env.example`，没有真值 | `.gitignore` 第 19–21 行：`.env`、`.env.*`、`!.env.example` | `git check-ignore -v ops/.env` → 命中 `.gitignore:19`；`ops/.env.example` 不被忽略 |
| 提交前自动扫密钥 | `.githooks/pre-commit` 扫描；`sk-` 假密钥实测被拦 | `docs/STATUS.md` §五「已反向验证」 |
| 密钥不进群聊 | 一律走安全卡片（`request_secret`），只以环境变量 `$DSH_SECRET_*` 形式使用 | 本文规矩 |
| 后端默认值不是安全密钥 | `backend/app/config.py` 里 `dev-*-change-me` 是本地占位；**生产必须覆盖** | `backend/app/config.py:35-37` |

### 1.2 生产环境必须覆盖的变量

以下变量在生产 `.env`（只存在于服务器与密钥管理器中）里必须是**随机强口令（≥24 位）**，不许沿用默认值：

```
QBL_ADMIN_TOKEN        # 后台鉴权头 X-Admin-Token
QBL_TOKEN_SECRET       # 用户令牌签名
QBL_PAY_SECRET         # 支付回调签名
MYSQL_PASSWORD
MYSQL_ROOT_PASSWORD
REDIS_PASSWORD         # 生产必须非空
QBL_WX_SECRET          # 小程序 AppSecret
```

生成方式（在服务器本地生成，不要发到任何聊天工具）：

```bash
openssl rand -base64 32
```

### 1.3 轮换

- 密钥泄露 → **立即轮换**，不评估「影响小」。
- 轮换后旧的立刻失效，重启相关容器。
- 轮换记录写进 `docs/STATUS.md`（只写「何时轮换了哪个变量」，**不写值**）。

## 2. 管理后台限制访问来源

三层，缺一不可：

| 层 | 措施 | 状态 |
| --- | --- | --- |
| **应用层** | 后台接口全部走 `require_admin` 依赖，校验 `X-Admin-Token`（`backend/app/deps.py:43`）；`/admin/*` 与 `/community/admin/*` 都挂了 | ✅ 已实现 |
| **网络层** | Nginx 只允许**公司固定出口 IP** 访问 `/admin` 与 `/community/admin`，其余一律 403/444 | 待服务器就绪后配置（配置片段见 §2.1） |
| **安全组** | 管理后台专用端口不开公网 | 待服务器就绪 |

### 2.1 Nginx 白名单片段（上线时粘贴）

```nginx
# 只允许公司固定出口 IP 访问后台
location ~ ^/(admin|community/admin) {
    allow 203.0.113.0/24;   # ← 换成公司真实固定出口 IP（上线前填）
    deny all;
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

> 没有固定出口 IP 时，退而求其次：后台只从**内网/VPN**访问，用 `allow 10.0.0.0/8; allow 172.16.0.0/12; allow 192.168.0.0/16; deny all;`，通过 SSH 隧道或 VPN 打开。**不接受「挂个弱口令就当安全」**。

### 2.2 现状说明（不美化）

- 现在后台唯一防护是 `X-Admin-Token`。**若上线时没有再套 Nginx 白名单或 VPN，就不算合格**，本文把这条列为上线阻断项。
- 后台还没有账号体系与操作日志表（D23 排在第 3 项），建表前的操作痕迹只能靠应用日志兜底。

## 3. 防火墙只开必要端口

### 3.1 云安全组入方向

| 端口 | 来源 | 用途 | 是否必须 |
| --- | --- | --- | --- |
| 22/tcp | 公司固定 IP（或跳板机） | SSH 运维 | ✅ 必须（**不要对所有 IP 开放**） |
| 80/tcp | 0.0.0.0/0 | HTTP（仅用于 301 跳转与 ACME 证书校验） | ✅ 必须 |
| 443/tcp | 0.0.0.0/0 | HTTPS | ✅ 必须 |
| 3306 / 6379 / 8000 | — | **一律不开公网** | ❌ 严禁 |

容器层：`ops/docker-compose.yml` 里 api 只绑 `127.0.0.1:8000`，mysql 只绑 `127.0.0.1:3306`，redis **不映射任何端口**。

### 3.2 主机防火墙（ufw / firewalld）兜底

```bash
# ufw 示例：默认拒绝，只放行 22/80/443
ufw default deny incoming
ufw default allow outgoing
ufw allow from <公司固定IP> to any port 22 proto tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
```

### 3.3 SSH 加固

- 禁用 root 直接登录：`PermitRootLogin no`
- 禁用口令登录，只用密钥：`PasswordAuthentication no`
- 改默认端口（可选，属于纵深防御，不是必需）

## 4. HTTPS 全站

| 要求 | 做法 |
| --- | --- |
| 全站 HTTPS | Nginx 80 → 301 到 443，不留 HTTP 明文服务 |
| 证书 | 云厂商免费 DV 证书，到期前 15 天告警 |
| 协议 | 只开 TLS 1.2 / 1.3，禁用 1.0/1.1、RC4、3DES |
| HSTS | `Strict-Transport-Security: max-age=31536000; includeSubDomains` |
| 小程序侧 | 微信要求 request 域名必须是 HTTPS 且已备案，不接受自签证书 |
| 内部服务 | api 对 Nginx 走 127.0.0.1 明文可以接受（同机回环），跨机必须走内网 + TLS |

### 4.1 Nginx 关键片段

```nginx
server {
    listen 80;
    server_name <域名>;
    location /.well-known/acme-challenge/ { root /var/www/certbot; }
    location / { return 301 https://$host$request_uri; }
}

server {
    listen 443 ssl http2;
    server_name <域名>;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_certificate     /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    server_tokens off;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
