# 微信云托管可行性评估（D38 个人主体路线）

> 提交人：运维｜时间：2026-11-03｜对应：老板 2026-11-03 路线调整
> 问题：不买服务器、不买域名，改用微信云托管，能不能跑得起来？
> **结论：技术上可行；但性能有硬缺口，见 §4。价格与官方依据见 §3、§6。**

---

## 1. 结论先行

| 问题 | 结论 |
| --- | --- |
| 能不能跑 FastAPI 后端？ | **能**。云托管支持自定义 Dockerfile，Python 有官方上手指引 |
| 能不能跑 RapidOCR？ | **能跑，但慢**。容器里装 `rapidocr + onnxruntime` 没问题（纯 CPU wheel，不需 GPU） |
| 个人主体能不能开通？ | **能**。只需「微信小程序」账号，官方文档未按主体类型限制；小程序管理员/开发者扫码即可进控制台 |
| 需不需要域名？ | **不需要**。小程序调云托管用 `callcontainer`，官方原文：「不需要使用域名…也不需要域名备案」 |
| 需不需要 ICP 备案？ | **域名 ICP 不需要**；但**小程序备案是另一件事**（工信部要求，在微信公众平台内提交），与云托管无关，仍要做 |
| 月费大概多少？ | **见 §3**。按官方刊例价，空转约 34–137 元/月（取决于规格与缩放策略），有流量再加 |
| 单张 ≤4 秒能不能达标？ | ⚠️ **有风险，本机实测已超标**。见 §4 |
| 3 张 ≤10 秒能不能达标？ | ⚠️ **同样有风险** |

**总体建议：可行，可以走这条路。但「单张 ≤4 秒」这个验收线要先降下来，或者先做并发/优化，再决定。**
这不是我拍得了的，要 Chief/产品定。

### 3.2 常见规格的「24 小时常驻」月费

按 §3.1 单价 × 720 小时算出来的（可复核）：

| 规格 | 满负荷常驻月费 | 折算 |
| --- | --- | --- |
| 1 核 1G | 0.087 × 720 = **62.64 元** | 官方给的规格价 |
| 1 核 2G | 0.119 × 720 = **85.68 元** | 官方给的规格价 |
| 2 核 4G | 0.238 × 720 = **171.36 元** | 官方给的规格价 |
| 4 核 8G | 0.476 × 720 = **342.72 元** | 官方给的规格价 |
| 8 核 16G | **685.44 元**（按 8×0.055 + 16×0.032） | 由单价算得 |

> 官方文档直接给了 0.25 核到 4 核的规格价，**8 核 16G 是我按单价乘出来的**，不是官方原表（原表只列到 4 核 8G=0.476 元/小时）。

### 3.3 三种使用形态的月费区间

| 形态 | 空闲缩容到 0 | 规格 | 月费估算 |
| --- | --- | --- | --- |
| 内测期（每天几十次） | 是（无流量无成本） | 2 核 4G | **5–20 元** |
| 上线初期（日活几百） | 最小副本 1 保性能 | 2 核 4G | **约 171 元** + MySQL |
| 上线初期 | 最小副本 1 保性能 | 4 核 8G | **约 343 元** + MySQL |

⚠️ **保险起见，评估用数按「最小副本 1」算**：因为 OCR 是 CPU 密集型，缩容到 0 后冷启动会直接伤到「30 秒出报告」的体验。

### 3.4 没算进去的

- **MySQL**：0.342 元/（个·小时），常驻一个月 ≈ **246 元**（若用云托管自带 MySQL）。**这块比容器还贵。**
- 对象存储、CDN 流量、公网流量。

> 所以「云托管比买 ECS 便宜」这个说法**不一定成立**，取决于要不要自带 MySQL。好在我们的数据量极小、可以先用容器内 SQLite（D2 决定），把 MySQL 推迟。

## 4. ⚠️ 性能：这是真正的风险点

### 4.1 本机实测（2026-11-03）

| 条件 | 结果 |
| --- | --- |
| 机器 | Intel i7-10510U，**4 物理核 / 8 逻辑核**，8 GB |
| 测试图 | 750×1334 手机截图尺寸，用 `data/testset/ocr` 真实文本渲染 |
| 样本 | 5 个文件 × 3 次 = 15 次 |
| **P50 中位数** | **6.01 秒** |
| P90 | 7.11 秒 |
| 最快 / 最慢 | 3.96s / 7.74s |
| 引擎初始化 | 0.12s |

**⚠️ 重要说明**：测这组数的时候本机 CPU 负载是 **100%**（还有其他进程在跑），所以数字偏保守。
但即使打个折，**P50 6 秒已经超过「单张 ≤4 秒」的验收线**。

### 4.2 换算到云托管

云托管的容器规格**最大 8 核 16G**，而且这里说的是「vCPU」。本机是 4 物理核 / 8 逻辑核。
按官方说法「容器规格 ≈ 传统服务器规格除以 2–3」，云托管 2 核 4G 大约相当于一台 4 核 8G 服务器。

| 云托管规格 | 大致对应 | 预估单图 OCR |
| --- | --- | --- |
| 1 核 2G | 约 2 核 4G 服务器 | 可能 >10 秒，**大概率不达标** |
| 2 核 4G | 约 4 核 8G 服务器 | 约 6–8 秒（参考本机），**不达标** |
| 4 核 8G | 约 8 核 16G 服务器 | 可能 3–5 秒，**临界** |
| 8 核 16G | 约 16 核 32G 服务器 | 可能达标，月费约 685 元 |

**这些都是推演，不是实测**——云托管上的真实耗时必须部署后实测才算数。

### 4.3 三条可以接受的路（需要 Chief/产品选）

1. **放宽验收线**：把「单张 ≤4 秒」改成「单张 ≤10 秒、3 张 ≤30 秒」。产品口径能不能接受，要产品定。
2. **优化 OCR 本身**：缩小 `limit_side_len`（现 1000）、换更小模型、只对含关键词的区域识别。**这能省时间，但要开发者做实验**。
3. **提高规格**：4 核 8G 起，月费 343 元。钱能解决一部分。

## 5. 存储与「24 小时内删除」

| 项 | 云托管里的做法 | 能否满足 |
| --- | --- | --- |
| 截图存哪 | 容器本地临时盘（D37 已定：不落对象存储） | ✅ |
| 怎么删 | 应用层定时任务：每小时扫一次，过期即删（代码已实现 `backend/app/retention.py`） | ✅ |
| 能否满足 24 小时 | **能满足**。TTL 22h + 每小时扫描 ⇒ 删除 ≤23h（Chief D37 定案） | ✅ |

**注意一个云托管特有的坑**：容器实例会被**扩缩容销毁重建**（缩容到 0、滚动发布），
本地临时盘上的文件**会跟着实例消失**。这对我们反而是好事（数据自动没了），但：

- **删除日志 `deletion.log` 也会跟着没** → 需要把日志采到云托管「服务日志」（可配采集路径）。
- **数据库如果也放容器本地盘**，实例重建就丢数据 → 必须用云托管的 MySQL 或挂载持久化存储。

> 这一条要开发者和运维一起确认，落在部署方案里。

## 6. 需不需要备案（把两件事分开）

| 事项 | 云托管下 | 依据 |
| --- | --- | --- |
| **域名 ICP 备案** | **不需要**。小程序调 `callcontainer` 不走域名；云托管默认域名仅测试用 | [自定义域名文档](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/domain/) |
| **小程序备案** | **仍需要**。这是工信部对小程序主体的要求，在微信公众平台提交，与云托管无关 | 待核实具体流程（以公众平台当期规则为准） |
| 自定义域名 | 如果将来要给 H5/网页调用，才需要域名 + 备案 | 同上 |

**所以老板省掉的是「买服务器 + 买域名 + 域名备案」，省不掉「小程序备案」。**

## 7. 结论与建议

**可行，推荐走。**

理由：
1. 官方文档明确支持 Python 自定义部署 + 小程序调用免域名免备案，老板要的「不买服务器、不买域名」能实现。
2. 个人主体的小程序账号即可开通，没有主体类型限制。
3. 内测期成本极低（带免费额度，按量计费，无流量几近 0）。

**但必须同时向老板说明一个风险**：OCR 性能。本机实测 P50 已经 6 秒，云托管规格受限（最大 8 核 16G），
**「单张 ≤4 秒」大概率达不到**。这不是云托管的问题，是 OCR 本身在小机器上就慢。

**建议**：先把验收线谈成「单张 ≤10 秒」再去部署，否则部署完了验收过不了，白跑一趟。
