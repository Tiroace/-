# 云托管目标配置 OCR 基线：实测结论

> 提交人：运维｜时间：2026-11-03｜对应 D40 第①项
> 问题：云托管目标配置下，同一批 21 张图的 OCR 基线是否与开发机相近？

---

## 0. 结论（一句话）

**无法在云托管上实测——云托管尚未开通（等老板走完第 1 关操作单）。**

开发机上的**等效模拟也没测成**：测量期间本机 CPU 被其他任务占满（97–100%）、

## 1. 已经确定的事实（开发机，内存正常时测的）

见 `ops/evidence/ocr-baseline-21.txt`（2026-11-03 12:24，可用内存 1046MB / CPU 60%）：

| 指标 | 值 |
| --- | --- |
| 单张 P50 / P95 | 7.92s / 8.32s |
| 3 张串行 P50 / P95 | 25.55s / 32.00s |
| 3 张并行 P50 / P95 | 16.38s / 21.73s |

这是**开发机（4 物理核 / 8 逻辑核 / 8GB）**的数，不是云托管数。

## 2. 尝试过的等效模拟（失败，记录原因）

### 2.1 方法

用 `intra_op_num_threads` 限制线程数模拟云托管可用核数：

| 场景 | threads |
| --- | --- |
| 开发机全开 | 4 |
| 云托管 2 核 4G 模拟 | 2 |
| 云托管 1 核 模拟 | 1 |

脚本：`ops/scripts/ocr_cloudrun_sim.py`

### 2.2 结果（**不可用**）

| 场景 | P50 | P95 |
| --- | --- | --- |
| 开发机全开(4线程) | 12.84s | 18.62s |
| 2 线程 | 15.01s | 16.03s |
| 1 线程 | 20.03s | 23.32s |

### 2.3 为什么不可用

1. **同一组参数，开发机这次 12.84s，12:24 那次是 7.92s**——差 62%，环境被污染。
2. **2 线程的 P95（16.03s）比 4 线程（18.62s）还好**——违反常识，只能解释为噪声。
3. 测量时 CPU 负载 **100%**、可用内存 **800–1284 MB**（正常基线时是 60% / 1046MB）。

**结论：本机现在有其他任务在跑（多个 DSH 进程活动），不是测性能的时机。**
按纪律，**不用不可信的数据下结论**，直接废弃。

## 3. 能给出的判断（基于原理，不是实测）

| 问题 | 回答 | 依据 |
| --- | --- | --- |
| 云托管 2 核 4G 会比开发机慢吗？ | **会慢**，2 核 vs 8 逻辑核 | 一般规律；之前的单点测试显示线程数减半约慢 20–40% |
| 云托管 4 核 8G 呢？ | **接近开发机** | 核数与开发机物理核（4）相当 |
| 会不会达标 D40（单张 P95 ≤10s）？ | **开发机 8.32s，余量只有 17%**，云上稍微慢一点就破线 | 实测 P95 8.32s vs 线 10s |
| 3 张并行呢？ | 开发机 21.73s，线 25s，**余量 13%** | 同样很紧 |

**风险提示：D40 的验收线在开发机上余量只有 13–17%。云托管若慢 20%，两条线都会破。**
所以**部署当天必须实测**，并且要预先想好「不达标怎么办」（见 §5）。

## 4. 部署当天的验证方法（写进手册 §9 CP3）

1. 在云托管容器里跑 `ops/scripts/ocr_baseline_21.py`（脚本已支持记录环境快照）。
2. 记录：单张 P50/P95、3 张并行 P50/P95。
3. 与开发机基线（7.92 / 8.32 / 16.38 / 21.73）对比，**算倍数**。
4. 判定：
   - 达标（≤10s / ≤25s）→ 进下一检查点
   - 不达标但相差不多（如 11–12s）→ 升规格到 4 核 8G 再测
   - 明显不达标（>15s）→ **停下来报 Chief，不要硬上**

### 4.1 在云托管里怎么跑这个脚本

云托管可以「登录实例」开 webshell，直接执行：

```bash
cd /app
python /app/ops/scripts/ocr_baseline_21.py
```

> 前提：部署包里带上 `ops/scripts/`。当前 `make_cloudrun_pkg.py` 只打
> `backend/ engine/ rules/` ——**需要把 `ops/scripts/ocr_baseline_21.py` 也打进去**，
> 或者部署后临时用控制台上传。

## 5. 如果不达标怎么办（预案）

| 情况 | 动作 | 成本 |
| --- | --- | --- |
| 单张 10–13s | 升到 4 核 8G 复测 | 171 → 343 元/月 |
| 单张 13–16s | 关方向分类 + 压缩图片后再测 | 需开发者配合 |
| 仍不达标 | **改 D40 验收线**（如单张 ≤15s、3 张 ≤35s），但要重新评估「30 秒承诺」 | 产品决策 |
