## 0. 怎么用这张表

1. 个人助理把 §1 的选择题转给老板，**一次只问一个决定**。
2. 老板选完（或者说「你来定」），运维按 §3 的「选定后配置清单」直接部署。

## 1. 需要老板决定的只有 3 件事

### 决定 1：容器规格（影响月费，最大头）

| 选项 | 月费（1 副本常驻） | OCR 预期 | 推荐度 |
| --- | --- | --- | --- |
| A. 2 核 4G | **171.36 元** | 慢，可能 10 秒以上 | 内测期可用 |
| **B. 4 核 8G** | **342.72 元** | 相对快，但仍难进 4 秒 | ⭐ **推荐** |
| C. 8 核 16G | 约 685 元 | 最快 | 不推荐（贵且仍不保证） |

> 单价来源：[微信云托管产品定价](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/Billing/price.html)
> **内测期可以先选 A**，把「实例最小副本」设成 0，实际花费只有几十块；内测结束后再调 B。

### 决定 2：要不要接云托管自带的 MySQL（第二个大成本）

| 选项 | 月费 | 说明 |
| --- | --- | --- |
| **A. 先不接**（用 SQLite） | 0 | **内测期可以**，但**容器重建会丢所有用户数据** |
| B. 接云托管 MySQL | **约 246 元**（0.342 元/个·小时） | 数据安全，必须在上线前接 |

> 我的建议：**内测期用 A 省成本，但正式上线（对外开放）之前必须切 B**。
> 中间如果有内测用户的数据要保留，A 期间的数据会丢——内测数据本来也不该当正式资产。

### 决定 3：OCR 速度验收线（这条要产品一起定）

| 选项 | 说明 |
| --- | --- |
| **A. 改成「单张 ≤10 秒、3 张并行 ≤25 秒」** | ⭐ **推荐**：实测单张 P95 8.32s、3 张并行 P95 21.73s（21 张真实图基线）；产品对外承诺「30 秒内出报告」，两条线都在承诺内 |
| B. 坚持「单张 ≤4 秒」 | 需买更大机器 + 继续优化，且**仍不保证达标** |

> 依据见 `ops/OCR性能缺口-优化与降级方案.md` §5。**这条不是老板一个人定，产品要一起点头。**

## 2. 运维推荐的默认配置（老板说「按推荐来」就用这套）

```yaml
环境    : 微信云托管（个人主体小程序开通）
服务名  : qbl-api
公网访问: 关闭（小程序用 callContainer 内网调用）
规格    : 4 核 8G
副本    : 最小 0（内测期）/ 最小 1（正式上线）
扩容    : CPU 使用率 > 70% 触发
日志    : 采集路径 /app/var/log，保留按云托管默认
数据库  : 内测期 SQLite；正式上线前切云托管 MySQL
OCR验收 : 单张 ≤10 秒 / 3 张并行 ≤25 秒（并行是硬要求）
```

## 3. 选定配置后的部署清单（运维执行）

> 老板一选完，照这张表逐条打勾，边做边勾。

| # | 步骤 | 动作 | 验证 | 勾 |
| --- | --- | --- | --- | --- |
| P1 | 生成部署包 | `python ops/scripts/make_cloudrun_pkg.py` | 输出「0.49 MB / 72 文件 / 安全自检通过」 | ☐ |
| P2 | 新建服务 | 控制台 → 新建服务 `qbl-api`，**关闭「允许公网访问」** | 服务出现在列表 | ☐ |
| P3 | 选规格 | 服务设置 → 容器规格 = 选定值 | 配置已保存 | ☐ |
| P4 | 配副本 | 最小/最大副本数 = 选定值 | 已保存 | ☐ |
| P5 | 配日志 | 服务设置 → 日志采集路径 = `/app/var/log` | 已保存 | ☐ |
| P6 | 配环境变量 | 按 §4 逐项填入（**密钥在控制台填，不进代码**） | 全部填完 | ☐ |
| P7 | 上传发布 | 部署发布 → 手动上传代码包 → 选 `ops/dist/qbl-cloudrun-<时间戳>/` → 发布 | 构建日志出现 `Application startup complete` | ☐ |
| P8 | 健康检查 | `curl https://<默认域名>/health`（若开了公网）或用小程序调 | 返回 `{"ok":true,...}` | ☐ |
| P9 | **OCR 实测基线** | 用 3 张真实截图跑一次，记录耗时 | 得出真实耗时数字，**用这个定验收线** | ☐ |
| P10 | 清理任务验证 | 等一次每小时清理周期，查 `/app/var/log/deletion.log` | 过期截图被删、有日志 | ☐ |
| P11 | 检查容器重建 | 缩容到 0 再唤醒，确认数据是否保留 | 确认数据库策略（SQLite 会丢） | ☐ |

## 4. 环境变量清单（在云托管控制台填，不写进代码）

| 变量 | 值 | 说明 |
| --- | --- | --- |
| `QBL_ENV` | `prod` | 生产环境标识 |
| `QBL_USE_LLM` | `0` | 一期禁止大模型（D19） |
| `QBL_FEATURE_COMMUNITY` | `0` | 社区关闭（D14） |
| `QBL_UPLOAD_TTL_HOURS` | `22` | D37 定案：22h + 每小时扫描 ⇒ 删除 ≤23h |
| `QBL_OCR_THREADS` | `4` | 实测 4 线程优于 8 线程（见性能方案 §2） |
| `QBL_WORKER_THREADS` | `2` | 云托管核数有限，别开太高 |
| `QBL_ADMIN_TOKEN` | 随机 32 位 | **控制台填**，不进代码 |
| `QBL_TOKEN_SECRET` | 随机 32 位 | 同上 |
| `QBL_PAY_SECRET` | 随机 32 位 | 同上 |
| `QBL_WX_APPID` | 正式 AppID | 第 1 关拿到后填 |
| `QBL_WX_SECRET` | 小程序 AppSecret | 同上，**控制台填** |

> 生成随机串：任意密码管理器，或本地 `openssl rand -base64 32`。**不要发群里**。

## 5. 成本对照（选定后一眼看明白）

| 配置组合 | 内测期实际（缩容到 0） | 正式上线（1 副本常驻） |
| --- | --- | --- |
| A：2 核 4G + SQLite | 约 5–20 元 | 171.36 元 |
| **B：4 核 8G + SQLite** | 约 10–40 元 | **342.72 元** |
| B + 云托管 MySQL | — | **约 589 元** |

> 内测期成本很低，因为缩容到 0 时只有请求期间计费。
