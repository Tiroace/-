## 6. 若 002 构建失败，优先看这两类

今晚包相对 001 的核心改动之一是**模型构建期下载**（`RUN python -c "RapidOCR()..."`），
这会**显著拉长构建时间**。若失败，日志里重点找：

- **超时类**：`timeout`、`超过最大构建时长`、`create_build_image` 阶段耗时异常长
- **下载类**：`connection`、`DownloadFile`、模型下载失败

**两类原因改法完全不同**：
- 超时 → 去掉构建期下载改回运行时，或申请提高构建超时
- 下载失败 → 换模型源 / 把模型文件直接打进包

> 这个风险是我加构建期下载时引入的，已提前记录，不是事后找补。

### 9.3 自动化为什么保存不了（技术记录，避免重复踩）

控制台是 React + Chakra UI，环境变量编辑器有两个坑：

1. **读取要穿透 shadow DOM**：普通 document.body.innerText 长度是 0，
   递归遍历 el.shadowRoot 才能读到内容（个人助理发现的，已确认有效）。
2. **「JSON」是 switch 不是按钮**：点文字「JSON」无效；
   要点它外层 <label class=chakra-switch> 里的 <input type=checkbox>，
   点完才会出现 textarea。
3. **保存按钮定位不稳**：页面每次 evaluate 后异步重渲染，
   同一份查询代码前一次能看到「保存」，后一次就看不到；
   page.locator / getByRole 对 shadow DOM 内按钮完全不可见（count: 0）。

**结论：这条路对自动化不稳，人力点 10 秒的事，不要再投入自动化。**
