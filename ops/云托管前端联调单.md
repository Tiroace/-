## 1. 构建（前端唯一的动作）

```powershell
cd D:\qiuzhibilei\src
$env:VITE_CLOUD_ENV     = "<环境 ID，运维给>"
$env:VITE_CLOUD_SERVICE = "qbl-api"
npm run build:review:mp-weixin
Remove-Item Env:VITE_CLOUD_ENV, Env:VITE_CLOUD_SERVICE   # 别把临时值留在会话里
```

`vite.config.js` 会把两个值注入为 `__QBL_CLOUD_ENV__` / `__QBL_CLOUD_SERVICE__`，
`config.js` 用它们判断 `hasCloudBackend()`。

**构建后自检**（应能看到这两个值进了产物）：

```powershell
Select-String -Path 'dist\build\mp-weixin\common\config.js' -Pattern 'prod-'
```

> 注：`strip-dev-build.mjs` 在 review 模式下还会校验 tabBar 只剩两项，这里是同一个产物。

## 4. 排查表（按命中顺序查）

| 现象 | 最可能原因 | 怎么确认 |
|---|---|---|
| 所有接口 404 | 服务名写错 | 云托管控制台核对服务名是否 `qbl-api` |
| `callContainer` 报 env 不存在 | 环境 ID 写错/环境未发布 | 控制台复制环境 ID 重贴 |
| 接口通但返回 502 | 容器未起来 | 看云托管构建日志有无 `Application startup complete` |
| **上传失败、普通接口正常** | 还在走 multipart | 构建产物里搜 `upload-base64`；确认 `hasCloudBackend()` 为真 |
| 上传返回 400 `BYPASS_FORBIDDEN` | 请求里混进了 `ocr_text` | 这就是 ocr_text 旁路闸门，**不是上传通道坏了**，去掉 `ocr_text` |
| 报告一直 pending | 后端 worker 未启动 | 云托管日志查 `worker` 关键字 |
| 生成报告很慢 | OCR 在云端 CPU 上跑 | 属已知性能问题，见 `ops/OCR性能缺口-优化与降级方案.md` |

## 5. 两个已知待核实项（不臆断，联调时实测）

1. **`wx.cloud.callContainer` 是否需要 `wx.cloud.init`**
   本地文档只写了「不需要域名/不需要备案」，没写初始化要求。
   若首次调用报「未初始化」，在 `App.vue` 的 `onLaunch` 里补一次 `wx.cloud.init({ env })` 即可。
   **补之前先确认，不要预先加进代码。**

2. **云托管对请求体的大小限制**
   base64 会让体积涨 33%。前端已压到 ≤200KB（base64 后约 267KB），
   实测若仍被拒，再降到 120KB 或改走对象存储直传。
